# 灵枢新增买家秀管理需求

> 版本：v0.3（讨论结论整理稿）
> 待定项统一标注 **TBD**，见文末第 14 节。

# 1. 背景与目标

- 灵鉴按 SPU 产出"需要新增买家秀"的任务清单，并给出每个 SPU 需要的图片数量。原有买家秀任务分发页面迁移至灵枢，统一到新板块【买家秀管理】。
- 买家秀图片通过 AI 生图（nano banana）批量制作，在灵枢内完成运营配置 → 设计制作 → 运营审核 → 自动推送 CMS 买家秀图片板块的闭环。
- 板块目标：
  - 运营侧：在架 SPU 提前配置质检图并确认实物一致性，任务清单侧重分发；减少逐条临时配图的成本。
  - 设计侧：按数量展开、自动匹配图1/素材/描述词，批量创建与批量调整。
  - 管理侧：任务量、进度、卡点、制作人产出与质检图 / 一致性配置情况可视化。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 主任务 | 灵鉴下发的一条任务，对应一个 SPU 及其需要的买家秀数量 |
| 子任务 | 主任务下的一张买家秀图片的生成任务，一条子任务 = 一次 nano banana 任务（可多次重新生成） |
| 需要数量 | 灵鉴给出的该 SPU 需新增买家秀张数，即子任务数 |
| 有效子任务 | 未被审核端废弃、且当前不处于【生图失败】的子任务 |
| 质检图 | SPU 级主数据：运营按角度配置的商品实拍图，作为图1 的首选来源；分发时快照到主任务 |
| 首图 | SPU 商品主图（商详首图），列表展示与商品图兜底用 |
| 实物一致性确认 | 运营确认「商品图 ↔ 质检图/实物」可对齐，避免错款旧图进入生图；状态挂在 SPU 上，分发时快照到主任务 |
| 图1 / 图2 / 图3 / 图4 | **主流程**三张：图1 = 商品参考（质检图，兜底商品图），图2 = 素材图，图3 = 第二张素材（选填）。**自由批量**四槽：图1 商品图（必填）、图2 参考图（选填、手选）、图3 质检图（选填）、图4 其他（选填） |
| 描述词 | 生图任务的 prompt，按角度使用模板并填入色值等槽位 |
| 制作方式 | 主任务级属性：批量制作 / 单个制作，由运营在分发时指定，用于区分设计工作量口径 |
| 审核轮次 | 主任务每次点击【提交审核】计一轮，子任务记录所在轮次 |
| 自由批量生图 | 设计侧独立工作台：不依赖灵鉴主任务，手动加入 SPU 后批量创建 nano banana；v0 本页闭环，不进任务清单 / 审核 / CMS |
| 批次 | 一次【批量创建】产生的一组生图记录，带来源字段 `source = 手动批量`，供后续接主流程 |

# 3. 主流程与页面清单

## 3.1 主流程

```
（可并行）运营在【SPU 质检图库】为在架 SPU 提前配置质检图、确认实物一致性
灵鉴下发主任务
→ 运营：在任务清单查看已带入的质检图 / 一致性状态，必要时快捷补配；指定颜色（可选）、指定制作方式 → 分发（快照写入主任务）
→ 设计：认领主任务
→ 设计：批量制作 / 单个制作，创建子任务 → AI 生图
→ 设计：逐张检查结果 → 重新生成 / 标记修改中并上传覆盖 / 子任务提交审核
→ 全部有效子任务提交后，设计对主任务点击【提交审核】
→ 运营：以主任务为单位逐张审核（通过 / 失败 / 废弃）
→ 有失败：主任务返修中 → 设计修改后再提交 → 返修待审核 → 再审
→ 全部有效子任务通过 → 系统自动按主任务推送 CMS 买家秀图片板块
→ 主任务状态回传灵鉴
```

## 3.2 页面清单

|---|---|---|
| SPU 质检图库 | 运营 | 在架 SPU 清单：配置质检图（按角度）、确认实物一致性；可早于任务下发 |
| 任务清单页 | 运营 | 承接灵鉴主任务，查看/快捷补配质检图与一致性、指定颜色与制作方式，分发、取消 |

# 4. 任务清单页（运营）

## 4.1 页面定位

承接灵鉴下发的主任务，运营在此完成分发。质检图与实物一致性以【SPU 质检图库】为唯一数据源；本页只读展示状态，并提供快捷补配入口。支持批量勾选、批量操作、导出（沿用调色任务规则：勾选导出所选，未勾选按筛选条件全量导出）。

## 4.2 筛选栏

| 字段 | 说明 |
|---|---|
| SPU | 文本 |
| 任务编号 | 主任务编号 |
| 品类 | 来自 SPU 主数据 |
| 主任务状态 | 见第 8 节 |
| 质检图状态 | 未配置 / 已配置 / 部分配置（取自 SPU 主数据或主任务快照，见 4.4） |
| 实物一致性 | 未确认 / 已确认 |
| 制作方式 | 批量制作 / 单个制作 / 未指定 |
| 制作人 | 设计 |
| 时间范围 | 下发时间 |

## 4.3 列表字段

| 字段 | 展示 | 说明 |
|---|---|---|
| 任务编号 | 只读 | 系统生成 |
| SPU | 可点击 | 点击展开右侧抽屉：商品图、SPU 基础信息、质检图与一致性（同数据源快捷编辑） |
| 品类 | 只读 | SPU 主数据 |
| 需要数量 | 只读 | 灵鉴下发 |
| 已完成数量 | 只读 | 已推送子任务数 |
| 颜色 | 可编辑 | 运营指定的目标颜色，可为空；作为子任务颜色默认值 |
| 质检图状态 | 标签 | 未配置 / 已配置 / 部分配置 |
| 实物一致性 | 标签 | 未确认 / 已确认 |
| 制作方式 | 可编辑 | 批量制作 / 单个制作，分发前必填 |
| 主任务状态 | 标签 | 见第 8 节 |
| 制作人 | 只读 | 认领后写入 |
| 下发时间 / 分发时间 / 认领时间 / 提交时间 / 审核完成时间 / 推送时间 | 只读 | 各节点时间 |
| 操作 | 按钮 | 配置质检图、分发、取消（仅待分发/待领取）、查看 |

## 4.4 质检图与一致性（快捷入口 + 分发快照）

- 数据归属：质检图四角度与实物一致性挂在 **SPU 主数据**，唯一维护页为【SPU 质检图库】（见第 4A 节）。
- 快捷入口：操作列【配置质检图】或抽屉内，**抽屉编辑同一 SPU 数据源**（与质检图库同一套槽位与 API），抽屉内可链到质检图库该 SPU 行查看销量等上下文。
- 分发时写入主任务快照（制作 / 审核只读快照，不随 SPU 主数据事后变更而静默改写）：
  - `qcImagesSnapshot`：四角度图 + 覆盖态
  - `consistencyStatus`：未确认 / 已确认（+ 确认人、确认时间）
- 质检图、实物一致性均**不是**分发的强制前置；面板统计「未配置即分发」「未确认即分发」比例。
- 制作时图1 仍优先快照中的质检图，无则商品图兜底并打标。

## 4.5 分发与取消

- 【分发】：制作方式必填；支持批量分发；分发时写入 4.4 快照。分发后主任务进入【待领取】，状态回传灵鉴。批量分发时可提示未配置 / 未确认条数，不拦截。
- 【取消】：仅【待分发】【待领取】状态可操作，需填写原因；主任务进入【废弃】并回传灵鉴。进入制作后不可取消。
- 防重：同一 SPU 进行中再次下发的去重由灵鉴侧控制，灵枢不做拦截。

# 4A. SPU 质检图库（运营）

## 4A.1 页面定位

在架商品的 SPU 主数据工作台。运营可在灵鉴任务下发前完成质检图配置与实物一致性确认；与【配置管理】并列（后者管参考图库 / 描述词模板，本页管按 SPU 的商品资产）。

## 4A.2 列表：SPU 基础信息

| 字段 | 展示 | 说明 |
|---|---|---|
| SPU | 文本 | 编码 + 名称 |
| 首图 | 缩略图 | 商详首图 / 商品主图 |
| 近 30 天销量 | 数值 | 默认按此降序；用于优先级，不做分发硬门槛。口径（件数 / GMV、渠道）实现前与数据侧对齐 |

以上三列为 SPU 基础信息，列表必显。

## 4A.3 列表：配置与状态字段

| 字段 | 展示 | 说明 |
|---|---|---|
| 品类 | 只读 | SPU 主数据 |
| 质检图覆盖 | 标签 / `x/4` | 未配置 / 部分配置 / 已配置；可展开看四角度点阵 |
| 实物一致性 | 标签 | 未确认 / 已确认（已确认时展示确认人、时间） |
| 最近更新 | 只读 | 时间 + 操作人 |
| 进行中任务 | 可选 | 是否有进行中买家秀主任务 |
| 操作 | 按钮 | 配置质检图、确认一致性 / 撤销确认 |

## 4A.4 筛选与排序

- 筛选：SPU、品类、质检图状态、实物一致性、是否有进行中任务。
- 快捷筛：高销未配、高销未确认。
- 默认排序：近 30 天销量降序。

## 4A.5 配置质检图

- 按角度配置：**正面、侧面、背面、半身** 四个槽位，每个槽位可上传 / 选择一张质检图。
- 允许部分配置；状态推导：0 个 = 未配置；4 个 = 已配置；其余 = 部分配置。
- 修改任一角度质检图后：实物一致性**自动回退为未确认**（已分发主任务快照冻结，不自动变）。

## 4A.6 实物一致性确认

- 定义：运营确认「商品图 ↔ 质检图 / 实物」可对齐，避免错款旧图进入生图。
- 确认人：运营（与配质检图同一角色）。
- 最低条件：至少已配置 **1 张** 质检图方可点击【确认】（避免无实拍锚点的空洞确认）。
- 状态：未确认 / 已确认；支持运营主动撤销确认。
- 闸门：
  - 未确认**允许**分发（非强制）；面板记「未确认即分发」。
  - 制作**允许**商品图兜底，子任务图1 来源打标。
  - SPU 主数据事后改图不影响已分发主任务快照。

## 4A.7 与任务清单的关系

- 无灵鉴任务的在架 SPU 也可配置。
- 任务清单读 SPU 主数据状态；分发时快照；快捷入口见 4.4。

# 5. 任务领取页（设计）

- 展示【待领取】及"自身制作中 / 返修中"的主任务。
- 操作列提供【认领】，认领后主任务进入【制作中】，制作人写入。
- 不设组长指派。
- 列表字段：任务编号、SPU（缩略图）、品类、需要数量、颜色、制作方式、质检图状态、实物一致性、下发时间、分发时间、状态、操作。

# 6. 制作页（设计）

## 6.1 批量制作

### 6.1.1 进入方式

在自己【制作中】的主任务中勾选一个或多个，点击【批量制作】。

### 6.1.2 行展开

每个主任务按需要数量展开为等量的行，每行对应一个待创建子任务。已存在子任务的主任务，仅展开尚未创建的剩余数量。

### 6.1.3 行字段

| 字段 | 必填 | 自动填充规则 | 可改 |
|---|---|---|---|
| SPU / 任务编号 | - | 来自主任务 | 否 |
| 颜色 | 是 | 默认取主任务颜色；主任务未指定时为空，创建前必填 | 是 |
| 角度 | 是 | 按行序预填：第 1 行正面、第 2 行侧面、第 3 行背面、第 4 行半身，第 5 行起循环 | 是（正面/侧面/背面/半身） |
| 标签 | 从库选图2/图3 时必填 | 品类由 SPU 带出；标签选项 = 当前品类 + 角度下图库已启用的标签，设计只能选不能新建 | 是 |
| 图1 | 是 | 取主任务中该角度的质检图；无则取商品图兜底（主图视为正面，其余角度需手动选择商品图）；均无则提示手动选择 | 是 |
| 图2 | 是 | 先选标签，按 品类-标签-角度 调库手选；**或手动上传** | 是 |
| 图3 | 否 | 按同一套标签调库手选，**或手动上传** | 是 |
| 描述词 | 是 | 取该角度的描述词模板，填入槽位：色值（按颜色 + 材质匹配词典）、材质、品类、场景 | 是（可全文编辑） |
| 色值匹配状态 | - | 匹配成功 / 未匹配（高亮，需人工填写） | - |

### 6.1.4 校验与创建

- 【批量创建任务】前逐行校验必填项；任一行不通过，标红并阻止提交。
- 色值未匹配的行允许提交，但描述词中的色值槽位必须已被人工填写；人工填写的颜色→色值可一键【存入词典】。
- 创建成功后每行生成一条子任务，状态【生图中】，主任务保持【制作中】。
- 图1 来源（质检图 / 商品图兜底 / 手动）、图2/图3 的素材 ID、描述词最终文本、模板版本，全部落在子任务上，后续修改模板或素材不影响已创建子任务。

## 6.2 单个制作

- 主任务制作方式为"单个制作"时，设计在主任务下逐条点击【新建子任务】。
- 表单字段与 6.1.3 一致（颜色、角度、标签、图1/图2/图3、描述词），自动填充规则一致。
- 子任务数达到需要数量后不可再新建（返修中补建除外，见 6.3.4）。

## 6.3 子任务操作

### 6.3.1 结果检查

生图成功的子任务自动进入【待提交审核】。设计在制作页或子任务详情页对结果图执行以下之一：

| 操作 | 结果 |
|---|---|
| 【提交审核】 | 子任务 → 待审核 |
| 【重新生成】 | 可修改颜色/角度/标签/图1/图2/图3/描述词后重跑，子任务 → 生图中；生成次数 +1，旧结果留版本 |
| 【标记修改中】 | 子任务 → 修改中；设计下载结果图外部处理后【上传覆盖】，上传成功 → 待提交审核，AI 原图留版本 |

### 6.3.2 批量调整

在制作页勾选多条【待提交审核】或【审核失败】的子任务，批量修改图2/图3/描述词/标签后【批量重新生成】。批量调整不改变颜色与角度（需逐条改）。

### 6.3.3 生图失败

- 子任务【生图失败】可【重试】（沿用参数）或修改参数后重新生成。
- 生图失败的子任务不计入主任务状态推导的门槛，但在制作页与面板中作为卡点显示。

### 6.3.4 返修中补建

主任务处于【返修中】时，若审核端废弃了子任务导致有效子任务数低于需要数量，设计可【新建子任务】补做，不强制。

### 6.3.5 主任务提交审核

- 全部有效子任务处于【待审核】且子任务数 = 需要数量时，主任务自动进入【待提交审核】，制作页显示【提交审核】按钮。
- 设计点击后：首轮 → 主任务【待审核】；非首轮 → 主任务【返修待审核】。审核轮次 +1，本轮所有待审核子任务记录轮次。

## 6.4 子任务详情页

在参考功能子任务详情页基础上调整：

| 区块 | 内容 |
|---|---|
| 头部信息 | 子任务编号、主任务编号、SPU、颜色、角度、标签、制作方式、状态、审核轮次、生成次数、制作人、创建时间 |
| 描述词 | 最终文本全文，标注模板版本 |
| 参考图片 | 图1（标注来源：质检图 / 商品图兜底 / 手动）、图2、图3（标注素材 ID 与层级标签） |
| 生成结果 | 当前结果图；历史版本列表（AI 生成 / 上传覆盖，含时间与操作人）；备注 |
| 操作区 | 按当前状态显示：重新生成 / 标记修改中 / 上传覆盖 / 提交审核 / 重试 |
| 审核信息 | 各轮审核结果与失败原因 |
| 操作日志 | 操作内容、操作人、时间，沿用参考功能格式 |

# 6.5 自由批量生图（设计，v0）

独立于灵鉴主流程的批量生图工作台。**与 6.1 共用同一套行编辑、自动匹配、批量调整与子任务详情中的重生成**，不另做第二套表单。菜单名与「批量制作」区分，避免和已认领主任务入口混淆。

## 6.5.1 定位与边界

- 任务信息不由上游传入；设计用**【新建】**、**表格导入（SPU / 个数）**或搜索 / 粘贴加入 SPU。页面顶部有使用说明。
- **v0 闭环**：批量创建 nano banana → 本页看结果 / 重新生成 / 单张或打包下载。
- **v0 不做**：进任务清单、认领、审核、推 CMS、回传灵鉴、计入制作人绩效、整包传图。表格导入支持 CSV（Excel 另存为 CSV）。
- 生图记录带来源 `source = 手动批量`，页上不暴露。后续若要上架，再按 SPU+颜色收成主任务「送审」，接现有审核 → CMS。

## 6.5.2 录入

- **加 SPU**：【新建】在列表加空行，填写 SPU（可搜索）、个数；【表格导入】列 **SPU、个数**；搜索 / 粘贴 SPU 仍可用。个数空则默认 4。命中带出名称、首图、品类、质检覆盖、**材质（SCM 自动匹配）**；未命中标红，不进入展开。
- **SPU 卡**：张数默认 **4**（正 / 侧 / 背 / 半身，超出循环）。颜色、标签不在此行填写。
- 卡顶工具：【全部默认 4 张】；【统一填颜色】作用于下方展开行。

## 7.2 布局（在参考功能审核页基础上调整）

| 区域 | 内容 |
|---|---|
| 左侧：主任务列表 | 仅显示【待审核】【返修待审核】【推送失败】的主任务；主任务卡显示 SPU、品类、制作方式、制作人、待审核 x/y；展开为子任务行，显示子任务编号、角度、颜色、状态 |

| 右侧：审核操作 | 【通过】【失败】【废弃】三个按钮；已审核的子任务显示结果与原因 |

## 7.3 审核分支（子任务级，单一维度）

| 操作 | 校验 | 结果 |
|---|---|---|
| 【通过】 | - | 子任务 → 待推送 |
| 【失败】 | 失败原因必填 | 子任务 → 审核失败 |
| 【废弃】 | 废弃原因必填 | 子任务 → 废弃，退出有效子任务，不计入制作人绩效；仅审核页可操作 |

## 7.4 当轮审核结束与主任务流转

- 主任务下本轮所有【待审核 / 返修待审核】子任务均有结论后，本轮审核结束。
- 存在【审核失败】子任务 → 主任务【返修中】，退回制作人，制作页按 6.3 处理。
- 全部有效子任务【待推送】 → 主任务【待推送】，系统立即自动推送（第 9.2 节），进入【推送中】。
- 主任务全部子任务被废弃时，主任务无有效子任务，主任务进入【废弃】并回传灵鉴。

## 7.5 推送失败处理

【推送失败】的主任务显示在审核页左侧列表，操作列提供【重新推送】；重推按主任务整体幂等执行。

# 8. 状态机

## 8.1 主任务状态

| 状态 | 说明 | 对应子任务情况 |
|---|---|---|
| 待分发 | 灵鉴下发，运营尚未分发 | 子任务未创建 |
| 待领取 | 运营已分发，尚未被领取 | 子任务未创建 |
| 制作中 | 领取后，到提交审核前 | 存在生图中 / 生图失败 / 修改中 / 待提交审核 / 部分待审核的子任务，或子任务数未达需要数量 |
| 待提交审核 | 全部有效子任务已由设计提交，且子任务数 = 需要数量 | 全部有效子任务处于【待审核】；允许存在生图失败的子任务 |
| 待审核 | 主任务首次点击【提交审核】 | 全部有效子任务处于【待审核】 |
| 返修中 | 当轮审核结束后，存在【审核失败】的子任务 | 任一子任务处于审核失败；修改后回到待提交审核 / 待审核 |
| 返修待审核 | 非首次点击【提交审核】 | 所有曾审核失败的子任务均已流转到【返修待审核】 |
| 待推送 | 全部有效子任务【审核通过】（瞬时状态，随即自动推送） | 全部有效子任务处于【待推送】 |
| 推送中 | 系统自动推送 CMS | 任一子任务处于【推送中】 |
| 已推送 | 已推送至 CMS | 全部有效子任务【已推送】 |
| 推送失败 | 推送失败，可重推 | 任一子任务处于【推送失败】 |
| 废弃 | 运营取消（仅待分发 / 待领取），或全部子任务被审核端废弃 | - |

## 8.2 子任务状态

| 状态 | 说明 |
|---|---|
| 生图中 | AI 正在生成图片 |
| 生图失败 | 生成失败，可重试；不计入有效子任务 |
| 待提交审核 | 生图成功或上传覆盖成功后自动进入 |
| 修改中 | 设计点击【标记修改中】，等待上传覆盖 |
| 待审核 | 设计点击【提交审核】（首轮） |
| 返修待审核 | 审核失败后重新生图 / 上传覆盖完成，设计再次点击【提交审核】 |
| 审核失败 | 人工审核不通过，附失败原因 |
| 待推送 | 人工审核通过 |
| 推送中 | 系统推送中 |
| 已推送 | 图片已推送至 CMS |
| 推送失败 | 推送失败 |
| 废弃 | 仅审核页可操作，附废弃原因 |

## 8.3 子任务状态流转

```
创建 → 生图中 → 生图成功 → 待提交审核
                ↘ 生图失败 → 重试/修改参数 → 生图中
待提交审核 → 提交审核 → 待审核（首轮）/ 返修待审核（非首轮）
待提交审核 → 重新生成 → 生图中
待提交审核 → 标记修改中 → 修改中 → 上传覆盖 → 待提交审核
待审核 / 返修待审核 → 通过 → 待推送 → 推送中 → 已推送 / 推送失败 → 重推 → 推送中
待审核 / 返修待审核 → 失败 → 审核失败 → 重新生成 / 标记修改中 → … → 待提交审核 → 提交审核 → 返修待审核
待审核 / 返修待审核 → 废弃
```

## 8.4 主任务状态推导规则

主任务状态由子任务状态推导（待分发 / 待领取 / 废弃(运营取消) 除外），优先级从高到低：

1. 任一子任务【推送失败】 → 推送失败
2. 任一子任务【推送中】 → 推送中
3. 全部有效子任务【已推送】 → 已推送
4. 全部有效子任务【待推送】 → 待推送（触发自动推送）
5. 当轮审核结束且任一子任务【审核失败】 → 返修中
6. 主任务已点击提交审核且全部有效子任务【待审核】 → 待审核；【返修待审核】 → 返修待审核
7. 全部有效子任务【待审核】且子任务数 = 需要数量，且主任务未点击提交审核 → 待提交审核
8. 其余 → 制作中
