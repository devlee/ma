# 意图单需求

> 版本：v0.1
> 意图单是灵策向执行侧下达任务的唯一单据。规矩（两类来源、四钩子、三条纪律、状态机）在《灵策总纲》3.4，本册是字段级定义。商品域四种单的「信」见《商品域/意图单类型》，其他域的单据类型随该域启动再写。

---

# 1. 信封

格式全局一套。各域只追加类型附加字段，不改信封，不在单上写实现步骤。

| 字段 | 必填 | 取值 | 谁填 |
|---|---|---|---|
| 编号 | 是 | 系统生成，全局唯一。归因外键，下发时原样传到执行侧，回填与商城归因都用它 | 系统 |
| 单据类型 | 是 | 各域登记的类型（商品域见《意图单类型》） | 生成时按来源带入 |
| 来源 | 是 | 蓝图 / 节点 / 诊断结论 ID / 人工。事件单填诊断结论或建议 ID；人工来源必填理由 | 系统预填；人工来源由开单人写理由 |
| 对象 | 是 | 站点 × 品类 × SPU，站点默认全站。最细到类型定义允许的层级 | 批量取自规划行与预案对象范围；事件单取自建议上的对象 |
| 目标 | 是 | 一个 L1 口径的指标 + 目标值。验收只认这个口径 | 类型预置口径；目标值批量取自规划行，事件单取自规则预置基准 |
| 预算 | 是 | 金额、任务点或配额。允许为 0 | 批量按预案资源需求；事件单按类型默认值，零成本动作为 0 |
| 预算来源 | 是 | 哪个资源池。为 0 也要填，记账不断 | 批量=被扣减的池；事件单=类型默认池 |
| 时限 | 是 | 完成日期 | 批量=触发链日期；事件单=类型默认时长，人可改并留痕 |
| 下发环节与路由 | 是 | L4 契约上的环节 + 终点（灵鉴→灵枢 / 直连灵犀 / 鹊桥 / 人工工作台） | 按单据类型，从契约表带入 |
| 判定窗口 | 是 | 本类型登记的判定方式，见第 4 节 | 按单据类型带入 |
| 状态 | 是 | 见第 2 节 | 系统 |
| 关联 | 批量必填，事件单可空 | 规划行 / 节点叠加包 / 预案 / 假设编号 | 批量生成时带入 |

人确认前可以改目标值、预算、时限，改动留痕。编号、单据类型、预算来源、判定窗口确认后不可改。

# 2. 状态与谁可以往下推

草稿 → 确认 → 下发 → 执行中 → 完成 → 已判定。任一在途状态可转已终止（驳回 / 止损 / 过期撤销）。终止单不回填五态，记录保留。

| 迁移 | 谁 |
|---|---|
| 草稿 → 确认 | 该单类型的审批角色（商品域：换图与素材为运营；处置里下架为运营负责人终审，其余迁移为运营）。驳回则直接已终止，理由必填 |
| 确认 → 下发 | 系统。若该池的事件单累计占用超过配置阈值，改为待规划 Owner 加签，通过后才下发 |
| 下发 → 执行中 | 执行端回执（系统回传或人工工作台点「开始」） |
| 执行中 → 完成 | 执行端回填完成（第 5 节）或执行系统回传完成 |
| 完成 → 已判定 | 判定窗口到期后由判定引擎回填。窗口类型为「执行确认即闭环」的，完成与已判定同时发生 |
| 在途 → 已终止 | 驳回=审批人；止损=判定结果生成建议、人批准后；过期撤销=时限到期仍未执行，系统生成建议、单据 Owner 确认 |

# 3. 两类生成

## 3.1 批量（周期性 / 节点性）

规划表的策略目标 × 节点实例的触发时点 × 预案模板的动作清单 → 一批草稿。蓝图未锁定不生成。

| 信封 | 取自 |
|---|---|
| 对象 | 预案动作的对象范围，按规划表行（站点 × 品类）展开；是否落到 SPU 由单据类型决定 |
| 目标 | 规划表该行上、与类型口径一致的目标值 |
| 预算 / 预算来源 | 预案的资源需求，从产能账或预算池扣减，来源记被扣的池 |
| 时限 | 节点实例触发链上该环的日期 |
| 来源 | 蓝图 + 节点实例 |
| 关联 | 规划行、叠加包、预案模板、假设编号（规划行挂了假设才有） |

草稿进待办，人确认后下发。没人确认的草稿过了触发日仍留在待办，并随「意图单到期」提醒，不自动下发。

## 3.2 事件性（单张）

建议卡片上点批准即生成，四个钩子系统预填，人不再填表：来源=这条建议或诊断结论，目标=规则预置的验收口径，预算来源=类型默认池，编号=系统生成。人工来源（没有诊断结论、有人直接要求）保留，理由必填，并计入月度对账的人工来源占比。

# 4. 判定窗口

窗口登记在单据类型上，不登记在环上。动作环问的是「这张单起效了吗」，到窗口到期才回填。

| 窗口类型 | 含义 | 商品域谁用 |
|---|---|---|
| 事件窗 | 以执行完成的时间戳为第 0 天，到期自动判定。活动重叠则顺延 | 换图单。窗口参数（初判 14 天、终判 30 天、学习期 3 天）以《换图决策需求》7.1 为准 |
| 时限核对 | 到时限核对目标口径是否达标，不另开观察期 | 素材单：时限到期核对完备度 |
| 执行确认即闭环 | 执行回填完成即已判定，不看之后的生意结果 | 处置单 |

人处理队列的节奏（候选审批、回滚待批、到期提醒）是作业时钟，见总纲 10.5，与上表无关。

# 5. 人工工作台回填

执行终点是人工工作台的单，落在个人待办中心。回填栏：

| 栏 | 必填 | 说明 |
|---|---|---|
| 意图单编号 | 是 | 带出，不可改。没有编号不能提交 |
| 完成时间 | 是 | 作为事件锚点的，完成时间就是第 0 天 |
| 做了什么 | 是 | 短句。不要求写步骤清单 |
| 结果链接或附件 | 类型要求时必填 | 换图类走系统回传，不走本表 |

回填人不能改目标、预算、预算来源。时限已到仍未完成的，按总纲 10.5 周度提醒单据 Owner 和执行人。

# 6. 与执行侧的交接

下发报文至少带：编号、单据类型、对象、目标、预算、时限、类型附加字段。执行回传至少带：编号、完成时间戳。换图的推送时间戳是判定锚点，缺失则该单不能进入已判定（沿用《换图决策需求》第 6 节）。
