# 商品对象层需求

> 版本：v0.1（讨论结论整理稿）
> 对象层是所有商品动作的前置判断层：回答"这个商品处于什么状态、值不值得投入、该往哪走"。
> 换图决策（见《换图决策需求》）的处置态依赖由本模块提供。待定项统一标注 **TBD**，见第 12 节。

---

# 1. 背景与目标

## 1.1 现状

- **销量等级已系统化**（灵鉴）：按滚动 30 天销量分 9 档（S/A/B/C/D/E1/E2a/E2b/F），全局 + 分站两层配置，等级挂接素材达标要求与候选池规则。
- **下架决策半人工**：销量初筛 + 运营负责人人工终决——权责结构正确，但初筛规则在人脑里、建议无证据行、决策无留痕、事后无回验。
- **"谁值得优化"由灵鉴候选池规则自行定义**：优化投入与退场决策割裂，存在给"本该退场的商品"持续投入设计资源的错配风险。
- **新品无独立管理**：新品被动落入低等级档位，或游离于动作体系之外。

## 1.2 目标

建立商品对象层，作为所有商品动作域（换图、素材优化、价格、上下架）的统一前置：

- **生命周期**为外层状态机：新品期 → 在售期 → 退场。
- **在售期三维画像**：销量等级（沿用）× 趋势标签（新增）× 处置态（新增，动作总开关）。
- **新品期独立管理**：品类级配置包 + 里程碑检查点 + 单向保护。
- 处置决策升级为"规则出证据 + 人拍板 + 留痕回验"，决策逻辑上收经营决策系统，灵鉴保留路由与执行配置。

## 1.3 设计原则

- **等级描述现实，处置态表达意图**：等级是算出来的（自动、无人签字），处置态是决定出来的（人批准、有留痕）。
- **不做综合评分**：三个正交维度（等级/趋势/处置态）各自可解释、可单独校验；综合分是黑盒，损害团队信任。现有销量等级的简单性是资产。
- **处置态粒度跟随动作粒度**：下架当前为全站操作，处置态 v1 全站一份；数据结构预留站点字段（后台已支持分站操作，未来分站处置为真实可能）。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 生命周期 | 商品的外层状态机：新品期 / 在售期 / 退场 |
| 销量等级 | 滚动 30 天销量分档（9 档），主数据唯一，全局 + 分站两层（沿用现有机制） |
| 趋势标签 | 校正后销量/流量的方向标签：上升 / 平稳 / 下降 |
| 处置态 | 在售期商品的投入决策状态：保持 / 优化 / 观察 / 下架（动作总开关） |
| 新品保护期 | 上架后 N 天（品类可配，默认 90）：不进下架/清仓类建议，单向保护 |
| 单向保护 | 保护期内"可提拔、不可判死"：不进退场建议，但达标可提前毕业享受高等级资源 |
| 检查点 | 新品期的里程碑：上架第 7 / 15 / 30 / 60 / 90 天，逐点对照品类新品基准 |
| 提前毕业 | 保护期内滚动 30 天销量已达某等级区间 → 立即转入在售期等级体系 |
| 测款失败 | 保护期满仍低于失败线 → 直接进下架建议 |
| 信号唤醒 | 观察态商品出现自然信号（出单、流量异动）→ 自动建议回优化/保持 |
| 停留上限 | 观察态连续 M 个检视周期无正向信号 → 自动生成下架建议 |

# 3. 总体结构

```
生命周期：  新品期 ────毕业（期满按滚动销量落档 / 提前毕业）───→ 在售期 ──处置态=下架──→ 退场
              │                                                「等级 × 趋势 × 处置态」
              └──测款失败（期满低于失败线）──────────────────────────────────────→ 退场
```

- 新品期：独立管理项（第 7 节），不参与等级动作体系，数据照常记录。
- 在售期：三维画像（第 4–6 节），所有动作候选只从处置态 = 保持 / 优化 的商品中产生。
- 退场：下架建议 → 运营负责人拍板 → 执行（全站）→ 留痕。

# 4. 销量等级（沿用与增强）

## 4.1 沿用

- 9 档区间（S >100 / A (50,100] / B (30,50] / C (20,30] / D (10,20] / E1 (5,10] / E2a (1,5] / E2b =1 / F =0，月销件数），滚动 30 天计算。
- 全局 + 分站两层结构沿用现有灵鉴机制。
- 等级 → 素材达标要求的映射沿用（新品档另设，见 7.4）。

## 4.2 增强一：口径统一

等级主数据以 9 档为唯一口径（E 细分为业务需求新增）。灵鉴配置页当前展示 7 档（S–F），需对齐至同一主数据源，避免两套档位并存。（**TBD**：对齐改造量）

## 4.3 增强二：刷新防抖

滚动窗口 + 细档位（E2a 为 1–5 件、E2b 为 1 件）必然产生边界震荡（边界附近的商品档位反复横跳）。防抖规则：

- **升级即时生效**（不让商品等资源）；
- **降级需连续 2 个刷新周期确认**（周期数可配置）方才生效。

## 4.4 增强三：等级迁移事件

等级迁移作为标准事件输出，供下游订阅：

- 升级 → 触发机会型动作候选（换图事件驱动来源、素材要求提档检查）；
- 降级（防抖确认后）→ 触发诊断（结合趋势标签判断原因）。

# 5. 趋势标签

## 5.1 口径

上升 / 平稳 / 下降三档。判定输入为**品类同期校正后**的滚动销量与流量：连续 N 期环比方向一致且累计幅度超过阈值（N、阈值可配置，初始值由历史数据校准）。校正的目的：全品类涨跌是品类信号，不应污染个体趋势。

## 5.2 用途

- **修正等级的方向盲区**：同为 B 级，上升的 B 配机会型动作，下降的 B 触发诊断——等级相同、动作不同。
- 与换图候选的趋势型信号（《换图决策需求》4.3）共享计算逻辑，避免两套趋势口径。
- 趋势 × 等级组合进入处置建议规则（第 6 节）与优先级排序。

# 6. 处置态

## 6.1 四态语义与资源含义

| 处置态 | 资源含义 | 典型对象 |
|---|---|---|
| 保持 | 正常资源，不干预 | 表现健康的款 |
| 优化 | **增量投入**：所有动作候选（换图、素材、灵鉴任务）只从"保持 / 优化"中产生 | 有流量有潜力、值得花设计产能的款 |
| 观察 | **零投入**：排除出一切动作候选池（灵鉴不推任务、换图不进候选） | 暂不值得投入、也不必退场的长尾（预计为数量最大的池子） |
| 下架 | 退场 | 测款失败、观察到期无信号的款 |

观察态的价值：把"优化"池子压缩到设计产能真正能覆盖的规模——优化名单 = 值得做动作的商品，而非"所有不该下架的商品"。观察态是无库存模式的理性产物（持有成本近乎为零）。

> 决策记录：不设"清仓"态——无库存模式（按单生产）没有去库存需求；若未来引入备货模式再评估恢复。

## 6.2 观察态四道防护（防止其成为"逃避决策的垃圾抽屉"）

1. **入口带理由**：进观察必须有规则依据或人工理由，留痕。
2. **低频自动检视**：按周期（默认 90 天，可配置）自动跑信号检查，纯数据扫描、零人力成本。
3. **停留上限**：连续 M 个检视周期（默认 2，可配置）无正向信号 → 自动生成下架建议。观察是缓冲区不是终点。
4. **信号唤醒**：观察期内出单、流量异动 → 自动建议回"优化"或"保持"。观察池由此成为零成本的被动测款场。

## 6.3 迁移规则（均为"规则建议 + 人批"，全部留痕）

| 迁移 | 触发规则（默认值待校准） |
|---|---|
| 保持 → 优化 | 效率低于品类基准 / 素材缺口达标要求未满足，且等级、流量满足投入门槛 |
| 优化 → 保持 | 动作起效、指标回到基准之上 |
| 优化 → 观察 | 投入过但连续无效（如连续 2 次动作判定"无效"）/ 流量萎缩至门槛下 |
| 观察 → 优化 / 保持 | 信号唤醒（出单、流量异动超阈值） |
| 观察 → 下架建议 | 停留超上限 |
| 任意 → 下架建议 | 非新品、连续零销超 N 月、无流量 |

- **下架**维持现有权责：运营负责人拍板；其余迁移由运营批准。
- 新品保护期内的商品不进任何退场类建议（单向保护，见第 7 节）。

## 6.4 建议名单与回验

- 处置建议**周度跑批**（下架不需要每日节奏），每条带证据行（等级、趋势、流量、零销时长、素材状态），形态复用换图决策工作台。
- **决策留痕与误杀回验**：下架决策记录证据快照；季度抽样复盘下架商品（下架前是否仍有流量/加购信号），产出"误杀率"作为下架规则的校准指标——处置规则和判定阈值一样，是被复盘的对象。

## 6.5 与灵鉴的分工（前置闸 + 规则上收）

- **处置态 = 优化** 成为灵鉴优化任务候选池的前置条件（第一步：候选池增加处置态过滤，即刻止住资源错配）。
- 第二步：灵鉴候选池中"谁值得优化"的规则（等级勾选、转化筛选条件）逐步迁移为处置态判定规则，灵鉴保留"缺什么素材、按什么优先级补"的执行配置——决策上收、路由留守。

# 7. 新品管理（生命周期·新品期）

## 7.1 定位

新品期是独立生命周期阶段，与等级体系平级管理。管理逻辑相反：等级体系**向后看**（按历史表现分配资源），新品期**向前看**（尽快攒出可判定的数据，本质是测款）。培养期模式与风格库验证期同构（同口径记数据、不进成熟排行、单向保护、毕业/延期/淘汰规则）。

## 7.2 新品配置包（全局默认 + 品类覆盖）

```
新品管理配置
├─ 保护期天数（默认 90；高客单品类可覆盖为 120）
├─ 检查点序列：上架第 7 / 15 / 30 / 60 / 90 天
│   └─ 每检查点 × 基准值（曝光量、首单、加购率、转化率等里程碑指标）
├─ 提前毕业线：滚动 30 天销量达到某等级区间（复用等级区间定义）
├─ 测款失败线：期满销量 / 流量低于阈值 → 直接进下架建议
└─ 延期规则：可延 1 次 × N 天；操作留痕，不设审批
```

检查点基准初始值由**历史新品同期数据回算**（该品类历史新品第 N 天的中位 / 分位表现），与判定阈值校准同一批数据工程。（**TBD**：历史上架数据可得性）

## 7.3 检查点产出三档

| 档 | 含义 | 出口 |
|---|---|---|
| 达标 | 按基准正常爬坡 | 继续 |
| 预警 | 低于基准但未触线 | 提示运营，可触发新品动作（首图测试、素材补齐、初始投放调整） |
| 触线 | 低于失败线 | 期中触线记录预警；期满仍触线 → 测款失败，进下架建议 |

## 7.4 新品素材基线

灵鉴素材达标配置**增设新品档**：上架即须齐备的最低素材要求（新品尚无等级，不能共用等级档）。

## 7.5 出口规则

- **毕业**：保护期满，按滚动 30 天销量落入等级区间，进入在售期三维管理。
- **提前毕业**：保护期内滚动销量已达设定等级区间 → 立即毕业，享受对应等级资源。保护是单向的：保护"不被判死"，不阻止"被提拔"。
- **延期**：临界新品可延期 1 次 × N 天，留痕不审批。
- **测款失败**：期满低于失败线 → 直接进下架建议（运营负责人拍板）。

## 7.6 新品成功率（向上喂指标树）

新品成功率 = 毕业进入目标档位（如 C 档以上）的比例，按品类统计——L1 目标层的领先指标，品类规划表"上新目标"的质量口径（从"上了多少款"升级为"成功了多少款"）。

# 9. 数据需求与系统对接

## 9.1 数据需求

| 数据 | 粒度 | 现状 |
|---|---|---|
| 滚动 30 天销量（等级源数据） | SPU × 日（带站点字段） | 已有（灵鉴等级在用） |
| 流量 / 加购 / 转化 | SPU × 日（带站点字段） | 已有（换图判定共用） |
| 上架时间（新品期锚点） | SPU | 需确认历史数据完整性（**TBD**） |
| 品类新品同期基准 | 品类 × 上架第 N 天 | 新建，历史回算 |
| 处置态 / 趋势标签 / 生命周期状态 | SPU（处置态预留站点字段） | 本模块新建主数据 |

## 9.2 系统对接

- **灵鉴**：① 优化任务候选池增加"处置态 = 优化"过滤（第一优先级改造）；② 等级主数据口径统一（9 档）；③ 素材达标配置增设新品档；④ 候选池"谁值得优化"规则逐步上收。
- **换图决策系统**：处置态字段替代其 v0"人工标注 + 默认保持"过渡方案（《换图决策需求》TBD 第 5 项）；趋势标签与其趋势型候选信号共享计算。
- **商品系统**：下架执行指令（经灵鉴路由）；上架时间回传。

# 11. 实现依赖顺序建议

1. 处置态主数据 + 灵鉴候选池前置闸（即刻止住资源错配，改造量最小）
2. 等级口径统一 + 刷新防抖 + 迁移事件
3. 处置建议规则与审批页（复用换图工作台形态）
4. 趋势标签（与换图趋势信号共建）
5. 新品期：配置包 + 检查点 + 里程碑看板 + 新品素材档
6. 观察态检视与唤醒机制、误杀回验报表
