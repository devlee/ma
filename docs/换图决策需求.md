> 版本：v0.1（讨论结论整理稿）
> 本文档是"经营决策系统"的第一个动作域模块，也是动作标准管线的首个全量实例。
> 待定项统一标注 **TBD**，见文末第 14 节。

# 1. 背景与目标

## 1.1 现状问题

现有换图流程为：人工挑选商品 → 人工打风格标签 → 分发任务 → 设计制作 → 审核 → 推送商品系统。存在三个断点：

- **候选靠人**：优先给哪些商品换图、换什么风格，全部由人凭经验决定，没有规则和数据依据，遗漏不可见。
- **没有效果判定**：换图上线后无人跟踪效果。历史数据分析表明约半数换图 SPU 的核心指标未提升，但无机制识别。
- **不能止损**：换图后表现恶化的商品无法被及时找出并回滚。

## 1.2 目标

将换图纳入动作标准管线，实现决策闭环：

```
触发与候选（规则） → 优先级排序 → 风格建议 + 人审 → 执行 → 效果判定（自动） → 止损 / 战绩沉淀
```

- 候选名单由规则自动生成，每条带证据；人从"从全量里挑"变成"审名单"。
- 风格建议基于风格库战绩自动推荐，人终审。
- 每次换图自动出效果判定，恶化触发回滚建议，战绩回写风格库。
- 风格库升级为带计分卡、有生命周期、有缺口预警的受管资产。

## 1.3 系统分工

| 系统 | 职责 |
|---|---|
| 经营决策系统（本模块所在，新建） | 候选规则、风格推荐、人审决策、效果判定、止损触发、风格库治理、配置管理 |
| 灵鉴 | 纯路由：接收决策系统的任务指令，路由至执行端；状态回传 |
| 灵枢 | 执行：换图任务流转（分发 → 设计制作 → 审核） |
| 商品系统 / CMS | 承接推送的新主图；提供图片版本管理与回滚能力（**TBD**，见第 14 节） |

# 2. 术语

| 术语 | 定义 |
|---|---|
| 换图动作 | 对一个 SPU 更换商品主图的完整动作实例，记录：SPU、原风格 → 新风格、决策人、各节点时间 |
| 推送时间戳 | 新主图在商品系统生效的时间，是效果判定的事件锚点（第 0 天） |
| 风格标签 | 全局唯一的风格分类主数据，按品类管理；与灵枢图库配置的标签为同一套 taxonomy，由风格库负责人统一维护 |
| 转移配对 | "品类 ×（原风格 → 新风格）"的组合。战绩按转移配对统计，而非仅按目标风格 |
| 适配度 | SPU 级的"商品 × 风格"匹配判断（战绩是品类级统计平均，看不见具体商品）。分结构化 / 视觉 / 定位三层，替代现状中人凭审美感觉的判断，见 5.3 |
| 战绩 | 某转移配对（或风格）历史换图的判定结果聚合：起效率、放量成功率、平均提升幅度 |
| 五态结论 | 单次换图的效果判定结论：放量成功 / 效率提升 / 无效 / 图片恶化 / 放量失败 |
| 花费分档 | 判定前按窗口内广告花费变化将样本分为 A 档（持平）/ B 档（放量）/ C 档（缩量），不同档用不同判定标尺 |
| 品类同期校正 | 率类指标变化减去该品类同一日历窗口的整体变化，剔除季节与大盘影响 |
| 探索配额 | 风格推荐中留给验证期新风格的使用比例，仅落在 B/C 级商品 |
| 验证期 | 新风格入库后的培养期：同口径记分、不同方式用分（不进排行、不触发汰换），有毕业 / 淘汰规则 |
| 风格计分卡 | 每个"品类 × 风格"的月度刷新指标卡：战绩、使用、趋势、拥挤度、素材健康 |
| 建议三元组 | AI/规则建议的留痕单元：建议内容 + 人的决策（采纳/修改/驳回及原因） + 最终效果判定 |

# 3. 总体流程

```
每日跑批：候选规则扫描全量在架 SPU → 生成候选名单（带证据）
→ 系统对每个候选生成风格建议 Top 2–3（转移配对战绩 × AI 适配度 × 探索配额，带置信度）
→ 运营在【换图决策工作台】审名单：批准（选定风格）/ 改选 / 驳回（记原因）
→ 批准后生成换图任务（记录原风格 → 新风格、决策人、时间），经灵鉴路由至灵枢换图流程
→ 灵枢：分发 → 设计制作 → 审核 → 推送商品系统；推送时间戳回传决策系统
→ 判定引擎：第 14 天出初判、第 30 天出终判（事件锚定，自动触发）
→ 结论分发：
   图片恶化 → 回滚建议（人批准后执行回滚任务）
   放量失败 → 收投放建议（图片判定挂起）
   全部结论 → 写回 SPU 动作履历 + 转移配对战绩 + 建议三元组
→ 风格计分卡月度刷新 → 风格库治理建议（补图 / 汰换 / 扩用 / 补新风格）→ 风格库负责人拍板

三条回流线：
① 战绩回流：判定结果 → 转移配对战绩 → 风格计分卡 → 库治理与推荐排序
② 适配度校验回流：判定结果按适配分档拆解 → 校准适配度在推荐排序中的权重（季度）
③ 模型迭代回流：人审驳回理由归类 → prompt / 适配模型迭代（附录 A.4）
```

闭环全景：

```
SPU 候选（规则） → 风格推荐（配对战绩 × AI适配度 × 探索配额） → 人审 → 执行 → SPU 五态判定
      ↑                 ↑     ↑                                  │                 │
      │                 │     └── prompt/适配模型迭代 ←── 驳回理由归类               │
      │                 │                                                          │
      └── 库治理决策（补图/汰换/扩用/补新风格） ← 风格计分卡 ← 战绩聚合 + 适配分档校验 ←┘
```

# 4. 候选规则

## 4.1 规则定义（阈值均为可配置参数，见第 10 节）

同时满足以下条件的 SPU 进入换图候选池：

| 条件 | 默认值（待校准） | 说明 |
|---|---|---|
| 处置态 | = 保持 或 优化 | 处置态为清仓 / 下架的商品不换图，避免资源错配 |
| 流量门槛 | 日均 PV ≥ X | 流量太小，换图效果无法测量 |
| 效率信号 | CTR 或 加购率 < 品类基准 × 70% | 双信号任一触发；品类基准 = 该品类同期中位数 |
| 主图使用时长 | ≥ N 天 | 避免频繁换图导致判定窗口重叠 |
| 排除项 | 不在活动锁定期；无进行中换图任务 | — |

## 4.2 候选名单内容

每条候选带证据行，例如：

> SPU-1008630｜品类：连衣裙｜等级：A｜候选原因：CTR 1.2%（品类基准 2.1%），主图已使用 200 天｜当前风格：白底图

## 4.3 名单机制

- 每日跑批刷新；已驳回的候选设置冷却期（默认 30 天，可配置）后才可再次进入。
- 名单按优先级排序：商品等级 > 流量规模 > 效率偏离幅度（权重可配置）。

# 5. 风格推荐

## 5.1 战绩粒度：转移配对

换图效果是"从什么风格换到什么风格"的函数。战绩按 **品类 ×（原风格 → 新风格）** 配对统计；配对样本不足（< 最低样本量）时降级用目标风格的边际战绩，并在置信度中标注。样本充足时可细化到"价格段 × 转移配对"。

## 5.2 推荐流程

1. **候选集与硬过滤**：该 SPU 品类下状态为"推广"的风格，排除：当前风格、疲劳预警 / 归档状态的风格、可用参考图不足的风格、结构化适配不通过的风格（5.3 第一层）。
2. **战绩排序**：按转移配对战绩排序，起效率为主，放量成功加权更高（计分规则见 9.1）。
3. **适配度调整**：按 AI 适配分调整排序（5.3）。战绩与适配度的相对权重为可配置参数，初始值由盲评回填实验校准（5.3.3）。
4. **探索配额**：默认 80% 流量推战绩最优，20% 推验证期新风格或次优。探索配额仅落在 B/C 级商品；S/A 级商品只推荐已验证的"推广"状态风格。
5. **输出**：Top 2–3 建议，每条含双证据：战绩（"该配对历史 14 例、起效率 64%"）+ 适配度（分档 + 理由）、**置信度标注**（样本量不足时明确提示"仅 3 例，参考价值低"）、库内可用参考图数量。

## 5.3 适配度

战绩是"品类 × 风格"级统计平均，看不见具体商品；适配度是 SPU 级个体判断，替代现状中"人凭审美感觉"的环节。分三层：

### 5.3.1 三层信号

| 层 | 实现 | 说明 |
|---|---|---|
| 结构化适配 | 规则（无需 AI） | 风格库为每个风格补"适用条件"元数据（适用品类、材质、色系、价格段、人群调性）；商品属性取自 SCM（材质自动匹配机制已有）。硬性不适配在候选集阶段过滤 |
| 视觉适配 | AI 视觉模型（核心增量） | 模型输入商品图 + 该风格参考图集，判断场景 / 光线 / 构图 / 廓形的协调性，输出**适配分 + 理由**。理由必须输出——人复核看的是理由不是分数 |
| 定位适配 | LLM 文本推理（轻量补充） | 价格段与风格调性匹配（高客单商品不配平价活力风格），结合商品价格、描述、人群信息判断 |

### 5.3.2 人的角色

从"每单凭感觉判断"变为"AI 初筛打分给理由，人持否决权"。人审时改选 / 驳回并注明"风格不搭"的案例，回流用于修正适配模型（提示词与判断标准）。

### 5.3.3 适配度自身的验证（不能假设 AI 审美有效，要测量）

- **上线前盲评回填实验**：让 AI 在不知道效果的前提下，为约 530 个历史换图的"商品 × 所换风格"打适配分，对照实际判定结果。高适配组起效率显著更高 → 信号有效，按相关性强弱定排序初始权重；无差异 → 适配度降级为仅做硬过滤，不参与排序。
- **上线后持续校验**：判定报告按"适配分档"拆解起效率（7.5 节固定段落）；适配度权重随证据按季度校准（与 10.4 同节奏）。

## 5.4 人审

- 运营对每条候选执行：**批准**（选定建议风格之一）/ **改选**（选库内其他风格）/ **驳回**（必填原因）。
- 每条建议记录三元组：建议内容、人的决策、（后续回填）效果判定。用于评估建议质量与放权依据（见第 13 节）。

# 6. 任务生成与执行衔接

- 批准即生成换图任务，任务记录：SPU、原风格、目标风格、参考图、决策人、决策时间。
- 任务经灵鉴路由到灵枢换图流程（分发 → 设计制作 → 审核 → 推送商品系统），流转机制沿用灵枢现有任务模式。
- **推送时间戳必须回传决策系统**——它是效果判定的事件锚点，缺失则该次换图无法判定。
- 推送时同步记录：新主图文件、生效时间、被替换的旧主图版本号（回滚依据）。

# 7. 效果判定引擎

## 7.1 前置处理（每个 SPU 独立）

| 项 | 规则 | 默认值（可配置） |
|---|---|---|
| 事件锚点 | 推送时间 = 第 0 天 | — |
| 投放学习期 | 换图后前 D 天数据不计入 | D = 3 |
| 初判窗口 | 前 [-14, -1] vs 后 [+1, +14]（等长对称） | 14 天 |
| 终判窗口 | 前 [-30, -1] vs 后 [+1, +30] | 30 天 |
| 趋势提示 | 第 7 天出趋势提示，不判定 | 7 天 |
| 品类同期校正 | 率类指标变化减去该品类同一日历窗口的整体变化 | — |
| 花费分档 | 窗口日均花费变化：A 档 ±20% 以内 / B 档 > +20% / C 档 < −20% | ±20% |
| 样本门槛 | 窗口 PV ≥ P 才判率类；订单 ≥ O 才判销量层 | P、O 待校准 |

> 设计依据：判定采用逐 SPU 事件锚定等长窗口，到期自动触发，替代人工分析时"按推送距固定观察日的天数分桶"的近似做法，消除窗口截断、批次混淆、季节漂移三类失真。

## 7.2 指标体系（两层 + 参考项）

| 层 | 指标 | 角色 |
|---|---|---|
| 前端效率层 | CTR（广告端）、加购率（加购数/PV） | 主判定：离图因果距离最近、响应快，止损依据 |
| 生意结果层 | 单访客收入（收入/PV）、转化率（订单/PV）、销量、收入 | 终判定论：叠加确认生意结果 |
| 参考项 | ROAS、花费变化 | 分档依据与红线，不单独作为图片好坏依据 |

数据口径：站内指标取 CMS 口径（PV 维度）；CTR 取广告平台（FB/GG/Feed）按 SPU 聚合（**TBD**：可得性与聚合口径，见第 14 节）。若站内数据可按流量来源切分，**自然流量口径的加购率**作为 B 档情形下不受投放结构影响的干净旁证信号（**TBD**）。

## 7.3 五态结论与触发动作

判定先分档、再按档内标尺出结论。核心原则：**率类指标只在流量结构可比（A 档）时才直接可比；B 档下"花费能放大"本身是正向信号，判定问题变为"放量是否健康"。**

| 结论 | 档位 | 判定条件（校正后） | 触发动作 |
|---|---|---|---|
| 放量成功 | B | 花费显著↑，ROAS 守住红线且单访客收入未显著降 | 风格记**强**战绩；维持/继续放量；沉淀案例 |
| 效率提升 | A | CTR 或加购率显著↑（≥ +10% 相对，待校准），结果层不降 | 风格记正战绩；生成"加大投放试探"建议 |
| 无效 | A | 效率层与结果层均在阈值带内 | 不动；转入其他动作候选（详情页、价格） |
| 图片恶化 | A | CTR 或加购率显著↓（≤ −15% 相对，待校准），初判即可触发 | **回滚建议**（人批准执行）；风格记负战绩 |
| 放量失败 | B | 花费显著↑，ROAS 破红线且单访客收入显著↓ | **收投放建议**；图片判定挂起，回稳后重判或用自然流量口径旁证 |

战绩计分口径：放量失败不计入风格负分（证据指向投放而非图片）；缩量提纯不计分或打折（见 7.4）。

## 7.4 附加标记（叠加在五态上）

| 标记 | 条件 | 影响 |
|---|---|---|
| 承接不足 | 效率层↑但转化率/单访客收入不动或降 | 图有效；触发承接诊断候选（尺码信息、评价、价格），不回滚 |
| 缩量提纯 | C 档（花费显著缩减）下效率提升 | 提示提升可能来自缩量，战绩不计或打折 |
| 活动重叠 | 判定窗口与大促/活动期重叠 | 标记并顺延终判 |
| 样本不足 | PV 或订单未达门槛 | 只出效率层结论或不判定，标注原因 |

## 7.5 聚合报告（自动生成，替代人工分析）

- **起效率总览**：五态分布（起效 = 放量成功 + 效率提升），按品类 / 风格 / 转移配对 / 商品等级 / 价格段拆解。
- **事件时间曲线**：所有 SPU 按"换图后第 N 天"对齐的平均提升曲线（起效时点、见顶、回落），用于校准初判/终判窗口长度。
- **Top 款集中度检查**：Top1/3/5/10 的收入、花费、流量增量占比 + 剔除 Top10 敏感性分析（固定输出段落，沿用既有人工分析方法）。
- **建议质量报表**：AI/规则建议采纳率、被采纳建议的起效率 vs 人工改选的起效率、按适配分档拆解的起效率（校验视觉适配信号有效性，见 5.3.3）。

# 8. 止损与回滚

- **图片恶化** → 系统自动生成回滚建议（附证据），运营批准后生成回滚任务，经灵鉴路由执行，恢复被替换的旧主图版本。
- **放量失败** → 系统生成收投放建议（回预算/回人群），推送投放负责人；图片判定挂起。
- 回滚动作本身也记录时间戳，回滚后可选开启二次观察窗口验证回滚有效性。
- **硬性前提**：商品系统必须保留主图历史版本并支持回滚（**TBD**，第 14 节第 1 项；不成立则止损降级为报警）。

# 9. 风格库治理

## 9.1 风格计分卡（按"品类 × 风格"维度，月度刷新）

| 维度 | 指标 | 回答什么 |
|---|---|---|
| 战绩 | 起效率、放量成功率、平均提升幅度、（细分）转移配对战绩 | 这个风格赢不赢 |
| 使用 | 被打标次数、覆盖 SPU 数 | 用得多不多 |
| 趋势 | 滚动 90 天胜率 vs 上一期 | 在变好还是疲劳 |
| 拥挤度 | 该风格占该品类在架主图的份额 | 同质化风险 |
| 素材健康 | 参考图数量、图龄、使用集中度（是否靠少数几张图撑） | 弹药够不够、新不新 |

计分规则（五态折算、疲劳阈值）与判定阈值同属可配置参数，版本留痕（第 10 节）。

## 9.2 风格生命周期状态机

```
候选（专人新增，未验证）
→ 验证期（探索配额，仅 B/C 级商品，攒判定样本）
→ 推广（毕业达标，进入正常推荐与排行）
→ 疲劳预警（胜率环比下滑超阈值 或 份额触顶）→ 降推荐权重
→ 归档（持续低胜率 / 长期零使用 / 验证失败）
```

每次状态迁移由数据触发建议、风格库负责人拍板并留痕。

## 9.3 验证期与毕业规则（新风格培养期）

原则：**同一套记分、不同的用分**。记分口径与成熟风格完全一致（保证毕业后战绩可比），保护的是分数的使用方式：

- **不进排行榜**：样本未达门槛（默认 10 例判定）前，胜率不与成熟风格同榜比较，仅显示"验证中 x/10"。
- **不触发汰换**：疲劳预警、归档规则对验证期不生效。
- **分层基准**：验证期配额落在 B/C 级商品，毕业考核对比基准为成熟风格在**同等级商品**上的历史起效率，不做全局对比。
- **恶化底线**：培养期不等于无限保护——前 5 例出现 3 例"图片恶化"即提前终止验证。

出口规则（参数可配置）：

| 规则 | 默认口径 |
|---|---|
| 毕业 | 攒满 10 例判定，同层起效率 ≥ 成熟风格同层基准 × 90% → 转"推广" |
| 留级 | 不达标但接近 → 追加一批配额，最多一次 |
| 淘汰 | 留级后仍不达标，或触发恶化底线 → 归档，记录失败原因供负责人复盘 |

同一风格内**新增参考图不单独设培养期**（粒度过细、管理成本不值），但图级使用与效果数据照常记录，供素材健康分析（识别"新图带崩风格"或"老图独撑"）。

## 9.4 库管理三类决策与信号

| 决策 | 信号 | 动作 |
|---|---|---|
| 更新迭代 | 区分两种情形：① 胜率持续下滑 + 各参考图效果普遍变差 = **风格疲劳** → 进疲劳预警、降权重；② 胜率尚可但下滑 + 使用集中在少数老图（同风格内参考图效果分化） = **素材老化** → 补新参考图，风格不动 | 按情形分别处理 |
| 扩大使用 | 高胜率 + 低使用/低份额 + 参考图充足 = 被低估风格 | 提高推荐权重；**跨品类迁移试验**：放入相邻品类的验证期配额 |
| 补充新风格 | ① 品类缺口：换图候选积压多但库内无起效率达标的可推风格（最高优先级）；② 集体疲劳：品类头部风格胜率同步下滑；③ 拥挤触顶：最优风格份额过高，探索配额无米下锅 | 缺口预警自动推送风格库负责人；新风格来源 = 专人经验 + AI 辅助（站内高表现图聚类、外部趋势扫描） |

## 9.5 战绩回填（上线初始化）

既有约 530 个换图 SPU 的风格标签已在系统中记录。上线前用既有数据按本文判定口径回填第一版"品类 × 转移配对"战绩表：

- AI 风格建议第一天即有战绩可依，无需冷启动降级方案。
- 回填过程同时校准初始阈值（第 10.4 节）并验证判定口径可计算性。
- 同步执行适配度盲评回填实验（5.3.3），上线前确定适配度在推荐排序中的初始权重。

# 10. 配置管理

## 10.1 原则

**改"多少"可配置，改"什么"不可配置。**

- **固定（判定的语法）**：窗口结构（事件锚定、前后等长）、花费分档机制、双层指标定义与口径、五态结论集及语义、校正方法、结论到动作的映射、计分卡维度。
- **可配置（判定的参数）**：分档边界、显著性阈值、ROAS 红线、样本门槛、窗口长度、学习期天数、冷却期、探索配额比例、验证期样本量与毕业线、疲劳与拥挤阈值、活动顺延规则。

## 10.2 作用域

全局默认值 + **品类级覆盖**（各品类基准、红线、样本门槛天然不同；高客单品类订单稀疏，门槛更低、终判窗口更长）。商品等级维度的覆盖为后续扩展。

## 10.3 版本化与留痕

- 每次判定结果记录所用配置版本；配置修改仅对新判定生效，**不回溯已出结论**（保证战绩跨期可比）。机制与灵枢描述词模板版本一致。
- 变更留痕：修改人、改前改后值、理由、生效时间。阈值调整视为经营决策，进决策留痕。

## 10.4 阈值校准闭环

- 初始值：用 530 SPU 回填数据校准（如按 CTR 变化分布的分位数定"显著"边界），不拍脑袋。
- 周期复核：每季度用累积判定数据复核——回滚后被证明冤枉的比例、该止损未触发的比例，作为阈值"误判率"指标。**阈值本身也是被复盘的对象。**

# 附录 A：AI 适配度评估的方案设计与 prompt

> AI 辅助方案 ≠ 一段 prompt。prompt 只是五件套中的一环。

## A.1 工程五件套

| 件 | 内容 |
|---|---|
| 输入准备 | 结构化上下文：商品属性（品类/材质/色系/价格段，取自 SCM）+ 商品图 + 风格定义（风格名、适用条件元数据、3–5 张代表参考图）。参考图按素材健康数据选"使用多且效果好"的图代表该风格，非随机抽取 |
| 模板版本化 | prompt 是配置资产：每次修改出新版本，每次调用记录版本号。机制与灵枢描述词模板版本一致 |
| 结构化输出 | 强制 JSON schema（见 A.3），禁止自由文本，保证可统计、可进报表 |
| 后处理校验 | schema 校验 + 一致性检验（盲评阶段同一输入跑 2–3 次，分歧大标记"低稳定"不进统计）；温度 0–0.3 |
| 留痕 | prompt 版本号写进建议三元组，与人的决策、最终判定关联，支持按版本拆解建议起效率 |

## A.2 prompt 设计原则

1. **拆维度评分**，不要整体感觉分——五个维度各自打分给理由，人复核可定位分歧、迭代可定位改哪里。
2. **明确判断边界**：评估的是协调性，不是美观度、不是商品好坏、不是销量预测（模型最易跑偏点）。
3. **锚定样例（few-shot）**：2–3 个带专家结论的例子（高适配 / 低适配 / 边界案例），钉住打分尺度。样例由风格库负责人挑选并写结论——本身是审美经验显式化的过程。
4. **允许说不知道**：信息不足时对应维度输出 null 并说明，置信度降档；低置信建议在工作台降权展示。
5. **强制输出"最大风险"**：一句话的最大不适配风险，是人审时最有用的信息，也是与否决理由对照的锚点。
6. **禁止越界**：不推荐清单外风格、不建议修改商品。

## A.3 prompt 模板（v0）

```
【角色】
你是服装电商的视觉风格适配评估专家。你的任务是评估一个商品与一个目标图片风格
的适配度：如果将该商品的主图制作成目标风格，视觉上是否协调。

【重要边界】
- 你评估的是"商品与风格的协调性"，不是图片美观度，不是商品好坏，不是销量预测。
- 只依据下面提供的图片和信息判断，不要臆测未提供的属性。
- 不要推荐清单之外的其他风格，不要建议修改商品。

【商品信息】
品类：{品类}｜材质：{材质}｜主色系：{色系}｜价格段：{价格段}
商品图：{商品图1..n}

【目标风格】
风格名：{风格名}
风格说明与适用条件：{风格库元数据}
该风格代表参考图：{参考图1..5}

【评估维度】（每项 1–5 分，各附一句具体理由；信息不足则该项填 null 并说明）
1. 场景协调：商品置于该风格典型场景中是否自然
2. 光线质感：商品材质在该风格光线处理下的呈现（如缎面反光 vs 柔光哑光）
3. 廓形姿态：商品版型与参考图的模特姿态、构图方式是否兼容
4. 色彩关系：商品主色与风格整体色调的搭配关系
5. 定位调性：商品价格档次与风格传达的档次感是否一致

【输出格式】（严格输出 JSON，不要输出其他内容）
{
  "dimensions": [
    {"name": "场景协调", "score": 4, "reason": "……"},
    ...
  ],
  "overall_grade": "高|中|低",
  "top_risk": "最大不适配风险，一句话",
  "confidence": "高|中|低"
}

【打分锚定示例】
示例1（高适配）：{商品+风格+专家评分与理由}
示例2（低适配）：{……}
示例3（边界案例）：{……}
```

说明：`overall_grade` 用三档；参与排序计算的是五维分数的加权，权重在系统侧配置（不写死在 prompt 里），便于盲评实验后调整。

## A.4 prompt 迭代机制（靠证据改，不靠感觉改）

- **盲评回填实验**（5.3.3）：分维度对照实际判定结果——整体相关性定适配度权重；**分维度相关性**定去留，没有信息量的维度删除（prompt 应越改越短）。
- **驳回理由归类**：人审驳回理由定期归类（可用 LLM 辅助），高频驳回模式 = prompt 缺的约束或维度。
- **版本对比**：每次改版出新版本号，季度对比各版本建议的起效率——prompt 迭代自身走"改动 → 数据裁决"闭环。
