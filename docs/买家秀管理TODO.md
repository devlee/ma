## 3. 功能开发（从演示到可用）

当前 8 个页面为 mock + 内存 store 的可交互演示，刷新即重置。接入真实系统需要：

| 状态 | 项 | 说明 |
|---|---|---|
| ⬜ | 接口层 | 抽 `src/api/`，替换 store 中的内存操作；主任务/子任务/素材/模板/词典 CRUD |
| ⬜ | 灵鉴对接 | 接收主任务（灵鉴任务 ID、SPU、品类、需要数量）；回传节点：待领取 / 制作中 / 待审核 / 已推送 / 废弃（需求 9.1） |
| ⬜ | CMS 推送 | 主任务进入待推送后自动整体推送；以子任务编号为幂等键；失败进【推送失败】并支持审核页重推（需求 9.2） |
| ⬜ | nano banana 生图任务 | 子任务创建 → 生图中 → 成功/失败 的异步回调；生成次数、版本历史落库 |
| ⬜ | 质检图 / 商品图数据源 | 质检图按角度存储；商品图兜底规则（主图 = 正面，其余需手动选） |
| ⬜ | 文件上传 | 质检图上传、上传覆盖结果图、素材批量上传；CMS 尺寸限制确定后加校验 |
| ⬜ | 权限接入 | 用真实登录角色替换 `RoleContext` 的手动切换；按需求第 12 节矩阵控制菜单与按钮 |
| ⬜ | 面板数据 | 六个模块的统计接口与筛选（时间范围、品类、制作人、制作方式）；设计角色仅看自己 |
| ⬜ | 工作量统计 | 按主任务制作方式分系数，仅统计已推送子任务（需求第 13 节） |
| ⬜ | 操作日志 | 子任务全部操作落日志（当前为 mock） |
| ⬜ | 主任务状态推导 | 按需求 8.4 节优先级在服务端实现，前端只展示 |
