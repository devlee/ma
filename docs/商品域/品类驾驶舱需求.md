# 1. 背景与目标

## 1.1 现状

- **品类画像散在文档**：价格段、颜色、尺码、销量集中度等分析以人工文档形式存在，无固定口径、无更新节奏、无历史序列。
- **品类级决定无统一入口**：该补什么款、该下什么款、资源往哪个品类倾斜、品类质量是否恶化——这些决定分散在各处（灵鉴配置、人工报表、运营经验），互相看不见。
- **月会数据复盘依赖人工整理**：每月重复劳动，且各期口径可能漂移。

## 1.2 定位

- **决策工作台，不是看板**：报表系统回答"数字是多少"，驾驶舱回答"该做什么决定"。**每个数字必须通向一个决定**，挂不上决定的信息不收（留在报表系统）。指标分两类：**触发指标**出现在 5.3 清单的触发条件里；**证据指标**不触发结论，作为结论的证据和下钻用（件单价、C–S 等级占比、平均单 SPU 销量、单访客收入这类）。两类都要能说出服务哪条结论，说不出的不收。
- **与各模块报告的分工**：驾驶舱放**摘要行 + 异常触发 + 跳转**，深度分析留在各模块自己的报告页（换图聚合报告、新品里程碑看板、处置建议审批页）。驾驶舱的角色是"路由到决定"。此分工对所有模块统一复用。
- **节奏定位**：月度品类决策视角（目标环）。面板数据日刷，随时可看；结论只在快照日出，差距成立只认快照（《灵策总纲》3.6）。周度动作节奏由各动作域自己的工作台承接（动作环）。

## 1.3 收纳原则：五类品类级决定

驾驶舱收什么内容，以"是否服务于品类级决定"为唯一标准。下面五类是按衣服大类写的（适用范围见 1.5），鞋+ACC 大类二期另定：

| # | 决定类型 | 回答的问题 | 结论（5.3 的「决定」列） | 出口（第 6 节分组） |
|---|---|---|---|---|
| 1 | 结构决定 | 商品盘子对不对（数量、价格段、颜色、尺码的供给结构 vs 销售结构） | 毛利恶化（结构性）、盘子老化、结构错配两条、高毛利段供给不足、大码与色系机会 | 补款建议、收缩建议、配置建议 |
| 2 | 进出决定 | 该补什么款、该下什么款 | 下架积压、结构错配·供给不足、盘子老化 | 下架待办、补款建议 |
| 3 | 投入决定 | 资源（设计产能、营销费用、优化任务）往哪些品类/商品倾斜 | 投放与份额错配、投放未跟等级、过度集中、过度分散、头部降档无接替、降档激增、漏斗分叉、去红差距 | 第二梯队培养、跨域议题（营销）、规划会议题；横比在列表页指标视图 |
| 4 | 新陈代谢决定 | 新品补充的节奏和质量够不够 | 上新配额未达成、上新质量、素材完备度差距、换图持续无效、风格单一 | 上新方向输入、素材单、换图持续无效信号 |
| 5 | 红线决定 | 品类有没有质量/服务问题在恶化 | 红线触发 | 红线预警 |

五类决定、结论、出口三者要对得上：每类决定至少有一条结论，每条预警或机会级结论至少有一个决策区出口。

## 1.4 使用角色

主用户：管理层 + 运营负责人；站点 Owner 可查本站点切片（《灵策总纲》10.3 权限矩阵）。当前未设"品类负责人"独立角色；若未来设立，驾驶舱即其首页——信息架构按此预留，见 **TBD** 第 1 项。

## 1.5 适用范围

驾驶舱是一种模式，页面只有一个；大类之间差的是面板集和结论清单，按大类配置。

- **v1 只为衣服大类编写**：第 4 节的八个面板、第 5 节的结论清单与总评规则，都是衣服 8 个品类的版本。
- **鞋+ACC 大类二期**。它 20 多个品类、销售额不到 3%，和衣服的差别不是指标多少，而是决定类型不同：它的价值很可能不在自己的盘子而在连带（拉客单价、和哪些衣服一起买），鞋有尺码但没有大码定制码，ACC 多数没尺码，素材达标要求也不同。二期先重写它的决定类型，再从决定类型倒推面板集，不拿衣服的八个面板删改。见 **TBD** 第 9 项。
- **二期之前鞋+ACC 不是不存在**：对象、GMV 与销量数据、品类梯度、规划表里的行、产能配额一期就有（加总校验和结构篇的大类贡献占比要用），只是不配面板、不跑结论清单、不出处置建议（《商品对象层需求》6.4）。
- 配置作用域因此加一层大类：全局默认 → 大类覆盖 → 品类覆盖（将来 + 站点）。面板集、结论清单、等级门槛、素材达标要求都挂在大类层。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 常驻面板 | 画像区固定展示的指标面板，无论有无异常均展示，颜色取该面板参与的结论的最高级别 |
| 触发指标 / 证据指标 | 触发指标出现在结论清单的触发条件里；证据指标不触发，作结论的证据和下钻（1.2） |
| 诊断结论 | 对清单每条规则的显式结论输出；无异常时输出"本期正常"而非空白 |
| 提示 / 预警 | 结论级别（5.2）。旧称「提示型信号 / 可执行型信号」，5.4 的分档推进指的就是从提示级升到预警级 |
| 结构错配 | 某维度（价格段/颜色/尺码）的销售占比与在架占比显著失衡 |
| 集中度 | 品类销量向头部 SPU 集中的程度：绝对口径 Top5 / 10 / 20 占比，相对口径 Top5% / 10% / 20% 占比，再加平均单 SPU 销量 |
| 去红毛利率 | 去掉活动红包后的毛利率；红包使用情况本身在运营域活动面板看，本页只看去红后的结果 |
| 组合结论 | 要同时看两个以上面板才成立的诊断结论，如动销走低 + 观察态积压 = 盘子老化 |
| 机会 | 结论的第四级：不是问题，是没吃到的需求；带验证指标与窗口，出口可能在别的域 |
| 系统结论 | 结论清单里的规则在快照日自动出的结论 |
| 人工结论 | 清单之外人登记的结论：新问题或新机会、对系统结论的归因补充、对系统结论的否决或降级 |
| 品类总评 | 一个品类一条的整机级判断：姿态 + 主要矛盾 + 一句话 + 依据 |
| 姿态 | 总评里的资源方向，四选一：加码 / 维持 / 修复 / 收缩；新品类可标观察 |
| 系统性结论 | 同一条结论在大类内横跨的品类数过半；出口改为总盘诊断议题，不逐品类开单 |
| AI 候选 | AI 提出、人未采纳的候选结论或候选规则；采纳后成为来源标 AI 的人工结论 |
| 纵视图 / 横视图 | 驾驶舱一个品类看所有指标；列表页一个指标看所有品类。同一口径同一快照 |
| 月度快照 | 每月固定日对驾驶舱全量数据、品类总评、系统与人工结论、决策区状态的归档，月会品类分册的自动生成源 |

# 3. 信息架构：两页一组

同一组指标两个方向看。品类驾驶舱是**纵视图**：一个品类、所有指标，回答「这个品类该做什么」。品类列表页是**横视图**：一个指标、所有品类，回答「资源往哪个品类倾」和「这是品类的问题还是全局的问题」。两页同一口径、同一快照、同一套健康色和阈值，只是行列转置，不另建报表。横视图上点一格，落到该品类驾驶舱的对应面板。

## 3.1 品类驾驶舱：一页四区

```
品类驾驶舱（单品类一页，品类列表页入口）
├─ 画像区：八个常驻面板（第 4 节）—— v1
├─ 诊断结论区：总评 / 系统结论 / 人工结论 / AI 候选（第 5 节）—— v1（AI 候选分期）
├─ 决策区：建议与待办聚合（第 6 节）—— v1
├─ 规划区：规划表该品类五板块的只读投影（L2 接入后启用，v1 仅素材目标占位）
├─ 节点区：旺季拐点 / 大促 / 上新日历（L2 节点日历接入后启用，v1 留位）
└─ 款级分析抽屉：等级迁移、集中度款级清单、处置建议（SPU·SKU 格，内容见《商品对象层需求》第 6 节）—— v1
```

两个抽屉：画像区每个指标名可点开「本指标在各品类」，排名加全站值，不离开当前页就能对照，这是横视图的轻量入口；面板二、三的款级数字可点开款级分析抽屉。

**规划区和面板目标列的分工**：规划区是规划表该品类五个板块的全量只读投影（目标 / 现状 / 差距三列）。面板一、五、六只带自己指标的目标列，取的是同一份投影，不另存。规划差距的红黄绿在两处显示同一个值。

## 3.2 品类列表页：三个视图

| 视图 | 行 × 列 | 格子 | 用途 |
|---|---|---|---|
| 总评视图（默认） | 品类 × 总评字段 | 姿态、主要矛盾、连续月数、规划差距红黄绿、异常数与机会数 | 管理层横扫；月会议程排序 |
| 指标视图 | 品类 × 一个面板的指标组，顶部切换八个面板 | 值 + 环比箭头 + 健康色；列头可排序 | 投入决定；总盘驾驶舱对象树下钻的落地页（GMV 落后 → 经营结果列组） |
| 结论视图 | 结论 × 品类 | 级别色 | 看哪条结论横跨多个品类；系统性结论从这里出（5.3） |

三个视图共同规则：按大类分组、梯度排序，分组表头带该大类的姿态分布与贡献占比；站点过滤同驾驶舱切片，v1 只切数据不出结论；只在大类内比，鞋+ACC 不和衣服混排（1.5）。

**可比性**：绝对值跨品类比没有意义，大品类永远排前面。指标视图默认展示占比、率和「相对自身历史的分位」，绝对值作辅助列。Top10% 这种相对口径就是为跨品类可比设计的。

**指标视图的列组**：三维和分布类面板平铺不开，每个面板选 3–5 个能横比的指标做列组，列组在配置中心可改：

| 面板 | 列组（默认） |
|---|---|
| 一 经营结果 | GMV 占比、GMV 同比、毛利率、去红毛利率、营销费用占比 |
| 二 商品数量与处置态 | 在架 SPU 数、动销率、观察态占比、下架建议中数 |
| 三 等级与集中度 | C–S 等级 SPU 占比、Top10% 销量占比、本月净降档数、平均单 SPU 销量 |
| 四 结构三维 | 最大错配维度及其差值、大码+定制码销量占比、高毛利段销售占比 |
| 五 新品健康 | 本期上新数、配额达成率、新品成功率、测款失败数 |
| 六 素材 | 完备度达标率、换图有效率、超期未换图占比、最大单一风格占比 |
| 七 营销 | 访客数环比、加购率、转化率、ROAS |
| 八 红线 | 客诉率、争议率、退款率（各带同比） |

**L2 前的替代**：总评视图的规划差距列，在规划表上线前用 GMV 同比代替并标注「同比替代」；梯度排序在梯度未录入前按 GMV 占比临时分档。上线后自动切换，不改页面。

## 3.3 v1 范围

- **驾驶舱 v1：画像区 + 诊断结论区 + 决策区**；列表页 v1 三个视图都做，它们读的是驾驶舱已有的数据。规划区（规划表该品类的只读投影：目标/现状/差距三列）与节点区（节点实例倒计时 + 进行中节点的叠加包达成）内容由《品类规划需求》定义，随规划上线启用。
- **站点口径（v1 即拆站点）**：数据视图全拆——八面板支持"全站 + 各 S 级站点"切片与对比，月度快照按全站 + 各主要站点归档；**诊断与信号层 v1 统一跑全站口径**，站点切片只展示数据不出结论，待全站阈值校准稳定后按站点逐个开启（配置作用域届时加"站点覆盖"层，与品类覆盖同机制）。粒度区分：**规划差距（红黄绿）是机械计算**（目标 − 现状，无需阈值校准），按站点 × 品类粒度展示不受此限；"全站先行"只约束需要阈值校准的诊断信号。
- 阅读顺序即面板顺序：先结果，再盘子，再等级，再结构，再过程，最后红线。

# 4. 画像区：八个常驻面板

每个面板统一具备：核心指标 + 环比（同比适用时）+ 健康状态标识 + 动作出口（跳转或建议入口）。面板数据日刷。

**面板颜色不单独算**：一个面板的颜色 = 该面板参与的结论（5.3 「用到的面板」列）在上一个快照日的最高级别，正常绿、提示黄、预警红、机会蓝；被人否决为「本期不成立」的结论不参与取色。面板和结论区永远一致。

同一个派生数可以出现在不同面板里：动销率、平均单 SPU 销量、分渠道费用与 ROI 在几个面板都有，因为各自回答的业务问题不同。诊断结论按第 5 节的结论归属，不按指标出现在哪个面板。

## 4.1 面板一：经营结果

| 指标 | 说明 |
|---|---|
| GMV / 销量 / 件单价 / 销量占比 / GMV 占比 | 环比 + 同比双对比（品类旺季属性使同比必要）。占比指本品类占全站的份额 |
| 毛利率 / 去红毛利率 | 成本口径 = 面料 + 工费 + 物流（是否含退款损耗待定义，**TBD** 第 2 项）。去红毛利率 = 去掉活动红包后的毛利 |
| 营销各渠道费用与 ROI | 环比 + 同比 |
| 动销率 | 有销量的 SPU 数 / 在架 SPU 数 |
| C–S 等级数量与销量占比 | C–S 等级 SPU 数 / 在架 SPU 数；C–S 等级 SPU 销量 / 品类总销量 |
| 平均单 SPU 销量 | 销量 / 在架 SPU 数 |

- 利润不下放品类（《灵策总纲》3.2 可控性原则），本面板只到毛利。红包使用率、折扣深度在运营域活动面板看，本面板只放去红后的结果。
- 动作出口：毛利率恶化 → 定价/成本核查；营销占比侵蚀毛利 → 投放策略调整；与面板四联动（销售向低价段集中通常与毛利恶化互为印证）。
- 数据前置：SPU 级成本若暂不可得，v1 用品类级成本率估算，**面板上标注口径**；去红毛利率需要把订单级红包摊到 SPU 的规则，登记进指标树口径字典（**TBD** 第 7 项）；分渠道费用到品类的归属方式见 **TBD** 第 8 项。
- 规划区上线后，GMV、销量、占比三项带目标列，取规划区同一份投影（3.1）。

## 4.2 面板二：商品数量与处置态

- 在架 SPU 总数及趋势；处置态四态分布（保持/优化/观察/下架建议中）。
- **观察态积压数**：观察池规模与停留时长分布（对象层四道防护的品类级监督视图）。
- **动销率**：近 30 天有销 SPU 占比。动销率走低 + 观察态积压走高 = 品类盘子老化的组合结论（见 5.3）。

## 4.3 面板三：等级与集中度

- **等级分布**：S–F 9 档 SPU 数与销量占比（来自对象层主数据）+ 环比迁移（升/降档数量，来自等级迁移事件）。同一张表带各档的花费、花费占比、ROI，看投放有没有跟着等级走。
- **集中度**：

| 指标 | 口径 | 回答的问题 |
|---|---|---|
| Top5 / 10 / 20 销量占比 | 头部款销量占品类比 | 单点依赖风险——头部掉量整个品类塌 |
| Top5% / 10% / 20% 销量占比 | 销量靠前的 SPU 的销量占比（相对口径） | 跨品类可比（大小品类用绝对 Top10 不公平） |
| 平均单 SPU 销量 | 销量 / 在架 SPU 数 | 在架 SPU 的平均销量，和头部占比对照看腰部厚度 |

- 阈值来源、水平与趋势两类触发、提示级升预警级的推进方式，统一写在 5.4。
- **两端都判断**：过度集中 → 头部款红线关注 + "第二梯队培养"建议（从 B 级挑潜力款倾斜资源）；过度分散（Top10 占比显著偏低且无上行）→ 缺爆款信号，检查营销聚焦。

## 4.4 面板四：价格段 × 颜色 × 尺码三维

- 价格段 × 颜色 × 尺码，每一维展示**销售占比 vs 在架占比**双柱对比。价格段按区间划分，区间按品类配置；颜色除单个颜色外按色系统计；尺码除单个尺码外统计大码和定制码。
- 错配即结构失衡信号：某分段销售占比高而在架占比低 → 供给不足（喂决策区补款建议）；反之 → 供给过剩（结合处置态看是否该收缩）。
- 价格段错配与面板一毛利联动看。
- 后续扩充为商品企划数据板块。
- 数据前置：SKU 级颜色/尺码销售数据核验（**TBD** 第 3 项，本模块最大数据前置）；色系映射、大码与定制码的定义走配置中心品类覆盖。

## 4.5 面板五：新品健康

- 新品上架情况与规划情况：本期上新 SPU 数、规划上新配额与达成。L2 上线前只有实际数，配额由品类规划表接管后补目标列。
- 新品成功率（毕业进入目标档位比例，L1 先行指标的品类切片）。
- 在保护期 SPU 数、各检查点通过率（达标/预警/触线分布）、测款失败数。
- 动作出口：跳转新品里程碑看板；成功率持续偏低 → 诊断结论区触发"上新质量"信号。

## 4.6 面板六：素材完备度与商品图新鲜度

- **完备度**：各等级 SPU 按素材达标要求的达标率（买家秀、颜色图、大码图、风格图覆盖）——先行指标，素材先行、销量滞后。
- **目标 vs 现状**：v1 目标值来自品类配置包静态配置；L2 上线后目标列取规划区同一份投影（3.1）。差距直接生成灵枢任务量预估。
- **商品图新鲜度（换图摘要行）**：近 90 天换图判定 N 例、有效率 X%、恶化 Y 例（带环比箭头）+ 换图覆盖率（超期未换图 SPU 占比、检视队列积压）。**一行摘要，不展开五态明细**；点击跳转换图聚合报告（《换图决策需求》7.5）的本品类切片。
- **商品图风格分布与表现**：本品类在架 SPU 主图按风格库风格归类后的占比，旁边放每个风格在本品类的表现（CTR、近 90 天换图有效率，取风格库计分卡的品类切片）。回答的是「这个品类是不是押在一种风格上，押的那种还灵不灵」。单一风格占比过高、或主流风格表现下滑 → 换图单的目标风格建议；点击跳转风格库计分卡。

## 4.7 面板七：营销效率

- 访客数、**加购率**、转化率、单访客收入（GMV 掉了，是流量掉了、加购掉了还是转化掉了——诊断分叉点；加购率是"到店但没进一步"与"进一步但没成交"之间的分割线）。
- 品类 ROAS、花费占比（品类间营销资源分配信号）。
- 边界：**取指标不取操作**——广告组层级的出价/预算操作留在投放系统，驾驶舱只收影响品类决定的聚合指标。

## 4.8 面板八：服务与交付红线（待定）

- 客诉率、争议率、退款率（**含同比/环比趋势**）——护栏红线指标的品类拆解，重点关注变化而非绝对值。退款原因结构暂不展开。
- 平均交付周期、延迟发货率——定制模式下交付喂客诉，供应链板块在品类视图的第一个探头。交付数据依赖供应链侧接入，**可二期**（**TBD** 第 4 项），界面位置 v1 即留出。
- 动作出口：恶化 → 质检/详情页核查/暂停放量建议；触发（水平触线或趋势恶化预警）→ 按红线机制升级（红线值与升级路径引用《战略目标层需求》4.4 护栏红线登记表，本面板不自定义）。

## 4.9 核对过但确认不收的

| 项 | 理由 |
|---|---|
| 利润、贡献利润 | 利润不下放品类，品类层只看毛利（《灵策总纲》3.2） |
| 红包使用率、折扣深度 | 属活动，在运营域活动面板看；本页只放去红毛利率 |
| 库存类指标 | 无库存模式不适用（沿用对象层决策记录） |
| 广告组操作指标、客诉工单明细 | 取指标不取操作，操作出口留在各自系统 |
| 竞品/市场外部数据 | 暂无数据源；未来机会类结论的可能来源 |
| 换图判定明细 | 住在换图聚合报告，驾驶舱只放摘要行（1.2 分工原则） |

# 5. 诊断结论区

本页承接诊断矩阵的**大类·品类 × 商品**。结论区四层：最上面是品类总评（5.6），一个品类一条；其下是系统结论（5.3 清单）；人工结论（5.5）和系统结论排在一起，来源标「人工」；最下面是 AI 候选（5.8），人采纳后才变成结论。SPU·SKU 那一格的款级分析 v1 做本页抽屉，内容定义在《商品对象层需求》与《换图决策需求》，不在这张清单里。面板七、面板八是营销域、客服/供应链域的摘要行，域启动后改成跳转，诊断结论仍先出在本页。

## 5.1 每月怎么出结论

1. **系统跑清单**。快照日系统对每个品类把 5.3 清单全部跑一遍，每条出正常 / 提示 / 预警 / 机会，附证据。清单全部条目 × 所有品类都是机器出的，人不逐条过。
2. **系统做系统性判定**。同一条结论横跨大类内过半品类的标「系统性」，上交总盘，不再往各品类推出口（5.3）。这一步在推逐品类出口之前。
3. **系统起草总评**。按 5.6 的优先级给出建议姿态和依据。
4. **人只处理三样**：非正常项（确认、否决写理由、或补归因）；清单外的事（登记人工结论）；总评（确认姿态、改姿态写理由、写一句话和主要矛盾）。正常项展示但不用点，存档证明的是系统跑过，不是人看过。
5. **复核完成**。月会前运营负责人点「本期复核完成」，未点的品类在列表页标「未复核」。
6. **归档**。系统结论、人工结论、总评连同状态和派生单号一起进月度快照。

人的工作量跟异常数走，不跟清单长度走。清单是下限，保证「系统看了没事」和「没看」能区分；清单外的判断靠人工结论进来。

## 5.2 结论四级

| 级别 | 含义 | 后续 |
|---|---|---|
| 正常 | 看了，没事 | 只记录 |
| 提示 | 有信号，阈值未校准或幅度不够 | 展示 + 进历史序列。出口只写「方向」，不进决策区、不开单；持续 N 期或校准后升预警才接出口 |
| 预警 | 问题成立 | 进决策区：生成建议、开单或跳转 |
| 机会 | 不是问题，是没吃到的需求 | 进决策区：本域能做的开单或改配置；跨域的进跨域议题；带验证指标与窗口 |

提示、预警、机会三级都必带触发规则、证据数据；预警和机会还必带出口链接。全部正常时输出「本期 N 项全部正常」，不留空白。四级对系统结论和人工结论通用。

**系统性结论**：同一条结论在同一大类内横跨的品类数超过阈值（默认过半），列表页结论视图把它标为「系统性」。系统性的结论不是品类的事：出口从逐品类开单改为一条总盘诊断议题，交总盘驾驶舱诊断结论区（《战略目标层需求》8.1），各品类页上该条结论显示「系统性，见总盘」，不重复推建议。8 个品类同时毛利恶化是成本或汇率的问题，不是 8 个品类各自的问题。

## 5.4 阈值、触发与清单版本

- 不拍固定数值。初始阈值 = 品类自身近 12 个月历史分位数（如超自身 P90 触发），全局默认 → 大类覆盖 → 品类覆盖，走统一配置机制。
- 每条规则含**水平型**（超阈）与**趋势型**（连续 N 期同向）两类触发，与换图候选信号同构。
- **分档推进**：新规则先以提示级上线；运行 2–3 个月以真实分布校准阈值后，升为预警级并接决策区出口。面板三集中度是第一个走这条路的。
- 规划差距（目标 − 现状）是机械计算，不走阈值校准。
- **清单是配置，带版本号**。固定的是版本，不是永远：加规则、改阈值、下线规则都在配置中心留痕，快照记当期用的清单版本，历史序列才可比。
- **规则下线**：一条规则连续 12 期在全部品类都正常，或连续出提示但从未被处理，进下线候选，季度校准时决定。
- **季度校准会**三件事：阈值校准、规则下线、候选规则入选。候选规则来自人工结论反复出现（5.5）和 AI 候选规则（5.8），入选前提是带回测。

## 5.5 人工结论：清单之外的结论

清单只覆盖事先想到的。清单外的结论有三种，都走人工结论：

| 种类 | 例子 | 处理 |
|---|---|---|
| 新问题或新机会 | 某品类因外部热点起量；某供应商换面料导致某颜色退货集中 | 登记为新结论，四级任选 |
| 对系统结论的归因补充 | 系统说毛利恶化，人判断是 X 面料涨价 | 挂在该条系统结论下，不另起一条 |
| 对系统结论的否决或降级 | 系统说过度集中，人判断是旺季头部冲量的正常现象 | 该条标「本期不成立」+ 理由，留痕；否决率是规则校准的输入 |

一条人工结论一张卡，字段和系统结论同一套，多一个来源标记：

| 字段 | 说明 |
|---|---|
| 观察 | 一句话说看到了什么 |
| 证据 | 引用哪几个面板的哪几个数，系统带上当期截片 |
| 判断与级别 | 为什么认为是问题或机会；提示 / 预警 / 机会 |
| 建议动作 | 可以多条，每条标所属域（商品 / 运营 / 营销 / 供应链 / 客服） |
| 验证指标与窗口 | 机会类必填，从指标树引用，窗口默认两个季度 |
| 状态 | 同 5.7 生命周期；机会类多待验证 / 验证到期 |
| 登记人、时间 | 留痕 |

采纳后的出口：

- 商品域能做的，开意图单（素材单、换图单、处置单）或改品类配置包；标准类调整走配置中心，不开单。
- 跨域的，进决策区跨域议题行，由月会拍板。域启动后改成直接派生该域的单据（活动单、预算分配单）。
- 战略级的（如「大码人群是增长点」），登记为战略假设（《战略目标层需求》4.2 策略判断），走战略环。

验证到期时系统按验证指标出一条结论，写明成立还是不成立。同类人工结论反复登记的，提升为 5.3 的规则，路径同提示级升预警级。AI 给人工结论供草稿的分期见 5.8。

## 5.6 品类总评

清单是零件级的，回答「哪里不对」；总评是整机级的，回答「这个品类整体该怎么办」。月会横比品类、规划会调梯度、产能排优先级，用的都是这一条。**不做健康分**：不同性质的信号加权平均后什么都说不出来，而且人会去优化分数。唯一能用数字表达的整机信号是规划差距的红黄绿，因为它是机械算的。

一个品类一条，四部分：

| 部分 | 内容 | 谁出 |
|---|---|---|
| 姿态 | 加码 / 维持 / 修复 / 收缩，新品类可标观察。对应资源方向 | 系统建议，人确认；改了写理由 |
| 主要矛盾 | 只挑一个：本月最该解决的是什么，决定下月动作包往哪压 | 人从非正常结论里选 |
| 一句话判断 | 例：「盘子老化叠加头部降档，结构失衡在低价段，建议修复」 | v1 运营负责人写；将来系统按模板起草 |
| 依据 | 规划差距红黄绿；当期预警与机会结论；连续几个月同一姿态 | 系统带出 |

**系统建议姿态的优先级**（不打分，按序判断）：

1. 有红线预警 → 修复。
2. 规划差距红，且有盘子老化、结构错配、头部降档这类结构性预警 → 修复；若品类梯度为常规或小品类且连续多月如此 → 收缩。
3. 规划达成，且有机会类结论 → 加码。
4. 其他 → 维持。

系统建议和人确认两个值都存。一致率是校准指标；v1 系统建议为提示级，跑几个月后再决定要不要让系统直接出。被否决的系统结论不计入上面的预警数。

**L2 前的替代**：规则 2、3 用到规划差距和品类梯度。规划表上线前，规划差距用 GMV 同比代替（同比为负视为红）；梯度未录入前按 GMV 占比临时分档，第 2 条里「常规或小品类」按临时档判断。依据里标注「替代口径」，上线后自动切换，历史总评不回算。

**姿态与梯度不符是通向战略环的桥**。姿态是月度读数，不改梯度也不改目标。但第一重点品类连续 3 个月「收缩」、或小品类连续 3 个月「加码」（月数走配置），系统自动生成一条规划会议题，候选动作是调梯度或校准目标。《战略目标层需求》5.3 说梯度季会可调，依据从这里来。

**放在哪**：诊断结论区首行；品类列表页一列（姿态、主要矛盾、连续月数）；月会品类分册首页；月度快照。大类层不单独诊断，大类是静态归类，它的读数就是下属品类的姿态分布加大类贡献占比对结构篇，放品类列表页的分组表头；总盘驾驶舱结构面板加一行「各梯度下品类姿态分布」（《战略目标层需求》第 8 节）。

## 5.7 结论生命周期

| 状态 | 含义 |
|---|---|
| 新出 | 本期首次成立 |
| 持续 | 上期已有，本期仍成立。提示连续 N 期持续自动升预警（N 走配置）；被否决的期数不计 |
| 处理中 | 已开意图单或已做配置变更，挂单号或变更记录；再次成立时显示处理中，不重复推建议 |
| 已处理仍持续 | 派生的单已判定无效或配置已变更一期以上，结论仍成立。不再推同一建议，出口改为换方案或升级：预警级进月会议题，机会级转人工结论重写假设 |
| 已消失 | 本期不再成立；保留历史 |
| 本期不成立 | 人否决了系统结论，带理由；不计入连续期数、总评预警数和面板取色；规则校准时统计否决率 |
| 待验证 / 验证到期 | 机会类专用，到期自动出验证结论 |

系统结论、人工结论、总评连同状态、派生的单号一起进月度快照，构成品类健康历史序列。与检视队列「检视通过也是产出」同构。

## 5.8 AI 候选

规则看事先想到的，人看经验覆盖的，AI 补第三个来源：在没写规则的地方找候选。定位是**候选结论的来源**，不是第四种诊断。它走人工结论的那张卡、那条验证路径、那条升级路径；人采纳前它什么都不是。

**边界**

- 不自动定级。AI 产出一律是「候选」，人采纳后才成为提示、预警或机会，来源标「AI」。
- 不开单、不改配置、不进决策区。
- 只引用指标树字典里的指标，不自造指标。
- 不实时。和清单一样在快照日跑，月度一批。

**三类产出**

| 类型 | 做什么 | 分期 |
|---|---|---|
| 归因草稿 | 对每条系统结论，把当期能解释它的数据摆出来（低价段占比升、某站点清仓、红包加深）；人判断哪条成立，即 5.5 的归因补充 | 一期 |
| 总评起草 | 按 5.6 的四部分起草一句话判断和主要矛盾候选，人改后确认 | 一期 |
| 无规则异常 | 在指标 × 品类 × 站点 × 月上做异常和拐点检测，提出清单外的候选结论 | 快照满两三个季度后 |
| 候选规则 + 回测 | 把反复出现的异常归纳为候选规则，在历史快照上回测：过去 12 期会触发几次，几次被人工结论或业务结果证实。无回测不进校准会 | 快照满 12 个月后 |

**一条候选一张卡**：观察、证据（引用面板和指标）、置信度、类型（新问题 / 归因 / 机会 / 候选规则）、回测结果（候选规则必填）。人的操作只有采纳和否决；采纳即生成一条来源标 AI 的人工结论，否决选一个理由（不成立 / 已知 / 不可操作）。

**两个管控指标**：采纳率、采纳后验证成立率。低于配置下限时自动收窄它的范围（先停无规则异常，保留归因草稿）。模型与提示词版本随月度快照存，同配置版本留痕。治理方式与《换图决策需求》第 12 节 AI 方案一致：推荐 + 人确认 + 回验。

# 6. 决策区：建议与待办聚合

决策区按五类决定分组，来源一律写结论名（5.3、5.5），不写面板。只有预警级和机会级的结论进这里。

| 决定 | 出口 | 来源（结论） | 形态 |
|---|---|---|---|
| 结构 / 进出 | 下架待办 | 下架积压；对象层下架建议在本品类的聚合（自下而上） | 待办数 + 跳转处置建议审批页 |
| 结构 / 进出 | 补款建议 | 结构错配·供给不足、盘子老化、高毛利段供给不足、色系机会。**带毛利约束**（低毛利段不盲目补）；机会类带色系、尺码或价格段标注 | 建议行：缺口维度 + 证据 + 建议方向 |
| 结构 | 收缩建议 | 结构错配·供给过剩（升预警后）、盘子老化 | 建议行 + 跳转处置审批（批量移观察 / 下架候选） |
| 结构 | 配置建议 | 大码机会；机会类与人工结论里属于标准调整的部分 | 建议行 + 跳转配置中心对应参数；不开意图单 |
| 投入 | 第二梯队培养 | 头部降档无接替、过度集中（升预警后） | 潜力款名单建议（B 级 × 上升趋势） |
| 投入 | 跨域议题 | 投放与份额错配、投放未跟等级（升预警后）、大码机会的运营与营销部分、人工结论里出口在其他域的动作 | 议题行：证据 + 建议动作 + 所属域；月会拍板；域启动后改为派生该域单据 |
| 投入 | 规划会议题 | 品类总评姿态与品类梯度连续 N 个月不符（5.6）；已处理仍持续的预警级结论 | 议题行：姿态序列 + 梯度 + 候选动作（调梯度 / 校准目标）；进季度规划会或月会 |
| 新陈代谢 | 素材单 | 素材完备度差距、上新质量（素材问题）、色系机会、大码机会 | 缺口清单 + 任务量预估，批准即开素材单（《商品域/意图单类型》） |
| 新陈代谢 | 上新方向输入 | 上新质量（选款问题）、高毛利段供给不足、结构错配·供给不足 | 写入规划表上新方向板块的候选（《品类规划需求》3.5、4.3） |
| 新陈代谢 | 换图持续无效信号 | 换图持续无效；风格单一（升预警后） | 信号行 + 跳转换图聚合报告品类切片 / 风格库计分卡 |
| 红线 | 红线预警 | 红线触发 | 预警行 + 升级机制 |

- "该下架"来自 SPU 级建议聚合，"该上架（补款）"是品类级原生信号——后者只有站在品类结构层面才看得出来，这是驾驶舱不可被商品列表页替代的理由。
- 决策区建议均为"规则出证据 + 人拍板 + 留痕"，复用换图决策工作台形态。批准即开单的，单据格式见《意图单需求》，商品域的信见《商品域/意图单类型》。

# 7. 月度快照

- 每月固定日（可配置）对八面板全量数据 + 品类总评（系统建议与人确认两个值）+ 系统结论与人工结论（含状态与派生单号）+ AI 候选及其采纳情况 + 清单版本与模型版本 + 决策区状态归档，按"全站 + 各主要站点"两层存（规划表站点 × 品类的现状列由站点切片喂）。
- 用途：① 月会品类分册自动生成源（替代人工整理，口径不漂移）；② 品类健康历史序列（趋势型信号的数据基础）；③ 规划区上线后"目标 vs 实际"复盘的实际值来源。
- 快照只读、不可修改；口径变更（如成本口径切换）在快照上标注版本，不回溯。
