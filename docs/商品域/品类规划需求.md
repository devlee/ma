# 1. 背景与目标

## 1.1 现状

- **动作不及时的根因是没有规划**：关键节点（品类旺季拐点、大促）没有前置动作清单，事到临头才组织。
- **规划散在人脑与文档**：品类目标、上新计划、资源分配无固定载体、无版本、无复盘对照物。
- **旺季靠经验**：拐点时间、提前量、动作清单依赖个人记忆，无法沉淀与校准。

## 1.2 目标

- 把商品域的蓝图四项——要什么（目标）、投多少（资源）、怎么分（规则）、何时动（节奏）——放进一个有版本、有锁定、有留痕、可被快照对照的数据对象，季度一起锁。
- 三件套成为 L3 批量意图单的周期性来源：**规划表（哪些品类发力）× 节点日历（什么时候）× 预案库（做什么动作）→ 一批意图单草稿 → 人确认后下发**（三条纪律见《灵策总纲》3.4，字段见《意图单需求》3.1）。**蓝图未锁定不生成单子。**
- 季节周期系统化：从历史数据回算，而非依赖记忆。

## 1.3 设计原则

- **算出来的和定出来的分开**：驾驶舱是计算结果（自动刷新、无人签字），规划表是决策结果（锁定、版本、Owner、承诺）。混在一起复盘就没有对照物。
- **目标和资源一起锁**（《灵策总纲》3.3）：只锁目标不锁资源，未达成时分不清"执行不力"还是"资源不足"。规划表锁定时，该季产能账的配额同时锁。
- **季度规划是年度规划的季度版本，月度不设规划**（《战略目标层需求》5.2）：目标值在年度规划页改，规划表只引用；月会只改排期、方向、资源、动作包。
- **目标下放的可控性原则**：指标只下放到能对它负责的层级。利润留在总盘层，品类层只认 GMV、销量，毛利作参考。
- **数据日刷、结论月出、承诺季锁、节点事件驱动**（对应《灵策总纲》第 7 节四个环，见 6.1）。
- **系统给初稿、人有终决权**：自动字段（基线预测、需求预估、触发链时点）均可人工修正、留痕。

## 3.3 三件套与批量意图单生成

| 件 | 回答的问题 | 性质 |
|---|---|---|
| 品类规划表 | 每个品类要去哪、现在在哪、差多少、靠什么补 | 承诺（锁定版本） |
| 节点日历 | 什么时候必须做什么 | 时间锚（定义生成实例） |

## 3.4 规划树与经营对象树

规划按**总盘 → 站点 → 大类 → 品类**展开（站点在品类上一层：先看哪个站点，再看站点下大类与品类；大类为静态归类：衣服 / 鞋子+ACC，规划表按大类分组小计）。

两个大类的行粒度不同。衣服大类 8 个品类逐行；鞋+ACC 大类 20 多个品类、销售额不到 3%，一期按梯度组织行：重点品类单列，长尾合并为一行，目标和产能配额给到大类或重点品类，不逐品类拆（梯度两档见《战略目标层需求》5.3）。鞋+ACC 的行一期只有板块 1 结果目标和板块 3 产能配额，盘子规划、上新方向等板块随驾驶舱二期启用（《品类驾驶舱需求》1.5）。加总校验对两个大类同样生效。这是"经营对象树"（总盘 → 站点 → 大类 → 品类 → SPU → SKU）在规划层的投影——各层制品在对象树的不同层级实例化：L0 目标挂总盘、年度规划挂总盘到品类、规划表挂站点 × 品类、驾驶舱挂品类、动作挂 SPU、结构三维挂 SKU。

- **站点分级**（S/A/B/C/D 五档、季度评分，定档机制与各档待遇见《战略目标层需求》5.4，当期名册见该册 5.5）：S 级站点配有专属团队（组织现实），规划树与责任树同构——站点层 Owner 实名，品类行 Owner 暂由站点 Owner 兼任（品类负责人角色落定后切换）；A 级固定 Owner 兼任。
- **v1 站点口径**：规划表直接按站点 × 品类两级建；驾驶舱数据视图按站点切片全拆，**诊断与信号层 v1 统一跑全站口径**（站点级诊断待全站阈值校准后逐站开启，防止配置爆炸）。规划差距是机械计算，按站点 × 品类展示不受此限。

## 3.5 与品类驾驶舱、品类列表页的关系

规划表是独立数据对象（锁定/版本/Owner）。驾驶舱"规划区"是它在单品类的**全量只读投影**（五板块的目标 / 现状 / 差距三列），面板一、五、六只带自己指标的目标列，取同一份投影不另存（《品类驾驶舱需求》3.1）；品类列表页总评视图的"规划差距红黄绿"列读同一个值（《品类驾驶舱需求》3.2）。页面职责钉死：

| 页面 | 形态 | 性质 |
|---|---|---|
| 品类驾驶舱页 | 单品类一页（画像 / 诊断结论 / 决策 / 规划区 / 节点区） | **只读**。看差距、定位问题、从决策区发起动作 |
| 品类列表页 | 横视图三视图；总评视图带规划差距列 | **只读**。横扫差距与姿态，排月会与规划会议程 |
| 品类规划表页 | 横向工作台：站点 × 品类全表 | **可编辑**。排期、方向、资源、叠加包在此修改，留痕；目标值跳年度规划页改 |

决策分两类，判据一条：**这次调整需不需要改规划表上已写下的数字或方向**——不需要（批下架、任务插队提优先级）是动作类，走驾驶舱决策区（批准即生成事件性意图单，钩子自动填充，见《灵策总纲》3.4）；需要（改上新排期、调产能分配、换补款方向）是规划类，跳规划表页编辑留痕。

驾驶舱决策区通向规划表的三条路（《品类驾驶舱需求》第 6 节）：

| 决策区出口 | 落到规划表哪里 | 处理 |
|---|---|---|
| 上新方向输入 | 板块 2 上新方向的候选列表 | 来源结论：上新质量（选款问题）、高毛利段供给不足、结构错配·供给不足、色系与大码机会。月度调整窗口由 Owner 勾选采纳或忽略，留痕 |
| 规划会议题 | 规划会议程（按梯度排序） | 来源：姿态与梯度连续 N 个月不符（《品类驾驶舱需求》5.6）、已处理仍持续的预警级结论。候选动作：调梯度、校准目标，都在年度规划页改，不在规划表改 |
| 跨域议题 | 板块 4 营销资源（过渡态）或叠加包资源预留 | 来源：投放与份额错配等；月会拍板；营销域启动后改派生该域单据，不再经规划表 |

两类之间的桥是**产能对账**：动作层持续插队会以事件单资源占比、任务积压的形式在月度对账中显形，推回规划层重新决策（10.3）。

# 4. 品类规划表

## 4.1 规划内容：五个板块

| 板块 | 规划的内容 | 谁拥有 | 数据来源（下层喂上来） |
|---|---|---|---|
| 1 结果目标 | GMV、销量（站点 × 品类）；毛利率只读参考列 | **年度规划季度版本**（只读引用）；规划表只持有基线预测、差距、目标依据备注 | 年度规划页 + 基线预测 |
| 2 盘子规划 | 上新（数量/方向/节奏/质量线）、汰换预估、结构调整方向、期末在架规模 | 规划表 | 驾驶舱结构三维、补款建议、上新方向输入、观察态积压、动销率；上新配额取策略包 |
| 3 动作与产能 | 素材补齐量、换图需求量、常规池需求预估、专项包申请、产能对账 | 规划表（需求侧）；产能账（供给侧） | 素材完备度差距、检视队列、上新规划推导；专项池优先级取策略包 |
| 4 营销资源 | 花费预算/占比、主推方向 | **过渡态**：营销域启动前人工填、只作参考；启动后改为引用营销规划页的品类切片（《灵策总纲》10.1） | 驾驶舱营销效率面板、集中度信号 |
| 5 节点 | 本季节点清单 + 各节点叠加包状态 | 节点日历（引用） | 节点日历触发链 |

两个恒等式是表的骨架：

```
期末盘子 = 期初在架 − 汰换 + 上新
GMV 目标 = 存量款基线贡献 + 新款贡献缺口
```

规划表每行带**梯度列**（只读，取当期策略篇）和**当期姿态列**（只读，取驾驶舱最近一期总评），两列不可编辑，用来排序和对照。

## 4.2 目标：年度规划季度版本的引用

- **唯一出处**：站点 × 大类 × 品类的季度 GMV、销量目标住在年度规划的季度版本里（《战略目标层需求》5.1、5.2）。季度规划会做切片和校准，在年度规划页改、锁定；规划表板块 1 读锁定的季度版本，显示版本号，不可在规划表上改。
- **规划表板块 1 自己持有的**：基线预测值（系统回算、留档）、差距与达成率（快照映射）、目标依据备注（规划会上为什么这样校准，引用假设编号）。
- **利润不下放品类**（可控性原则）：毛利率为只读参考列；利润目标由管理层在总盘层持有，站点层预留（《战略目标层需求》TBD 8）。
- **指标树的落点**：L1 责任登记的"目标值指针"指向年度规划或域蓝图的那一格（《战略目标层需求》6.2）。GMV、销量的指针落年度规划季度版本；上新数量、新品成功率目标线、素材补齐量等过程目标的指针落规划表板块 2、3 的格子。口径不在本册重写，指向口径字典。
- **基线预测值留档**：事后"预测 vs 实际"是规划方法本身的校准指标（预测能力和判定阈值一样是被复盘的资产）。
- **年度规划建成前的过渡**：系统自下而上出基线预测，管理层自上而下给总盘目标，差额在规划会分配到站点 × 品类、锁定。过渡期目标值暂存规划表板块 1，年度规划页上线后迁移为引用，历史版本不回算。

## 4.3 梯度与策略包的消费

规划表是策略篇商品块的消费端，不另定一套分级（《战略目标层需求》5.3）。

| 策略包要素 | 规划表怎么用 |
|---|---|
| 梯度（衣服四档 / 鞋+ACC 两档） | 每行只读梯度列；表按大类分组、梯度排序；规划会议程按梯度排序 |
| 上新配额倾斜 | 板块 2 的上新数量目标以配额为初值，目标差距反推（4.4）只能在配额基础上上调或说明下调理由；驾驶舱"上新配额未达成"结论读的是这个数 |
| 专项池优先级 | 板块 3 专项包申请按梯度排队；产能账专项池分配时同梯度内再看叠加包的期间目标 |
| 素材与换图倾斜 | 板块 3 素材补齐量预估按该档的完备度要求推导；换图候选优先级参数在对象层与换图侧读同一份策略包 |
| 梯度调整 | 季会可调，依据来自驾驶舱规划会议题（姿态与梯度连续不符）；改在年度规划页策略篇，规划表随之刷新梯度列，不改已锁定版本 |

鞋+ACC 大类一期只用重点 / 长尾两档，策略包只有专项池优先级与目标激进度两项，上新配额与素材倾斜随驾驶舱二期启用。

## 4.4 上新规划：四个来源合成一个决策

上新规划 = 数量 × 方向 × 节奏 × 质量线：

| 维度 | 来源 | 机制 |
|---|---|---|
| 数量 | 策略包配额 + 目标差距反推 | 初值 = 梯度配额；缺口 ÷（品类新品成功率 × 成功新品平均产出）≈ 需上新 N 款，与配额对照，偏离要写理由 |
| 方向 | 结构缺口 + 风格信号 + 机会类结论 | 驾驶舱结构三维错配/补款建议（价格段/颜色/尺码）；风格库计分卡的上升风格与低拥挤度风格；机会类结论（高毛利段供给不足、色系需求、大码需求）经决策区"上新方向输入"进候选列表（3.5） |
| 节奏 | 节点倒排 | 旺季款上架时间 = 拐点 − 生产周期 − 素材周期 − **新品爬坡期（约等于保护期 90 天）**；上新是触发链中最早的动作 |
| 质量线 | 新品成功率目标 | 考核"成功了多少款"而非"上了多少款"；驾驶舱"上新质量"结论拆选款问题与素材问题，选款问题回写方向 |

**约束项：产能。** 上新素材需求 + 存量补齐 + 换图需求 = 设计产能需求，规划会对账实际产能，超了优先砍观察态商品投入（优化池收缩）。生产端打样产能为供应链占位字段，人工填（**TBD**）。

## 4.5 版本与锁定

- **季度规划会锁定**基础版本，锁定即快照；复盘与判定对锁定版本比，不回溯。
- **一起锁**：锁定动作同时冻结四样——引用的年度规划季度版本号、产能账当季配额（常规/专项池预留比、站点比例）、策略包版本（梯度名册）、节点实例排期。任一样未锁，规划表不能锁。
- **锁定三道检查**（《灵策总纲》3.3）：**加总校验**（规划表站点 × 品类 Σ = 年度规划季度版本的站点、大类、总盘数，不平不能锁；需求预估 Σ ≤ 产能账可用量，超了出对账结论）；**假设溯源**（上新方向里的激进押注、显著超基线的配额上调、梯度调整，必须挂假设编号，挂不上当场补登记）；**变更留痕**（每个字段前值 → 后值 → 依据 → 操作人）。
- **月度调整窗口**：月会看完快照差距后，规划内容（排期/方向/资源/动作包）集中调整、留痕；目标值不动，梯度不动。
- **目标值变更**只在年度规划页发生，两个时点：季度规划会（正常校准）；季中战略环级异动（平台政策/汇率/供应链剧变），走变更审批留痕，并关联假设清单状态变更（《战略目标层需求》5.2）。规划表感知为引用版本号变化。
- **节点叠加包**独立版本：季度复盘对基础版、节点复盘对叠加包，两层互不污染。

# 5. 批量意图单生成

- **触发**：节点实例触发链到期的环（素材准备、投放蓄水、专项规划）和规划表节奏型批次（上新批次、素材补齐批次）。蓝图未锁定不生成。
- **相乘取数**：对象按规划表行（站点 × 品类）展开；目标取该行与单据类型口径一致的目标值；预算与预算来源取预案资源需求并从产能账或预算池扣减；时限取触发链该环日期；来源记蓝图 + 节点实例；关联记规划行、叠加包、预案、假设编号。字段逐项见《意图单需求》3.1。
- **人确认**：草稿按节点实例成批列在规划 Owner 待办里，可整批确认、单张改量、单张驳回写理由；确认后进意图单状态机。
- **下发分流**（《灵策总纲》3.5）：商品域素材单、换图单经灵鉴路由至灵枢；营销类直连灵犀；客服类至鹊桥；执行方待定环节（价格·上下架、运营、供应链）落人工工作台。
- **与事件单的关系**：事件单（诊断里批准开出）不经本流程，但从同一个池子扣额度；单池事件单累计占用超阈值时须规划 Owner 加签，阈值在配置中心蓝图分区。批量单与事件单在产能账里分列，是月度对账的两个看点（10.3）。

## 6.2 月度动线

1. **品类列表页总评视图**横扫：姿态、主要矛盾、规划差距红黄绿、连续月数；按梯度排月会议程，绿的翻页。

# 7. 节点日历

## 7.1 三类节点

| 类型 | 例子 | 来源 |
|---|---|---|
| 周期型 | 品类旺季拐点 | 同期指数曲线回算 → 自动生成候选 → 人确认 |
| 日历型 | 平台大促（黑五）、节日 | 人工录入；进同一实例状态机，后续机制共用 |
| 节奏型 | 上新批次、素材补齐批次 | 由规划表过程目标推导生成 |

> 口径澄清：换图候选层面"明确不做季节错位"（SPU 级图片季节信号对婚纱礼服不成立，《换图决策需求》4.4 注）与品类级旺季规划不矛盾——品类量价周期（婚礼季）真实存在，两条决策记录各自成立。换图不是节奏型节点：换图单由诊断批准或检视队列产生，不按批次排。

## 7.2 品类同期指数曲线（季节性的数据本体）

- **回算**：品类近 2–3 年销量按周聚合、逐年归一化（消年度增长）、跨年平均 → 52 周相对强弱曲线。
- **拐点识别**：指数低位连续 N 周上行且累计超阈值 → 旺季启动拐点；同理识别峰值、回落点。输出"预计第几周"。
- **一份资产三处复用**：判定引擎的品类同期校正、节点日历的拐点识别、**年度规划目标篇的月度分解加权**（《战略目标层需求》5.1）共用同一条曲线，资产环统一维护，全系统只建一份——战略层的月度目标线和蓝图层的节点曲线永远是同一条，不另存副本。
- **冷启动例外**：历史不足 2 年的品类用相近品类曲线代用或人工录入节点（人工节点的正当来源）。
- **年度滚动重算**：新一年数据进入后刷新曲线；拐点预测偏差（预计周 vs 实际周）回写识别规则校准。

## 7.3 节点定义与节点实例

| 对象 | 内容 | 性质 |
|---|---|---|
| 节点定义 | 品类、节点类型、识别规则与曲线版本、提前量配置（分项见 7.4，品类可配） | 资产，年年复用 |
| 节点实例 | 某一年的具体节点：预计拐点周 + 倒推触发日期链 + 状态 | 每年由定义自动生成 |

实例状态机：**待确认 → 已排期 → 触发中 → 进行中 → 已结束 → 已复盘**。"待确认"不可省：季节回算是统计推断，系统出证据（曲线图 + 历年实际拐点），人确认后排期——"规则出证据 + 人拍板"。

> 与战略层的分界：节点的日期与曲线是**日历事实**，住这里；对节点的**重大押注**（如"旺季 GMV 占比提至 40%"）是可证伪判断，登记进战略假设清单（《战略目标层需求》4.2 第 4 类来源），其"影响范围"指向对应叠加包，证伪时顺藤回调。

## 7.4 触发链

```
T−W 周 ─→ 上新批次触发（提前量最长：生产 + 素材 + 新品爬坡期 ≈ 保护期 90 天）
T−X 周 ─→ 专项规划任务：生成节点叠加包草稿（目标包模板 + 预案动作清单初稿）→ 专项规划会定稿锁定
T−Y 周 ─→ 素材准备意图单下发（经 L3 → L4 商品契约 → 灵鉴路由 → 灵枢）
T−Z 周 ─→ 投放蓄水意图单（营销域，直连灵犀）
T      ─→ 节点启动：驾驶舱节点区转"进行中"，展示叠加包目标 vs 实时达成
T+结束 ─→ 复盘任务：叠加包达成判定 + 预案有效性复盘
```

- **专项规划本身是触发链的标准首环**（上新触发除外，它更早）：不是孤立会议，而是节点实例上的任务，产出物（叠加包）挂回实例。
- 触发链各环时点系统按提前量倒推给初稿，专项规划会上可人工调整。
- **触发链延误为日级预警**（与护栏红线触发并列为仅有的两类"等不起"信号）：错过提前量无法补救。送达走待办中心置顶红条（《灵策总纲》10.5）。

## 7.5 复盘回路

节点结束后复盘任务收两笔账，分别回写两个资产（资产环，频率挂在节点复盘上）：

- **拐点预测偏差** → 回写节点定义，校准识别规则；
- **预案有效性**（动作清单哪些起效/无效/漏项）→ 回写预案库，草稿预案跑过一次且复盘后升"验证预案"。

# 8. 预案库

- **全域共用、按域分区**：库一个，分区按域（商品预案 / 活动预案 / 营销预案 / 供应链预案…），本文档定义的分级与修订规矩全域通用；v1 只启用商品域分区。页面在蓝图板块，资产板块双入口（同一页面不复制）。
- **预案模板** = 节点类型 × 触发时机 + 动作清单 + 资源需求 + 历史复盘记录 + **所属域分区**（结构见 11.4）。
- **冷启动**：第一批预案从历史动作整理（历次换图 push、大促准备动作），不求全，求"下次不从零想"。
- **轻量分级**：草稿预案（没跑过）/ 验证预案（跑过至少一次且复盘）。不建风格库式的重验证期机制。
- **修订机制**：每次节点复盘回写；预案库属资产环成员，与风格库、阈值同列被数据持续校准。

# 9. 专项规划与节点叠加包

- **规划事件两类**：季度例行规划会 + 节点触发的专项规划（品类旺季、全站大促均需专项）。
- **叠加包机制**：不改季度锁定版基础目标，在其上叠加期间目标（GMV/销量增量）+ 动作包（预案引用 + 本次调整）+ 资源预留（专项池申请、投放预留），独立版本、独立复盘。
- 叠加包的期间目标若构成重大押注，登记为战略假设并在包上记编号（7.3 分界）。
- 全站大促（黑五）为**跨品类节点包**，资源从全站总账的专项池预留出（不占单站点专项池）。

# 10. 产能账

## 10.1 两本账

| | 常规池 | 专项池 |
|---|---|---|
| 分配轴 | 站点 × 等级（现行灵鉴规则**保留**：站点总比例 → 站内按等级） | 品类 × 事件（节点叠加包、上新批次） |
| 驱动 | 规则自动：等级挂素材要求 → 缺口生成任务 → 排队 | 规划驱动：专项规划定包，按梯度排优先级（策略包），经 L3 下发 |
| 哲学 | 资源跟着表现走（对象层哲学延续，不问品类） | 资源跟着战役走（规划层意志，以品类为锚） |
| 事件单扣减 | 诊断批准的素材单、换图单从常规池扣 | 叠加包期间批准的事件单从该包预留扣 |

品类在常规池的份额是**涌现**的（S/A 级商品多的品类自然多拿），规划表不推翻它——品类规划的产能内容是**需求预估 + 专项包申请 + 对账**，不是分配（见 11.1 板块 3）。事件单从哪个池扣由钩子预填，人不选；单池累计占用超阈值要加签（《灵策总纲》3.4）。

## 10.2 三级账结构

```
全站总账（总盘层）
├─ S 级站点单独账（有专属规则与 Owner 的站点，逐站一本）
└─ 默认账（A–D 级站点：A 级单列小计可见、B/C/D 级合并计，走全局默认规则；分档见《战略目标层需求》5.4）
```

| 账 | 内容 | 谁定 |
|---|---|---|
| 全站总账 | 产能总量（人力盘）、常规/专项池总预留比、全站供需总对账、**站点间比例调剂**、跨品类节点包预留 | 管理层 / 规划会 |
| 站点单独账 | 站点资源比例、站内等级优先级、站内常规/专项比、站内对账 | 站点 Owner |
| 默认账 | A 级站点单列小计、B/C/D 级合并计；随总账带过，异动才拆看 | — |

- **恒等式约束**：总账 = Σ 站点单独账 + 默认账；任一层改比例自动校验加总，防"各账合理、加总超产能"。
- **单独账门槛** = 站点分级表当期 S 级（《战略目标层需求》5.5），跟季走；升降档带交接清单（单独账开立或合并）。开发资源比例以 5.4 各档比例为输入。
- **与规划表一起锁**：季度规划会锁定规划表时，总账的池预留比与站点比例同时锁；季中调剂走留痕。

## 10.3 月度对账（自上而下，三层对应三种决策）

本段是诊断矩阵**站点 × 商品**格子的定期诊断（《灵策总纲》3.6）。结论出在产能账页，一月一次（全局快照日），不另开诊断页。

| 诊断维度 | 在看什么 | 非正常时的出口 |
|---|---|---|
| 总账供需 | 总积压；**事件单资源占比**（事件单消耗 ÷ 总消耗）；**人工来源占比**（来源为人工的意图单消耗占比） | 积压 → 人力盘（招人/外包），不是改分配；两个占比超阈 → 推回规划层：是蓝图少规划了还是动作层在绕过蓝图 |
| 站点账 | 站点间结构是否失衡 | 总账层调剂站点比例 |
| 品类行 | 需求是否超出产能；单池事件单占用是否触加签线 | 砍处置态池（优化池收缩）、调排期，或申请专项包；触加签线的后续事件单由规划 Owner 加签 |

对账结论三态：正常 / 积压 / 超支，回填规划表板块 3 对账状态列，并进月度快照。

## 10.4 品类资源倾斜的四个杠杆（均不碰常规池规则）

1. 上新量（新品走新品素材档，上新计划直接带产能；配额来自策略包）；
2. 节点叠加包（战役性投入走专项池，按梯度排优先级）；
3. 处置态池子大小（移入/移出"优化"态改变常规池需求量）；
4. （留作后手）等级规则的品类覆盖——战略品类 B 级享 A 级素材标准，走配置作用域机制（全局 → 大类 → 品类），不急开。
