# 1. 背景与目标

## 1.1 现状

- **动作不及时的根因是没有规划**：关键节点（品类旺季拐点、大促）没有前置动作清单，事到临头才组织。
- **规划散在人脑与文档**：品类目标、上新计划、资源分配无固定载体、无版本、无复盘对照物。
- **旺季靠经验**：拐点时间、提前量、动作清单依赖个人记忆，无法沉淀与校准。

## 1.2 目标

- 把商品域的蓝图四项——要什么（目标）、投多少（资源）、怎么分（规则）、何时动（节奏）——放进一个有版本、有锁定、有留痕、可被快照对照的数据对象，季度一起锁。
- 三件套成为 L3 批量意图单的周期性来源：**规划表 × 节点日历 × 预案库 → 一批意图单草稿 → 人确认后下发**（第 5 节）。**蓝图未锁定不生成单子。**
- 季节周期系统化：从历史数据回算，而非依赖记忆。

## 1.3 设计原则

- **算出来的和定出来的分开**：驾驶舱是计算结果（自动刷新、无人签字），规划表是决策结果（锁定、版本、Owner、承诺）。
- **目标和规则都是引用，资源一起锁**：目标值和分资源的规则由年度规划持有，规划表只引用、可偏离写理由；锁规划表时产能账同时锁（4.4）。
- **目标下放的可控性原则**：利润留在总盘层，品类层只认 GMV、销量，毛利作参考。
- **数据日刷、结论月出、承诺季锁、节点事件驱动**（6.1）。
- **系统给初稿、人有终决权**：自动字段均可人工修正、留痕。

## 3.3 三件套与相乘语义

| 件 | 回答的问题 | 性质 |
|---|---|---|
| 品类规划表 | 每个品类要去哪、现在在哪、差多少、靠什么补 | 承诺（锁定版本） |
| 节点日历 | 什么时候必须做什么 | 时间锚（定义生成实例） |
| 预案库 | 到了节点具体做哪些动作 | 资产（复盘修订） |

规划表的策略与目标包 × 节点实例的触发时点 × 预案模板的动作清单 → 一批意图单草稿，流程见第 5 节。

## 3.4 规划树与经营对象树

规划按**总盘 → 站点 → 大类 → 品类**展开（站点在品类上一层；大类为静态归类：衣服 / 鞋子+ACC，规划表按大类分组小计）。这是经营对象树（总盘 → 站点 → 大类 → 品类 → SPU → SKU）在规划层的投影：L0 目标挂总盘、年度规划挂总盘到品类、规划表挂站点 × 品类、驾驶舱挂品类、动作挂 SPU、结构三维挂 SKU。

- **两个大类的行粒度不同**：衣服大类 8 个品类逐行；鞋+ACC 大类 20 多个品类、销售额不到 3%，一期按梯度组织行：重点品类单列，长尾合并为一行，目标给到大类或重点品类行。鞋+ACC 的行一期只有板块 1 和板块 3 的专项包申请与对账，策略包只有专项池优先级与目标激进度两项；其余板块与配额、倾斜随驾驶舱二期启用（《品类驾驶舱需求》1.5）。加总校验对两个大类同样生效。
- **站点分级**（S/A/B/C/D 五档、季度评分，《战略目标层需求》5.4、5.5）：S 级站点配专属团队，规划树与责任树同构——站点层 Owner 实名，品类行 Owner 暂由站点 Owner 兼任（品类负责人角色落定后切换）；A 级固定 Owner 兼任。
- **v1 站点口径**：规划表按站点 × 品类建；驾驶舱诊断与信号层 v1 统一跑全站口径，规划差距是机械计算，按站点 × 品类展示不受此限。

## 3.5 与驾驶舱的关系：一个对象、两个视图

规划表是独立数据对象（锁定/版本/Owner），可编辑。驾驶舱"规划区"是它在单品类的**全量只读投影**（五板块目标 / 现状 / 差距三列），面板一、五、六的目标列取同一份投影不另存（《品类驾驶舱需求》3.1）；品类列表页总评视图的"规划差距红黄绿"读同一个值（3.2）。

决策分两类，判据一条：**这次调整需不需要改规划表上已写下的数字或方向**——不需要（批下架、任务插队）是动作类，在驾驶舱决策区批准即生成事件性意图单（《灵策总纲》3.4）；需要（改上新排期、调产能分配、换补款方向）是规划类，回规划表编辑留痕。

驾驶舱决策区通向规划表的三条路（《品类驾驶舱需求》第 6 节）：

| 决策区出口 | 落到规划表哪里 | 处理 |
|---|---|---|
| 上新方向输入 | 板块 2 上新方向候选列表 | 来源结论：上新质量（选款问题）、高毛利段供给不足、结构错配·供给不足、色系与大码机会。月度调整窗口由规划 Owner 采纳或忽略，留痕 |
| 规划会议题 | 规划会议程（按梯度排序） | 来源：姿态与梯度连续 N 个月不符（《品类驾驶舱需求》5.6）、已处理仍持续的预警级结论。候选动作调梯度、校准目标，都改在年度规划 |
| 跨域议题 | 板块 4 花费预算（过渡态）或叠加包资源预留 | 来源：投放与份额错配等；月会拍板；营销域启动后改派生该域单据 |

两类之间的桥是**产能对账**：动作层持续插队会以事件单资源占比、任务积压的形式在月度对账中显形（10.3），推回规划层重新决策。

# 4. 品类规划表

## 4.1 一张总表

站点 × 品类一行，一季一版。**标识组**：站点 / 大类 / 品类（鞋+ACC 长尾为合并行）/ 季度 / 版本号与状态（草稿 → 锁定 → 变更中）/ Owner / 当期姿态（只读，取驾驶舱最近一期总评，用于排序对照）。

| 板块 | 字段 | 谁拥有 / 从哪来 | 何时变 |
|---|---|---|---|
| 0 适用规则组 | 梯度、上新配额（款数）、专项池优先级、素材与换图倾斜档、策略包版本号 | **年度规划策略篇商品块**，只读引用（4.2） | 年会锁定、季会可调；规划表随版本刷新，不改已锁版本 |
| 1 结果目标 | GMV 目标、销量目标（只读引用，带季度版本号）；基线预测值（系统回算、留档）；目标依据备注（引用假设编号）；毛利率只读参考列 | 目标值：**年度规划季度版本**（《战略目标层需求》5.1、5.2），规划表不可改。基线预测、差距、依据备注归规划表 | 季度规划会；季中仅战略环异动（4.4） |
| 2 盘子规划 | 期初在架 SPU 数（自动）、上新数量目标（初值 = 配额，偏离写理由）、上新方向（结构化枚举：价格段/颜色/尺码/风格四维缺口 + 来源标注；候选列表及采纳状态）、上新节奏（批次 × 目标上架周，旺季款标倒排依据）、新品成功率目标线、预计汰换数（系统预估 + 人工修正）、期末盘子规模（恒等式自动算） | 规划表。来源：驾驶舱结构三维与补款建议、上新方向输入、观察态积压、动销率、对象层新品成功率与平均产出、风格库计分卡（4.3） | 月度调整窗口 |
| 3 动作与产能 | 素材补齐量预估（完备度差距按倾斜档要求推导）、换图需求量预估（检视队列推导）、常规池需求预估（自动汇总）、专项包申请（关联叠加包，按专项池优先级排队）、对账状态（月度回填：正常/积压/超支）、本行事件单占用（只读） | 需求侧归规划表；供给、对账结论与事件单占用来自产能账（第 10 节） | 月度调整窗口；对账状态月度回填 |
| 4 营销资源 | 花费预算或占比；主推方向（枚举：头部巩固/第二梯队培养/新品扶持，可多选） | 花费预算为**过渡态**：营销域启动前人工填、只作参考，启动后改为引用营销域规划的品类切片。主推方向（推哪些款）是商品域的选择，始终归规划表 | 月度调整窗口 |
| 5 节点 | 本季关联节点实例列表（旺季 / 淡季 / 大促）+ 叠加包状态 | 节点日历（引用，按本站点所在站点组取实例，不重复填） | 事件驱动 |
| 现状与差距列 | 板块 1–3 每个目标字段的现状值、差距、达成率、红黄绿 | 月度快照自动映射（站点切片） | 快照日 |

两个恒等式是表的骨架：

```
期末盘子 = 期初在架 − 汰换 + 上新
GMV 目标 = 存量款基线贡献 + 新款贡献缺口
```

通用规则：自动字段可人工修正但留痕；方向类字段用枚举不用自由文本（否则复盘无法对"方向对不对"记账）；只读引用字段显示来源对象与版本号。

补充两点：

- **利润不下放品类**：毛利率为参考列，利润目标由管理层在总盘层持有，站点层预留（《战略目标层需求》TBD 8）。
- **L1 指标树落点**：GMV、销量的目标值指针落年度规划季度版本；上新数量、成功率目标线、素材补齐量等过程目标的指针落板块 2、3 的格子（《战略目标层需求》6.2）。口径指向字典，不在本册重写。
- **年度规划建成前的过渡**：系统自下而上出基线预测，管理层自上而下给总盘目标，差额在规划会分配到站点 × 品类、锁定；过渡期目标值暂存板块 1，季度版本建成后迁移为引用，历史版本不回算。

## 4.2 适用规则组与策略包

**策略包住在哪**：唯一编辑处是年度规划策略篇商品块（《战略目标层需求》5.3）——哪个品类哪一档（名册）和每档的专项池优先级、上新配额、素材与换图倾斜档，一档一行，年会锁定、季会可调、调整挂假设编号。配置中心只放两样：梯度档位枚举；倾斜档的参数含义（各档对应什么完备度要求、换图候选优先级加几，在对象层与换图分区，TBD 10）。

**规划表怎么消费**：

| 规则组字段 | 用法 |
|---|---|
| 梯度 | 表按大类分组、梯度排序；规划会议程按梯度排序 |
| 上新配额 | 板块 2 上新数量目标的初值；目标差距反推只能在配额基础上上调或说明下调理由；驾驶舱"上新配额未达成"结论读板块 2 的数 |
| 专项池优先级 | 板块 3 专项包申请按它排队；产能账专项池分配时同优先级内再看叠加包期间目标 |
| 素材与换图倾斜档 | 板块 3 素材补齐量按该档要求推导；对象层素材要求与换图候选优先级读同一个档。"战略品类 B 级享 A 级素材标准"走这条路，不另开配置覆盖 |

规划表只能偏离并写理由，不能改规则。梯度调整的依据来自驾驶舱规划会议题（3.5）。

## 4.3 上新规划：四个来源合成一个决策

| 维度 | 来源 | 机制 |
|---|---|---|
| 数量 | 配额 + 目标差距反推 | 初值 = 配额；缺口 ÷（品类新品成功率 × 成功新品平均产出）≈ 需上新 N 款，与配额对照，偏离写理由 |
| 方向 | 结构缺口 + 风格信号 + 机会类结论 | 驾驶舱结构三维错配/补款建议（价格段/颜色/尺码）；风格库计分卡的上升风格与低拥挤度风格；机会类结论经决策区"上新方向输入"进候选列表（3.5） |
| 节奏 | 节点倒排 | 旺季款上架时间 = 拐点 − 生产周期 − 素材周期 − **新品爬坡期（≈ 保护期 90 天）**；上新是触发链中最早的动作（7.4） |
| 质量线 | 新品成功率目标 | 考核"成功了多少款"而非"上了多少款"；驾驶舱"上新质量"结论拆选款问题与素材问题，选款问题回写方向 |

**产能约束**：上新素材需求 + 存量补齐 + 换图需求 = 设计产能需求，规划会对账实际产能，超了优先砍观察态商品投入（优化池收缩）。规划表的产能内容是需求预估 + 专项包申请 + 对账，不是分配，分配规则在产能账（10.1）。生产端打样产能为供应链占位字段，人工填（TBD 5）。

## 4.4 版本与锁定

- **季度规划会锁定**基础版本，锁定即快照；复盘与判定对锁定版本比，不回溯。
- **一起锁**：锁定同时冻结四样——年度规划季度版本号、策略包版本号、产能账当季配额（常规/专项池预留比、站点比例）、节点实例排期。任一样未锁，规划表不能锁；尚未上线的模块（第 14 节顺序）在检查里跳过并标注，上线后逐项启用。
- **三道检查**（《灵策总纲》3.3）：**加总校验**（站点 × 品类 Σ = 季度版本的站点、大类、总盘数，不平不能锁；需求预估 Σ ≤ 产能账可用量，超了出对账结论）；**假设溯源**（激进的上新方向、显著超基线的配额上调、梯度调整，必须挂假设编号，挂不上当场补登记）；**变更留痕**（前值 → 后值 → 依据 → 操作人）。
- **月度调整窗口**：月会看完快照差距后，板块 2–5 集中调整、留痕；目标值与规则组不动。每条驾驶舱结论能动哪个板块见 6.2。
- **目标值与规则变更**只在年度规划发生：季度规划会（正常校准）；季中战略环级异动，走变更审批并关联假设状态变更（《战略目标层需求》5.2）。规划表感知为引用版本号变化。
- **节点叠加包**独立版本：季度复盘对基础版、节点复盘对叠加包，两层互不污染。

# 5. 批量意图单生成

- **触发**：节点实例触发链到期的环（素材准备、投放蓄水、专项规划）和节奏型节点（上新批次、素材补齐批次）。蓝图未锁定不生成。
- **相乘取数**：对象按规划表行展开；目标取该行与单据类型口径一致的目标值；预算与预算来源取预案资源需求并从产能账或预算池扣减；时限取触发链该环日期；来源记蓝图 + 节点实例；关联记规划行、叠加包、预案、假设编号。字段逐项见《意图单需求》3.1。
- **确认粒度**：草稿按节点实例成批，由规划 Owner 确认——整批确认、单张改量、单张驳回写理由；确认后进意图单状态机（三条纪律见《灵策总纲》3.4）。
- **下发分流**（《灵策总纲》3.5）：商品域素材单、换图单经灵鉴路由至灵枢；营销类直连灵犀；客服类至鹊桥；执行方待定环节落人工工作台。
- **事件单**不经本流程，但从同一个池子扣额度，批量单与事件单在产能账里分列（10.1）。

# 7. 节点日历

全公司一本：各域的叠加包、活动、EDM 波次、产能提前量挂同一批节点。登记形式是**两张表单加一个视图**：节点定义（规则资产，年年复用）、节点实例（一年一条，带状态机）、日历视图（只读展示，第 11 节）。人手工录入的只有节点定义和日历型实例；周期型实例是系统填好的表单等人确认。

## 7.1 统一模型：锚点 + 窗口，按品类 × 站点组

每个节点实例都有一个**锚点 T**（驱动触发链倒推）和一个**期间窗口**（驱动叠加包的期间目标与复盘窗口）。三类节点共用这一套字段：

| 类型 | 例子 | 锚点 T | 窗口 | 来源 |
|---|---|---|---|---|
| 周期型·旺季 | 品类婚礼季 | 启动拐点周 | 启动 → 回落 | 同期指数曲线回算 → 系统生成待确认实例 → 人确认 |
| 周期型·淡季 | 旺季之间的低谷 | 谷底周 | 回落 → 下一次启动 | 同上，与旺季实例交替生成 |
| 日历型 | 平台大促（黑五）、节日 | 活动开始日 | 活动期 | 人工录入；进同一实例状态机 |
| 节奏型 | 上新批次、素材补齐批次 | 批次上架周 | 爬坡期 | 由规划表过程目标推导生成；素材补齐批次默认排进淡季窗口 |

**站点维度用站点组，不逐站。** 季节差异的来源是南北半球，所以：

- **站点组**是配置中心的枚举 + 站点归组表：**默认组**（美国及其他北半球站点）、**南半球组**（澳洲；将来新西兰、南非、巴西进来直接归组）。归组是站点属性，记在站点分级表的一列（《战略目标层需求》5.5），不是分级。
- 周期型节点的曲线、定义、实例都按**品类 × 站点组**；品类维度天然区分（prom 和礼服各自一条曲线），站点组区分半球。
- 节点定义的作用域走继承：默认组一套定义，南半球组只在有差异的品类上覆盖，没覆盖的继承默认组——与配置作用域机制同构。
- 日历型节点人工录入、数量少，允许三档范围：全站（黑五）/ 站点组 / **单站点**（澳洲 Boxing Day、某国国庆）。逐站只开给日历型。
- 触发链派生的意图单对象范围限定在该组站点内；规划表板块 5 按本站点所在组取实例；叠加包覆盖范围带站点组（第 9 节）。

> 口径澄清：换图候选层面"明确不做季节错位"（《换图决策需求》4.4 注）与品类级旺季规划不矛盾——品类量价周期真实存在，两条决策记录各自成立。换图不是节奏型节点：换图单由诊断批准或检视队列产生，不按批次排；换图集中整修走淡季实例的整修链。

## 7.2 品类同期指数曲线

- **回算**：品类 × 站点组，近 2–3 年销量按周聚合、逐年归一化、跨年平均 → 52 周相对强弱曲线。默认组用全站剔除南半球组数据。
- **四个点的识别**（全部按品类 × 站点组，输出「预计第 N 周 ± k 周」）：

| 点 | 识别规则 | 归属 |
|---|---|---|
| 启动拐点 | 低位连续 N 周上行、累计涨幅超阈值 | 旺季实例锚点 |
| 峰值周 | 旺季窗口内指数最高周 | 旺季实例属性 |
| 回落拐点 | 峰值后连续 M 周下行、累计跌幅超阈值 | 旺季窗口结束 = 淡季窗口开始 |
| 谷底周 | 淡季窗口内指数最低周 | 淡季实例锚点 |

- **窗口形状**：从曲线派生三项属性，随曲线版本走——峰值倍数（峰值指数 ÷ 启动前基线）、爬坡斜率（启动到峰值的周均涨幅）、回落斜率（峰值到回落的周均跌幅）。用在年度规划目标篇的月度分解加权、叠加包期间目标按曲线周分解成节奏、投放蓄水与备货节奏。
- **置信度**：历年同一拐点周的离散度。三年都在第 9–10 周为高置信，第 6 到 14 周飘为低置信；k 由离散度给出。
- **一份资产三处复用**：判定引擎的品类同期校正、节点日历的拐点识别、年度规划目标篇的月度分解加权（《战略目标层需求》5.1）共用同一条曲线，全系统只建一份。
- **冷启动**：历史不足 2 年的品类用相近品类曲线代用或人工录入节点；南半球组数据不足时，用默认组曲线平移 26 周作初稿，人工校正后确认，待自己的数据够两年再回算替换（TBD 11）。
- **年度滚动重算**：新一年数据进入后刷新曲线并生成下一年实例；拐点偏差与形状偏差回写识别规则（7.5）。

## 7.3 节点定义与节点实例

| 对象 | 字段 | 性质 |
|---|---|---|
| 节点定义 | 品类（或"全站"）× 站点组（默认 / 覆盖）、节点类型（旺季 / 淡季 / 大促 / 节奏型）、识别规则版本 + 曲线版本、提前量配置分项（旺季：上新倒排 W / 专项规划 X / 素材准备 Y / 投放蓄水 Z；淡季：整修链各环提前量；品类可配）、历年预测偏差记录 | 资产，年年复用 |
| 节点实例 | 所属定义、年度、第几次（双峰品类一年两个旺季）、范围（站点组；日历型可为全站 / 单站点）、**锚点三值**（系统预测 / 人确认 / 事后实际）、窗口起止（预测 / 确认 / 实际）、峰值周、窗口形状三项、置信度、证据（曲线图、历年实际拐点）、触发链（各环任务 × 触发日期 × 状态 × 派生意图单批次号）、状态、确认人与时间 | 周期型每年由定义自动生成；日历型人工新建；节奏型规划表生成 |

**实例状态机**：待确认 → 已排期 → 触发中 → 进行中 → 已结束 → 已复盘。

**人工确认**：

- 确认什么：确认或修正锚点周与窗口起止，不是只点同意。预测、确认、实际三值都存，复盘才分得清是模型错了还是人改错了。
- 什么时候：年初曲线重算后系统生成全年实例，一次批量确认；每季度规划会前对下一季实例用最新数据重算做滚动复核，有变化的回到待确认。
- 不确认会怎样：触发链不能启动。临近 T−W（最早一环）仍未确认，进待办催办；再拖即触发链延误预警。
- 高置信节点（离散度 ≤1 周且连续两年预测偏差 ≤1 周）将来可配置自动确认，一期全部人工。

> 与战略层的分界：节点的日期、曲线与窗口形状是**日历事实**，住这里；对节点的**重大押注**（如"旺季 GMV 占比提至 40%"）是可证伪判断，登记进战略假设清单（《战略目标层需求》4.2 第 4 类来源），其"影响范围"指向对应叠加包。

## 7.4 触发链

**旺季实例**（T = 启动拐点周）：

```
T−W 周 ─→ 上新批次触发（提前量最长：生产 + 素材 + 新品爬坡期 ≈ 90 天）
T−X 周 ─→ 专项规划任务：生成节点叠加包草稿 → 专项规划会定稿锁定
T−Y 周 ─→ 素材准备意图单下发（L3 → L4 商品契约 → 灵鉴 → 灵枢）
T−Z 周 ─→ 投放蓄水意图单（营销域，直连灵犀）
T      ─→ 节点启动：实例转"进行中"，叠加包目标 vs 实际按曲线周节奏对照（进度，周刷）
回落   ─→ 收尾动作：清仓处置、投放收缩、停止本季上新（淡季实例的窗口从这里开始）
T+结束 ─→ 复盘任务：叠加包达成判定 + 预案有效性复盘 + 形状偏差
```

**淡季实例**（T = 谷底周，窗口 = 回落 → 下一次启动）走**整修链**：换图集中、素材补齐批次、结构调整与收缩处置排在窗口内，提前量短；一般不设期间目标，只有动作包与产能预留，复盘看整修完成率。

- 专项规划是旺季触发链的标准首环（上新触发除外，它更早）：不是孤立会议，而是节点实例上的任务，产出物挂回实例。
- 各环时点系统按提前量倒推给初稿，专项规划会上可人工调整。
- **触发链延误为日级预警**：错过提前量无法补救。

**进行中的进度与结论分工**：窗口内实际指数（实际周销量 ÷ 启动前基线）vs 曲线预期指数是**进度**，周刷，显示在驾驶舱节点区，不出结论；月度快照日驾驶舱按「节点进度偏离」规则出结论（《品类驾驶舱需求》5.3），出口回叠加包动作包或蓄水投放加码。单位用周不用月：旺季窗口常只有 8–12 周，按月看不出偏离。

## 7.5 复盘回路

节点结束后复盘任务收三笔账，回写两个资产：**拐点偏差**（预测 / 确认 / 实际三值的周差）与**形状偏差**（实际爬坡斜率、峰值倍数、回落斜率 vs 预期）回写节点定义，校准识别规则与曲线，并喂基线预测；**预案有效性**（哪些起效/无效/漏项）回写预案库，草稿预案跑过一次且复盘后升"验证预案"。

# 8. 预案库

一个库、按域分区（商品 / 活动 / 营销 / 供应链…），分级与修订规矩全域通用；v1 只启用商品分区。冷启动：第一批预案从历史动作整理（历次换图 push、大促准备动作），不求全，求"下次不从零想"。

| 字段组 | 字段 |
|---|---|
| 标识 | 预案名、所属域分区、适用节点类型（旺季 / 淡季整修 / 大促 / 节奏型）、适用范围（品类 / 全站 × 站点组）、分级（草稿 / 验证）、版本 |
| 内容 | 动作清单（动作 × 相对时点 T−n 周 × 资源需求 × 负责环节 × 产出的意图单类型）、触发条件说明 |
| 沉淀 | 历次使用记录（节点实例引用）、复盘修订记录（有效/无效/漏项） |

- **轻量分级**：草稿预案（没跑过）/ 验证预案（跑过至少一次且复盘）。不建风格库式的重验证期机制。
- **修订**：每次节点复盘回写（7.5）；预案库属资产环成员，与风格库、阈值同列。

# 9. 专项规划与节点叠加包

规划事件两类：季度例行规划会 + 节点触发的专项规划（品类旺季、全站大促均需专项）。专项规划的产出是叠加包：不改季度锁定版基础目标，在其上叠加期间目标 + 动作包 + 资源预留，独立版本、独立复盘。全站大促（黑五）为**跨品类节点包**，资源从全站总账的专项池预留出，不占单站点专项池。

| 字段组 | 字段 |
|---|---|
| 标识 | 所属节点实例、覆盖范围（品类列表 / 全站跨品类 × 站点组）、版本与状态（草稿 → 锁定 → 复盘完成）、Owner、关联假设编号（重大押注时） |
| 期间目标 | GMV / 销量增量目标（相对基础版的叠加值）、期间窗口（取实例窗口）、按曲线周分解的节奏；淡季实例一般不设 |
| 动作包 | 预案模板引用 + 本次增删调整（动作 × 对象范围 × 完成时限） |
| 资源预留 | 专项池产能申请（量 + 来源账：站点账 / 总账）、投放预算预留、期间事件单占用（只读） |
| 复盘 | 达成判定结果、动作有效性记录（回写预案库）、拐点偏差记录（回写节点定义） |

生命周期：触发链 T−X 环生成草稿 → 专项规划会定稿锁定 → 节点进行中对照达成 → 节点结束复盘完成。专项池申请按规则组的专项池优先级排队（4.2）。专项规划会节奏与参会角色 TBD 6。

# 10. 产能账

## 10.1 两本账

| | 常规池 | 专项池 |
|---|---|---|
| 分配轴 | 站点 × 等级（现行灵鉴规则**保留**：站点总比例 → 站内按等级） | 品类 × 事件（节点叠加包、上新批次） |
| 驱动 | 规则自动：等级挂素材要求 → 缺口生成任务 → 排队 | 规划驱动：专项规划定包，按规则组专项池优先级排队，经 L3 下发 |
| 哲学 | 资源跟着表现走（不问品类） | 资源跟着战役走（以品类为锚） |
| 事件单扣减 | 诊断批准的素材单、换图单从常规池扣 | 叠加包期间批准的事件单从该包预留扣 |

品类在常规池的份额是**涌现**的（S/A 级商品多的品类自然多拿），规划表不推翻它。事件单从哪个池扣由钩子预填，人不选；**单池累计占用超阈值要加签**（规划 Owner，阈值在配置中心蓝图分区，《灵策总纲》3.4）；批量单与事件单的消耗分列记账。

**品类资源倾斜的四个杠杆**（均不碰常规池规则）：① 上新量（新品走新品素材档，上新计划直接带产能）；② 节点叠加包（战役性投入走专项池）；③ 处置态池子大小（移入/移出"优化"态改变常规池需求量）；④ 素材与换图倾斜档（4.2）。

## 10.2 三级账

```
全站总账（总盘层）
├─ S 级站点单独账（逐站一本）
└─ 默认账（A 级单列小计可见、B/C/D 级合并计，走全局默认规则）
```

| 账 | 内容 | 谁定 |
|---|---|---|
| 全站总账 | 产能总量（人力盘）、常规/专项池总预留比、全站供需总对账、站点间比例调剂、跨品类节点包预留 | 管理层 / 规划会 |
| 站点单独账 | 站点资源比例、站内等级优先级、站内常规/专项比、站内对账 | 站点 Owner |
| 默认账 | A 级站点单列小计、B/C/D 级合并计；随总账带过，异动才拆看 | — |

| 字段组 | 字段 |
|---|---|
| 标识 | 账层级、期间（季度 + 月度切片）、锁定版本号（与规划表同锁，4.4） |
| 供给 | 产能总量（单位口径 TBD 3）、常规池 / 专项池预留比 |
| 分配 | 站点比例（总账层，以站点分级各档开发资源比例为输入）、站内等级优先级（站点账层，沿用灵鉴配置） |
| 消耗 | 需求预估（各品类行汇总）、实际消耗（批量单 / 事件单两列）、任务积压量、事件单资源占比、人工来源占比、单池加签触发记录 |
| 对账 | 月度对账结论（正常/积压/超支）、调剂记录 |

- **恒等式**：总账 = Σ 站点单独账 + 默认账；任一层改比例自动校验加总。
- **单独账门槛** = 站点分级表当期 S 级（《战略目标层需求》5.5），跟季走；升降档带交接清单（单独账开立或合并）。开发资源比例以该册 5.4 各档比例为输入。
- 常规池规则的配置逐步上收至配置中心蓝图分区（TBD 4）。

## 10.3 月度对账

本节是诊断矩阵**站点 × 商品**格子的定期诊断（《灵策总纲》3.6），全局快照日一月一次，自上而下三层对应三种决策：

| 诊断维度 | 在看什么 | 非正常时的出口 |
|---|---|---|
| 总账供需 | 总积压；**事件单资源占比**（事件单消耗 ÷ 总消耗）；**人工来源占比**（来源为人工的意图单消耗占比） | 积压 → 人力盘（招人/外包），不是改分配；两个占比超阈 → 推回规划层：是蓝图少规划了还是动作层在绕过蓝图 |
| 站点账 | 站点间结构是否失衡 | 总账层调剂站点比例 |
| 品类行 | 需求是否超出产能；单池事件单占用是否触加签线 | 砍处置态池、调排期，或申请专项包 |

对账结论三态：正常 / 积压 / 超支，回填规划表板块 3 对账状态列，并进月度快照。积压或事件单占用超阈可提前触发对账。
