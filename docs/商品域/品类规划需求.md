# 品类规划需求（商品域 · 经营蓝图册）

> 版本：v0.3（已按《灵策总纲》修订：原"动作日历/任务包"表述统一为**意图单**（总纲 3.4），下发经 L4 契约分流（总纲 3.5）；L2 层级定名"经营蓝图"（总纲 3.3），"三件套"保留为商品域规划套件的机制名）
> L2 经营蓝图 · 商品域：品类规划表 + 节点日历 + 预案库。回答"动作为什么不及时"的根因——没有规划。
> 节点日历与预案库为全域共用件（机制全域通用，字段级定义暂存本册）。
> 上游依赖《品类驾驶舱需求》（现状与快照）、《商品对象层需求》（等级/处置态/新品）、《换图决策需求》（判定引擎/风格库/配置机制）。待定项统一标注 **TBD**，见第 15 节。

# 1. 背景与目标

## 1.1 现状

- **动作不及时的根因是没有规划**：关键节点（品类旺季拐点、大促）没有前置动作清单，事到临头才组织。
- **规划散在人脑与文档**：品类目标、上新计划、资源分配无固定载体、无版本、无复盘对照物。
- **旺季靠经验**：拐点时间、提前量、动作清单依赖个人记忆，无法沉淀与校准。

## 1.2 目标

- 三件套成为 L3 意图单生成的周期性来源：**规划表（哪些品类发力）× 节点日历（什么时候）× 预案库（做什么动作）→ 一批意图单草稿 → 人确认后下发**（格式与钩子见《灵策总纲》3.4）。**蓝图未锁定不生成单子。**
- 规划从"文档"升级为"数据对象"：有版本、有锁定、有留痕、可被快照对照复盘。
- 季节周期系统化：从历史数据回算，而非依赖记忆。

## 1.3 设计原则

- **算出来的和定出来的分开**：驾驶舱是计算结果（自动刷新、无人签字），规划表是决策结果（锁定、版本、Owner、承诺）。混在一起复盘就没有对照物。
- **目标下放的可控性原则**：指标只下放到能对它负责的层级。利润的决定因素不在品类执行层手里，利润目标留在总盘层。
- **数据日刷、结论月出、承诺季锁、节点事件驱动**（周期总原则，见 9.1）。
- **系统给初稿、人有终决权**：自动字段（基线预测、需求预估、触发链时点）均可人工修正、留痕。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 三件套 | 域规划表 × 节点日历 × 预案库，**可复制的域规划模式**；本文档是商品域实例（品类规划表）。其中**节点日历与预案库为全域共用件**：日历全公司一本（各域的叠加包/活动/EDM 波次/产能提前量挂同一批节点），预案库一个、**按域分区**（商品/活动/营销…），草稿/验证分级规矩通用 |
| 规划树 | 规划的对象层级：总盘 → 站点 → 品类（站点在品类上一层） |
| 锁定版本 | 季度规划会锁定的规划表快照；复盘与判定的对照物，不回溯 |
| 节点叠加包 | 节点专项规划的产出：不改季度基础目标，在其上叠加期间目标 + 动作包 + 资源预留，独立版本独立复盘 |
| 同期指数曲线 | 品类 × 周的销量相对强弱曲线（2–3 年历史回算），季节性的数据本体 |
| 节点定义 / 节点实例 | 定义是规则资产（年年复用），实例是某一年的具体节点（自动生成、人确认、带触发链） |
| 触发链 | 节点实例按提前量倒推出的任务序列（专项规划 → 上新 → 素材 → 蓄水 → 启动 → 复盘）；链上对执行侧的下发物统一为**意图单** |
| 常规池 / 专项池 | 产能两本账：常规池按"站点 × 等级"规则自动分配（现行灵鉴机制）；专项池按"品类 × 事件"由规划驱动 |
| 产能三级账 | 全站总账 → S 级站点单独账 → 默认账（长尾站点合并） |
| 基线预测 | 存量盘子在"不做额外动作"假设下的产出预测（历史同期 × 趋势 × 季节曲线），目标合理性与上新缺口的计算基准 |

# 3. 总体结构

## 3.1 三件套与相乘语义

| 件 | 回答的问题 | 性质 |
|---|---|---|
| 品类规划表 | 每个品类要去哪、现在在哪、差多少、靠什么补 | 承诺（锁定版本） |
| 节点日历 | 什么时候必须做什么 | 时间锚（定义生成实例） |
| 预案库 | 到了节点具体做哪些动作 | 资产（复盘修订） |

相乘生成批量意图单的语义：规划表的策略与目标包 × 节点实例的触发时点 × 预案模板的动作清单 → 一批意图单草稿（对象/目标/预算/时限，不写实现步骤）→ 人确认后经 L4 契约分流下发：商品域素材/换图类经灵鉴路由至灵枢，营销类直连灵犀，客服类至鹊桥，执行方待定环节（价格·上下架、运营、供应链）落人工工作台（《灵策总纲》3.5）。

## 3.2 规划树与经营对象树

规划按**总盘 → 站点 → 大类 → 品类**展开（站点在品类上一层：先看哪个站点，再看站点下大类与品类；大类为静态归类：衣服 / 鞋子+ACC，规划表按大类分组小计）。这是"经营对象树"（总盘 → 站点 → 大类 → 品类 → SPU → SKU）在规划层的投影——各层制品在对象树的不同层级实例化：L0 目标挂总盘、规划表挂站点 × 品类、驾驶舱挂品类、动作挂 SPU、结构三维挂 SKU。

- **站点分级**（S/A/B/C/D 五档、季度评分，定档机制与各档待遇见《战略目标层需求》5.4）：S 级站点配有专属团队（组织现实），规划树与责任树同构——站点层 Owner 实名，品类行 Owner 暂由站点 Owner 兼任（品类负责人角色落定后切换）；A 级固定 Owner 兼任。
- **v1 站点口径**：规划表直接按站点 × 品类两级建；驾驶舱数据视图按站点切片全拆，**诊断与信号层 v1 统一跑全站口径**（站点级诊断待全站阈值校准后逐站开启，防止配置爆炸）。

## 3.3 与品类驾驶舱的关系：一个对象、两个视图、两类页面

规划表是独立数据对象（锁定/版本/Owner），驾驶舱"规划区"是它在单品类的**只读投影**（目标/现状/差距三列）。页面职责钉死：

| 页面 | 形态 | 性质 |
|---|---|---|
| 品类驾驶舱页 | 单品类一页（画像/诊断/决策/规划区/节点区） | **只读**。看差距、定位问题、从决策区发起动作 |
| 品类规划表页 | 横向工作台：站点 × 品类全表 | **可编辑**。目标、排期、方向、资源、叠加包在此修改，留痕 |

决策分两类，判据一条：**这次调整需不需要改规划表上已写下的数字或方向**——不需要（批下架、任务插队提优先级）是动作类，走驾驶舱决策区跳各模块工作台（批准即生成事件性意图单，钩子自动填充，见《灵策总纲》3.4）；需要（改上新排期、调产能分配、换补款方向）是规划类，跳规划表页编辑留痕。两类之间的桥是**产能对账**：动作层持续插队会以任务积压的形式在月度对账中显形，推回规划层重新决策。

# 4. 品类规划表

## 4.1 规划内容：五个板块

| 板块 | 规划的内容 | 数据来源（下层喂上来） |
|---|---|---|
| 1 结果目标 | GMV、销量（站点 × 品类）；毛利率只读参考列 | 基线预测 + 总盘分配对齐 |
| 2 盘子规划 | 上新（数量/方向/节奏/质量线）、汰换预估、结构调整方向、期末在架规模 | 驾驶舱结构三维、补款建议、观察态积压、动销率 |
| 3 动作与产能 | 素材补齐量、换图轮巡量、常规池需求预估、专项包申请、产能对账 | 素材完备度差距、检视队列、上新规划推导 |
| 4 营销资源 | 花费预算/占比、主推方向 | 驾驶舱营销效率面板、集中度信号 |
| 5 节点 | 本季节点清单 + 各节点叠加包状态 | 节点日历触发链 |

两个恒等式是表的骨架：

```
期末盘子 = 期初在架 − 汰换 + 上新
GMV 目标 = 存量款基线贡献 + 新款贡献缺口
```

## 4.2 上新规划：四个来源合成一个决策

上新规划 = 数量 × 方向 × 节奏 × 质量线：

| 维度 | 来源 | 机制 |
|---|---|---|
| 数量 | 目标差距反推 | 缺口 ÷（品类新品成功率 × 成功新品平均产出）≈ 需上新 N 款 |
| 方向 | 结构缺口 + 风格信号 | 驾驶舱结构三维错配/补款建议（价格段/颜色/尺码）；风格库计分卡的上升风格与低拥挤度风格 |
| 节奏 | 节点倒排 | 旺季款上架时间 = 拐点 − 生产周期 − 素材周期 − **新品爬坡期（约等于保护期 90 天）**；上新是触发链中最早的动作 |
| 质量线 | 新品成功率目标 | 考核"成功了多少款"而非"上了多少款" |

**约束项：产能。** 上新素材需求 + 存量补齐 + 换图轮巡 = 设计产能需求，规划会对账实际产能，超了优先砍观察态商品投入（优化池收缩）。生产端打样产能为供应链占位字段，人工填（**TBD**）。

## 4.3 目标口径与来源

- 结果目标以 **GMV + 销量**为主；利润不下放品类（可控性原则），毛利/贡献利润保留为参考列，利润目标由管理层在总盘层持有。
- **目标来源：年度规划切片**——季度目标 = 年度规划（《战略目标层需求》第 5 节）的季度切片 + 规划会校准（校准幅度留痕，累计偏离过大回检战略假设）。年度规划建成前的过渡：双向对齐——系统自下而上出基线预测，管理层自上而下给总盘目标，差额在规划会分配到站点 × 品类、锁定。目标四件套（口径/基线/目标值/Owner）先作为规划表字段落地，L1 指标树上线后挂树。
- 基线预测值留档：事后"预测 vs 实际"是规划方法本身的校准指标（预测能力和判定阈值一样是被复盘的资产）。

## 4.4 版本与锁定

- **季度规划会锁定**基础版本，锁定即快照；复盘与判定对锁定版本比，不回溯。
- **月度目标环调整窗口**：月会看完快照差距后，规划内容（排期/方向/资源/动作包）集中调整、留痕；目标值不动。
- **目标值变更**仅两个时点：季度规划会（正常更新）；季中战略环级异动（平台政策/汇率/供应链剧变），走变更审批留痕，且此类变更回流 L0 战略假设检验。
- **节点叠加包**独立版本：季度复盘对基础版、节点复盘对叠加包，两层互不污染。

# 5. 节点日历

## 5.1 三类节点

| 类型 | 例子 | 来源 |
|---|---|---|
| 周期型 | 品类旺季拐点 | 同期指数曲线回算 → 自动生成候选 → 人确认 |
| 日历型 | 平台大促（黑五）、节日 | 人工录入；进同一实例状态机，后续机制共用 |
| 节奏型 | 上新批次、换图轮巡 | 由规划表过程目标推导生成 |

> 口径澄清：换图候选层面"明确不做季节错位"（SPU 级图片季节信号对婚纱礼服不成立，《换图决策需求》4.4 注）与品类级旺季规划不矛盾——品类量价周期（婚礼季）真实存在，两条决策记录各自成立。

## 5.2 品类同期指数曲线（季节性的数据本体）

- **回算**：品类近 2–3 年销量按周聚合、逐年归一化（消年度增长）、跨年平均 → 52 周相对强弱曲线。
- **拐点识别**：指数低位连续 N 周上行且累计超阈值 → 旺季启动拐点；同理识别峰值、回落点。输出"预计第几周"。
- **一份资产三处复用**：判定引擎的品类同期校正、节点日历的拐点识别、**年度规划目标篇的月度分解加权**（《战略目标层需求》5.1）共用同一条曲线，资产环统一维护，全系统只建一份——战略层的月度目标线和规划层的节点曲线永远是同一条，不另存副本。
- **冷启动例外**：历史不足 2 年的品类用相近品类曲线代用或人工录入节点（人工节点的正当来源）。
- **年度滚动重算**：新一年数据进入后刷新曲线；拐点预测偏差（预计周 vs 实际周）回写识别规则校准。

## 5.3 节点定义与节点实例

| 对象 | 内容 | 性质 |
|---|---|---|
| 节点定义 | 品类、节点类型、识别规则与曲线版本、提前量配置（分项见 5.4，品类可配） | 资产，年年复用 |
| 节点实例 | 某一年的具体节点：预计拐点周 + 倒推触发日期链 + 状态 | 每年由定义自动生成 |

实例状态机：**待确认 → 已排期 → 触发中 → 进行中 → 已结束 → 已复盘**。"待确认"不可省：季节回算是统计推断，系统出证据（曲线图 + 历年实际拐点），人确认后排期——"规则出证据 + 人拍板"。

> 与战略层的分界：节点的日期与曲线是**日历事实**，住这里；对节点的**重大押注**（如"旺季 GMV 占比提至 40%"）是可证伪判断，登记进战略假设清单（《战略目标层需求》4.2 第 4 类来源），其"影响范围"指向对应叠加包，证伪时顺藤回调。

## 5.4 触发链

```
T−W 周 ─→ 上新批次触发（提前量最长：生产 + 素材 + 新品爬坡期 ≈ 保护期 90 天）
T−X 周 ─→ 专项规划任务：生成节点叠加包草稿（目标包模板 + 预案动作清单初稿）→ 专项规划会定稿锁定
T−Y 周 ─→ 素材准备意图单下发（经 L3 → L4 商品契约 → 灵鉴路由 → 灵枢）
T−Z 周 ─→ 投放蓄水意图单（营销域，直连灵犀）
T      ─→ 节点启动：驾驶舱节点区转"进行中"，展示叠加包目标 vs 实时达成
T+结束 ─→ 复盘任务：叠加包达成判定 + 预案有效性复盘
```

- **专项规划本身是触发链的标准首环**（上新触发除外，它更早）：不是孤立会议，而是节点实例上的任务，产出物（叠加包）挂回实例。
- 触发链各环时点系统按提前量倒推给初稿，专项规划会上可人工调整。
- **触发链延误为日级预警**（与红线触发并列为仅有的两类"等不起"信号）：错过提前量无法补救。

## 5.5 复盘回路

节点结束后复盘任务收两笔账，分别回写两个资产：

- **拐点预测偏差** → 回写节点定义，校准识别规则；
- **预案有效性**（动作清单哪些起效/无效/漏项）→ 回写预案库，草稿预案跑过一次且复盘后升"验证预案"。

# 6. 预案库

- **全域共用、按域分区**：库一个，分区按域（商品预案 / 活动预案 / 营销预案 / 供应链预案…），本文档定义的分级与修订规矩全域通用；v1 只启用商品域分区。
- **预案模板** = 节点类型 × 触发时机 + 动作清单 + 资源需求 + 历史复盘记录 + **所属域分区**（结构见 10.4）。
- **冷启动**：第一批预案从历史动作整理（历次换图 push、大促准备动作），不求全，求"下次不从零想"。
- **轻量分级**：草稿预案（没跑过）/ 验证预案（跑过至少一次且复盘）。不建风格库式的重验证期机制。
- **修订机制**：每次节点复盘回写；预案库属资产环成员，与风格库、阈值同列被数据持续校准。

# 7. 专项规划与节点叠加包

- **规划事件两类**：季度例行规划会 + 节点触发的专项规划（品类旺季、全站大促均需专项）。
- **叠加包机制**：不改季度锁定版基础目标，在其上叠加期间目标（GMV/销量增量）+ 动作包（预案引用 + 本次调整）+ 资源预留（专项池申请、投放预留），独立版本、独立复盘。
- 全站大促（黑五）为**跨品类节点包**，资源从全站总账的专项池预留出（不占单站点专项池）。

# 8. 产能账

## 8.1 两本账

| | 常规池 | 专项池 |
|---|---|---|
| 分配轴 | 站点 × 等级（现行灵鉴规则**保留**：站点总比例 → 站内按等级） | 品类 × 事件（节点叠加包、上新批次） |
| 驱动 | 规则自动：等级挂素材要求 → 缺口生成任务 → 排队 | 规划驱动：专项规划定包，经 L3 下发 |
| 哲学 | 资源跟着表现走（对象层哲学延续，不问品类） | 资源跟着战役走（规划层意志，以品类为锚） |

品类在常规池的份额是**涌现**的（S/A 级商品多的品类自然多拿），规划表不推翻它——品类规划的产能内容是**需求预估 + 专项包申请 + 对账**，不是分配（见 10.1 板块 3）。

## 8.2 三级账结构

```
全站总账（总盘层）
├─ S 级站点单独账（有专属规则与 Owner 的站点，逐站一本）
└─ 默认账（A–D 级站点：A 级单列小计可见、B/C/D 级合并计，走全局默认规则；分档见《战略目标层需求》5.4）
```

| 账 | 内容 | 谁定 |
|---|---|---|
| 全站总账 | 产能总量（人力盘）、常规/专项池总预留比、全站供需总对账、**站点间比例调剂**、跨品类节点包预留 | 管理层 / 规划会 |
| 站点单独账 | 站点资源比例、站内等级优先级、站内常规/专项比、站内对账 | 站点 Owner |
| 默认账 | A 级站点单列小计、B/C/D 级合并计；随总账带过，异动才拆看 | — |

- **恒等式约束**：总账 = Σ 站点单独账 + 默认账；任一层改比例自动校验加总，防"各账合理、加总超产能"。
- **单独账门槛**：配专属 Owner 且有独立资源比例的站点才开单独账（现状即 S 级站点）——站点分级的第一个系统化用途。

## 8.3 月度对账顺序（自上而下，三层对应三种决策）

本段是诊断矩阵**站点 × 商品**的定期诊断。结论出在产能账页，一月一次，不另开诊断页。

| 诊断维度 | 在看什么 | 非正常时的出口 |
|---|---|---|
| 总账供需 | 总积压 | 人力盘（招人/外包），不是改分配 |
| 站点账 | 站点间结构是否失衡 | 总账层调剂站点比例 |
| 品类行 | 需求是否超出产能 | 砍处置态池（优化池收缩）、调排期，或申请专项包 |

## 8.4 品类资源倾斜的四个杠杆（均不碰常规池规则）

1. 上新量（新品走新品素材档，上新计划直接带产能）；
2. 节点叠加包（战役性投入走专项池）；
3. 处置态池子大小（移入/移出"优化"态改变常规池需求量）；
4. （留作后手）等级规则的品类覆盖——战略品类 B 级享 A 级素材标准，走配置作用域机制，不急开。

# 9. 使用回路与周期

## 9.1 周期总表

**总原则：数据日刷、结论月出、承诺季锁、节点事件驱动。**

| 侧 | 内容 | 周期 |
|---|---|---|
| 驾驶舱 | 画像面板数据 | 日刷（滚动窗口：30 天等级/动销、90 天换图、12 个月集中度分位、2–3 年季节曲线） |
| 驾驶舱 | 红线预警 + 触发链延误 | **日级**（仅有的两类"等不起"信号） |
| 驾驶舱 | 诊断结论正式输出 + 月度快照 | 月度快照日（默认每月 1 日） |
| 驾驶舱 | 决策区待办 | 跟随来源模块（处置周批、补款/集中度月度、红线日级） |
| 规划表 | 目标值 | 季度规划会锁定；节点专项出叠加包；季中仅战略环异动 |
| 规划表 | 规划内容（排期/方向/资源/动作包） | 月度目标环窗口集中调整、留痕 |
| 规划表 | 节点叠加包 | 事件驱动（触发链） |
| 规划表 | 产能对账 | 月度；积压超阈可提前触发 |

两侧用**快照日咬合**：快照 → 差距成立 → 月会 → 规划表调整窗口 → 下月快照检验。日刷数据只用于盯红线和进度，不作为调规划的依据（单日波动不构成规划信号）。

## 9.2 月度动线（在驾驶舱内走完"看"）

1. 规划区看差距（红黄绿），绿的翻页（诊断区显式"本期正常"），红黄的花时间；
2. 画像区定位差距在哪个板块（GMV 差距是四种问题的总和，拆开看哪条腿瘸）；
3. 诊断结论区看为什么（信号 + 证据）；
4. 决策区领动作 / 跳规划表调内容。

## 9.3 调整对照表：看到什么，调什么

| 差距定位 | 责任板块 | 月度调整 |
|---|---|---|
| 上新数量落后排期 | 盘子·节奏 | 补排期、产能重分配；旺季倒排的上新最不能拖 |
| 上新够但成功率低 | 盘子·方向 | 重校结构缺口与风格选择，下批调向；数量不加码 |
| 存量基线掉（等级恶化、动销降、观察积压涨） | 盘子·汰换 + 动作 | 换图/素材加码、汰换提速、产能从低效池转移 |
| 流量掉（访客/花费未达） | 营销资源 | 投放执行问题，找站点营销 Owner |
| 转化掉（流量在、单访客收入降） | 动作·素材/换图 | 商品侧动作优先级提升 |
| 结构错配未收敛 | 盘子·结构 | 补款建议升级为上新方向输入 |
| 产能对账失衡（积压） | 动作与产能 | 观察态扩容、优化池收缩，或申请专项包 |
| 触发链延误 | 节点叠加包 | 人工提级，最高优先级 |

## 9.4 差距归因回写

差距若源于规划时的错误假设（基线预测偏高、成功率高估），记账到规划方法，季度规划会校准预测模型。

# 10. 表单定义（字段与口径级，不含界面原型）

## 10.1 表单一：品类规划表行（站点 × 品类）

**标识组**：站点 / 品类 / 季度 / 版本号与状态（草稿 → 锁定 → 变更中）/ Owner（站点运营实名）

**板块 1 结果目标**：GMV 目标、销量目标、基线预测值（系统回算、留档）、目标依据备注；毛利率只读参考列

**板块 2 盘子规划**：期初在架 SPU 数（自动）、上新数量目标、上新方向（**结构化枚举**：价格段/颜色/尺码/风格四维缺口勾选 + 备注，标注来源：结构错配信号 / 风格库信号）、上新节奏（批次 × 目标上架周，旺季款标注倒排依据）、新品成功率目标线、预计汰换数（系统预估 + 人工修正）、期末盘子规模（恒等式自动算）

**板块 3 动作与产能**：素材补齐量预估（完备度差距推导，自动）、换图轮巡量预估（检视队列推导，自动）、常规池需求预估（自动汇总）、专项包申请（关联表单二，列表）、对账状态（月度回填：正常/积压/超支）

**板块 4 营销资源**：花费预算或占比、主推方向（枚举：头部巩固/第二梯队培养/新品扶持，可多选）

**板块 5 节点**：本季关联节点实例列表 + 叠加包状态（引用，不重复填）

**现状与差距列**（全部只读，月度快照自动映射）：板块 1–3 每个目标字段的现状值、差距、达成率、红黄绿标识

> 通用规则：自动字段可人工修正但留痕；方向类字段用枚举不用自由文本（否则复盘无法对"方向对不对"记账）。

## 12.2 系统对接

- **驾驶舱**：快照喂现状列；规划区/节点区投影启用；结构错配与补款建议作为上新方向输入。
- **判定引擎**：共建共维同期指数曲线（一份资产两处用）。
- **风格库**：计分卡上升风格 / 低拥挤度风格 → 上新方向输入（风格库第二消费场景）。
- **对象层**：新品成功率与平均产出、观察态积压、处置态池规模。
- **灵鉴**：常规池规则（站点比例 + 等级优先级）保留现行机制，配置逐步上收至决策系统配置中心挂站点层规划（**TBD** 时点）；专项包经 L3 意图单 → 灵鉴路由 → 灵枢（商品域部分；其他域按 L4 契约分流，见《灵策总纲》3.5）。
- **L1 指标树（未来）**：目标四件套字段挂树；新品成功率、素材完备度品类目标向上对齐。
