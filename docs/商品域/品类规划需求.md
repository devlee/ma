# 1. 背景与目标

## 1.1 现状

- **动作不及时的根因是没有规划**：关键节点（品类旺季拐点、大促）没有前置动作清单，事到临头才组织。
- **规划散在人脑与文档**：品类目标、上新计划、资源分配无固定载体、无版本、无复盘对照物。
- **旺季靠经验**：拐点时间、提前量、动作清单依赖个人记忆，无法沉淀与校准。

## 1.2 目标

- 把商品域的蓝图四项——要什么（目标）、投多少（资源）、怎么分（规则）、何时动（节奏）——放进一个有版本、有锁定、有留痕、可被快照对照的数据对象，季度一起锁。
- 三件套成为 L3 批量意图单的周期性来源：**规划表（哪些品类发力）× 节点日历（什么时候）× 预案库（做什么动作）→ 一批意图单草稿 → 人确认后下发**（三条纪律见《灵策总纲》3.4，字段见《意图单需求》3.1）。**蓝图未锁定不生成单子。**
- 季节周期系统化：从历史数据回算，而非依赖记忆。

## 1.3 设计原则

- **算出来的和定出来的分开**：驾驶舱是计算结果（自动刷新、无人签字），规划表是决策结果（锁定、版本、Owner、承诺）。混在一起复盘就没有对照物。
- **目标和资源一起锁**（《灵策总纲》3.3）：只锁目标不锁资源，未达成时分不清"执行不力"还是"资源不足"。规划表锁定时，该季产能账的配额同时锁。
- **季度规划是年度规划的季度版本，月度不设规划**（《战略目标层需求》5.2）：目标值由年度规划季度版本持有，规划表只引用；月度只改排期、方向、资源、动作包。
- **规则也是引用**：资源怎么分由年度规划策略篇决定，规划表只消费、可偏离写理由，不自定一套。
- **目标下放的可控性原则**：指标只下放到能对它负责的层级。利润留在总盘层，品类层只认 GMV、销量，毛利作参考。
- **数据日刷、结论月出、承诺季锁、节点事件驱动**（对应《灵策总纲》第 7 节四个环，见 6.1）。
- **系统给初稿、人有终决权**：自动字段（基线预测、需求预估、触发链时点）均可人工修正、留痕。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 蓝图四合一 | 目标 × 资源 × 规则 × 节奏，L2 的结构（《灵策总纲》3.3）。本册是它在商品域的实例，对照表见 3.1 |
| 三件套 | 品类规划表 × 节点日历 × 预案库，**商品域规划套件的机制名**，相乘生成批量意图单。其他域有自己的规划表与预案分区，不复用这个名字；节点日历与预案库为全域共用件 |
| 年度规划季度版本 | 年度规划在季度规划会切片校准后锁定的版本（《战略目标层需求》5.2）。站点 × 大类 × 品类的季度 GMV、销量目标的**唯一出处**；规划表板块 1 只读引用 |
| 品类梯度 | 衣服大类四档、鞋+ACC 两档，年度人定、季会可调（《战略目标层需求》5.3）。档位枚举是配置；哪个品类哪一档（名册）是年度规划策略篇商品块的内容 |
| 策略包 | 每个梯度档绑定的商品资源倾斜：专项池优先级、上新配额、素材与换图倾斜档。**名册与每档内容都住在年度规划策略篇商品块**，年会锁定、季会可调；配置中心只放档位枚举和倾斜档的参数含义。规划表以「适用规则组」引用 |
| 适用规则组 | 规划表每行只读引用的一组字段：梯度、上新配额、专项池优先级、素材与换图倾斜档、策略包版本号。让「这一行按什么规则分资源」显式可对照 |
| 规划树 | 规划的对象层级：总盘 → 站点 → 大类 → 品类（站点在品类上一层，大类为静态归类） |
| 锁定版本 | 季度规划会锁定的规划表快照；复盘与判定的对照物，不回溯 |
| 规划 Owner | 规划表行的 Owner（v1 由站点 Owner 兼任）。批量意图单草稿由其确认；单池事件单占用超阈值由其加签 |
| 节点叠加包 | 节点专项规划的产出：不改季度基础目标，在其上叠加期间目标 + 动作包 + 资源预留，独立版本独立复盘 |
| 同期指数曲线 | 品类 × 周的销量相对强弱曲线（2–3 年历史回算），季节性的数据本体 |
| 节点定义 / 节点实例 | 定义是规则资产（年年复用），实例是某一年的具体节点（自动生成、人确认、带触发链） |
| 触发链 | 节点实例按提前量倒推出的任务序列（专项规划 → 上新 → 素材 → 蓄水 → 启动 → 复盘）；链上对执行侧的下发物统一为**意图单** |
| 常规池 / 专项池 | 产能两本账：常规池按"站点 × 等级"规则自动分配（现行灵鉴机制）；专项池按"品类 × 事件"由规划驱动，按梯度排优先级 |
| 产能三级账 | 全站总账 → S 级站点单独账 → 默认账（A 级单列小计、B/C/D 级合并计） |
| 事件单占用 | 诊断里批准开出的事件性意图单从蓝图分配的池子扣额度；单池累计占用超阈值须规划 Owner 加签（《灵策总纲》3.4） |
| 基线预测 | 存量盘子在"不做额外动作"假设下的产出预测（历史同期 × 趋势 × 季节曲线），目标合理性与上新缺口的计算基准 |

## 3.3 三件套与批量意图单生成

| 件 | 回答的问题 | 性质 |
|---|---|---|
| 品类规划表 | 每个品类要去哪、现在在哪、差多少、靠什么补 | 承诺（锁定版本） |
| 节点日历 | 什么时候必须做什么 | 时间锚（定义生成实例） |
| 预案库 | 到了节点具体做哪些动作 | 资产（复盘修订） |

## 3.4 规划树与经营对象树

规划按**总盘 → 站点 → 大类 → 品类**展开（站点在品类上一层：先看哪个站点，再看站点下大类与品类；大类为静态归类：衣服 / 鞋子+ACC，规划表按大类分组小计）。

两个大类的行粒度不同。衣服大类 8 个品类逐行；鞋+ACC 大类 20 多个品类、销售额不到 3%，一期按梯度组织行：重点品类单列，长尾合并为一行，目标给到大类或重点品类，不逐品类拆（梯度两档见《战略目标层需求》5.3）。鞋+ACC 的行一期只有板块 1 结果目标和板块 3 的专项包申请与对账（给到大类或重点品类行），盘子规划、上新方向等板块随驾驶舱二期启用（《品类驾驶舱需求》1.5）。加总校验对两个大类同样生效。这是"经营对象树"（总盘 → 站点 → 大类 → 品类 → SPU → SKU）在规划层的投影——各层制品在对象树的不同层级实例化：L0 目标挂总盘、年度规划挂总盘到品类、规划表挂站点 × 品类、驾驶舱挂品类、动作挂 SPU、结构三维挂 SKU。

- **站点分级**（S/A/B/C/D 五档、季度评分，定档机制与各档待遇见《战略目标层需求》5.4，当期名册见该册 5.5）：S 级站点配有专属团队（组织现实），规划树与责任树同构——站点层 Owner 实名，品类行 Owner 暂由站点 Owner 兼任（品类负责人角色落定后切换）；A 级固定 Owner 兼任。
- **v1 站点口径**：规划表直接按站点 × 品类两级建；驾驶舱数据按站点切片全拆，**诊断与信号层 v1 统一跑全站口径**（站点级诊断待全站阈值校准后逐站开启，防止配置爆炸）。规划差距是机械计算，按站点 × 品类展示不受此限。

## 3.5 规划表与驾驶舱：一个对象、两个视图

规划表是独立数据对象（锁定/版本/Owner）。驾驶舱的"规划区"是它在单品类的**全量只读投影**（五板块的目标 / 现状 / 差距三列），面板一、五、六只带自己指标的目标列，取同一份投影不另存（《品类驾驶舱需求》3.1）；品类列表页总评视图的"规划差距红黄绿"读同一个值（《品类驾驶舱需求》3.2）。驾驶舱和列表页只读，规划表可编辑。

决策分两类，判据一条：**这次调整需不需要改规划表上已写下的数字或方向**——不需要（批下架、任务插队提优先级）是动作类，在驾驶舱决策区批准即生成事件性意图单（钩子自动填充，《灵策总纲》3.4）；需要（改上新排期、调产能分配、换补款方向）是规划类，回规划表编辑留痕。

驾驶舱决策区通向规划表的三条路（《品类驾驶舱需求》第 6 节）：

| 决策区出口 | 落到规划表哪里 | 处理 |
|---|---|---|
| 上新方向输入 | 板块 2 上新方向的候选列表 | 来源结论：上新质量（选款问题）、高毛利段供给不足、结构错配·供给不足、色系与大码机会。月度调整窗口由规划 Owner 采纳或忽略，留痕 |
| 规划会议题 | 规划会议程（按梯度排序） | 来源：姿态与梯度连续 N 个月不符（《品类驾驶舱需求》5.6）、已处理仍持续的预警级结论。候选动作：调梯度、校准目标，都改在年度规划，不改规划表 |
| 跨域议题 | 板块 4 花费预算（过渡态）或叠加包资源预留 | 来源：投放与份额错配等；月会拍板；营销域启动后改派生该域单据，不再经规划表 |

两类之间的桥是**产能对账**：动作层持续插队会以事件单资源占比、任务积压的形式在月度对账中显形，推回规划层重新决策（10.4）。

# 4. 品类规划表

## 4.1 是什么

商品域的承诺对象：站点 × 品类一行，一季一版，锁定后是复盘的对照物。它承载四合一里的目标（板块 1、2）、资源需求（板块 3、4）、节奏（板块 5），并以适用规则组引用规则。

| 板块 | 规划的内容 | 谁拥有 | 数据来源（下层喂上来） |
|---|---|---|---|
| 0 适用规则组 | 梯度、上新配额、专项池优先级、素材与换图倾斜档、策略包版本号 | **年度规划策略篇商品块**（只读引用）；规划表只能偏离并写理由，不能改规则 | 策略篇当期锁定版本 |
| 1 结果目标 | GMV、销量（站点 × 品类）；毛利率只读参考列 | **年度规划季度版本**（只读引用）；规划表只持有基线预测、差距、目标依据备注 | 年度规划季度版本 + 基线预测 |
| 2 盘子规划 | 上新（数量/方向/节奏/质量线）、汰换预估、结构调整方向、期末在架规模 | 规划表 | 驾驶舱结构三维、补款建议、上新方向输入、观察态积压、动销率；上新数量初值取规则组配额 |
| 3 动作与产能 | 素材补齐量、换图需求量、常规池需求预估、专项包申请、产能对账 | 规划表（需求侧）；产能账（供给侧） | 素材完备度差距、检视队列、上新规划推导；专项包按规则组优先级排队 |
| 4 营销资源 | 花费预算/占比、主推方向 | 花费预算/占比为**过渡态**：营销域启动前人工填、只作参考，启动后改为引用营销域规划的品类切片；主推方向（推哪些款）是商品域的选择，始终由规划表拥有 | 驾驶舱营销效率面板、集中度信号 |
| 5 节点 | 本季节点清单 + 各节点叠加包状态 | 节点日历（引用） | 节点日历触发链 |

两个恒等式是表的骨架：

```
期末盘子 = 期初在架 − 汰换 + 上新
GMV 目标 = 存量款基线贡献 + 新款贡献缺口
```

## 4.2 里面有什么

**标识组**：站点 / 大类 / 品类（鞋+ACC 长尾为合并行）/ 季度 / 版本号与状态（草稿 → 锁定 → 变更中）/ Owner（站点运营实名）/ **当期姿态**（只读，取驾驶舱最近一期总评，用于排序和对照）

**板块 0 适用规则组**（全部只读引用，带策略包版本号）：梯度、上新配额（款数）、专项池优先级、素材与换图倾斜档

**板块 1 结果目标**：GMV 目标、销量目标（只读引用，带年度规划季度版本号）、基线预测值（系统回算、留档）、目标依据备注（引用假设编号）；毛利率只读参考列

**板块 2 盘子规划**：期初在架 SPU 数（自动）、上新数量目标（初值 = 规则组配额，偏离写理由）、上新方向（**结构化枚举**：价格段/颜色/尺码/风格四维缺口勾选 + 备注，标注来源：结构错配信号 / 风格库信号 / 机会类结论；上新方向输入候选列表及采纳状态）、上新节奏（批次 × 目标上架周，旺季款标注倒排依据）、新品成功率目标线、预计汰换数（系统预估 + 人工修正）、期末盘子规模（恒等式自动算）

**板块 3 动作与产能**：素材补齐量预估（完备度差距按倾斜档要求推导，自动）、换图需求量预估（检视队列推导，自动）、常规池需求预估（自动汇总）、专项包申请（关联叠加包，列表，按规则组优先级排队）、对账状态（月度回填：正常/积压/超支）、本行事件单占用（只读，来自产能账）

**板块 4 营销资源**：花费预算或占比（过渡态：人工填，标注"过渡"，营销域启动后改为引用）、主推方向（枚举：头部巩固/第二梯队培养/新品扶持，可多选；商品域拥有，不随营销域改引用）

**板块 5 节点**：本季关联节点实例列表 + 叠加包状态（引用，不重复填）

**现状与差距列**（全部只读，月度快照自动映射）：板块 1–3 每个目标字段的现状值、差距、达成率、红黄绿标识

## 4.3 规则

**目标从哪来。** 站点 × 大类 × 品类的季度 GMV、销量目标住在年度规划的季度版本里（《战略目标层需求》5.1、5.2）。季度规划会做切片和校准并锁定；规划表板块 1 读锁定的季度版本，不可在规划表上改。规划表板块 1 自己持有的只有基线预测值、差距与达成率、目标依据备注。利润不下放品类（可控性原则）：毛利率为只读参考列，利润目标由管理层在总盘层持有，站点层预留（《战略目标层需求》TBD 8）。基线预测值留档，事后"预测 vs 实际"是规划方法本身的校准指标。年度规划建成前的过渡：系统自下而上出基线预测，管理层自上而下给总盘目标，差额在规划会分配到站点 × 品类、锁定；过渡期目标值暂存板块 1，年度规划季度版本建成后迁移为引用，历史版本不回算。

**指标树的落点。** L1 责任登记的"目标值指针"指向年度规划或域蓝图的那一格（《战略目标层需求》6.2）。GMV、销量的指针落年度规划季度版本；上新数量、新品成功率目标线、素材补齐量等过程目标的指针落规划表板块 2、3 的格子。口径不在本册重写，指向口径字典。

**规则从哪来。** 策略包的唯一编辑处是年度规划策略篇商品块（《战略目标层需求》5.3）：哪个品类哪一档（名册）和每档的专项池优先级、上新配额、素材与换图倾斜档，一档一行，年会锁定、季会可调、调整挂假设编号。配置中心只放两样：梯度档位枚举；倾斜档的参数含义（高 / 中 / 低档分别对应什么完备度要求、换图候选优先级加几，在对象层与换图分区）。规划表以板块 0 引用策略包当期锁定版本，怎么消费：

| 规则组字段 | 规划表怎么用 |
|---|---|
| 梯度 | 表按大类分组、梯度排序；规划会议程按梯度排序 |
| 上新配额 | 板块 2 上新数量目标的初值；目标差距反推只能在配额基础上上调或说明下调理由；驾驶舱"上新配额未达成"结论读的是板块 2 的数 |
| 专项池优先级 | 板块 3 专项包申请按它排队；产能账专项池分配时同优先级内再看叠加包的期间目标 |
| 素材与换图倾斜档 | 板块 3 素材补齐量预估按该档要求推导；对象层素材要求与换图候选优先级读同一个档 |

梯度调整季会可调，依据来自驾驶舱规划会议题（姿态与梯度连续不符）；改在策略篇，规划表随之刷新规则组，不改已锁定版本。鞋+ACC 大类一期只用重点 / 长尾两档，策略包只有专项池优先级与目标激进度两项，上新配额与素材倾斜随驾驶舱二期启用。

**上新规划：四个来源合成一个决策。** 上新规划 = 数量 × 方向 × 节奏 × 质量线：

| 维度 | 来源 | 机制 |
|---|---|---|
| 数量 | 规则组配额 + 目标差距反推 | 初值 = 配额；缺口 ÷（品类新品成功率 × 成功新品平均产出）≈ 需上新 N 款，与配额对照，偏离要写理由 |
| 方向 | 结构缺口 + 风格信号 + 机会类结论 | 驾驶舱结构三维错配/补款建议（价格段/颜色/尺码）；风格库计分卡的上升风格与低拥挤度风格；机会类结论（高毛利段供给不足、色系需求、大码需求）经决策区"上新方向输入"进候选列表（3.5） |
| 节奏 | 节点倒排 | 旺季款上架时间 = 拐点 − 生产周期 − 素材周期 − **新品爬坡期（约等于保护期 90 天）**；上新是触发链中最早的动作 |
| 质量线 | 新品成功率目标 | 考核"成功了多少款"而非"上了多少款"；驾驶舱"上新质量"结论拆选款问题与素材问题，选款问题回写方向 |

**产能约束。** 上新素材需求 + 存量补齐 + 换图需求 = 设计产能需求，规划会对账实际产能，超了优先砍观察态商品投入（优化池收缩）。生产端打样产能为供应链占位字段，人工填（**TBD**）。规划表的产能内容是需求预估 + 专项包申请 + 对账，不是分配；分配规则在产能账（10.3）。

## 4.4 什么时候变

- **季度规划会锁定**基础版本，锁定即快照；复盘与判定对锁定版本比，不回溯。
- **一起锁**：锁定动作同时冻结四样——引用的年度规划季度版本号、策略包版本号、产能账当季配额（常规/专项池预留比、站点比例）、节点实例排期。任一样未锁，规划表不能锁；尚未上线的模块（按第 14 节顺序）在检查里跳过并标注，上线后逐项启用。
- **锁定三道检查**（《灵策总纲》3.3）：**加总校验**（规划表站点 × 品类 Σ = 年度规划季度版本的站点、大类、总盘数，不平不能锁；需求预估 Σ ≤ 产能账可用量，超了出对账结论）；**假设溯源**（上新方向里的激进押注、显著超基线的配额上调、梯度调整，必须挂假设编号，挂不上当场补登记）；**变更留痕**（每个字段前值 → 后值 → 依据 → 操作人）。
- **月度调整窗口**：月会看完快照差距后，规划内容（排期/方向/资源/动作包）集中调整、留痕；目标值不动，规则组不动。每条驾驶舱结论能动哪个板块见 6.2。
- **目标值与规则变更**只在年度规划发生：季度规划会（正常校准）；季中战略环级异动（平台政策/汇率/供应链剧变），走变更审批留痕，并关联假设清单状态变更（《战略目标层需求》5.2）。规划表感知为引用版本号变化。
- **节点叠加包**独立版本：季度复盘对基础版、节点复盘对叠加包，两层互不污染。

# 5. 批量意图单生成

- **触发**：节点实例触发链到期的环（素材准备、投放蓄水、专项规划）和节奏型节点（上新批次、素材补齐批次）。蓝图未锁定不生成。
- **相乘取数**：对象按规划表行（站点 × 品类）展开；目标取该行与单据类型口径一致的目标值；预算与预算来源取预案资源需求并从产能账或预算池扣减；时限取触发链该环日期；来源记蓝图 + 节点实例；关联记规划行、叠加包、预案、假设编号。字段逐项见《意图单需求》3.1。
- **确认粒度**：草稿按节点实例成批，由规划 Owner 确认——整批确认、单张改量、单张驳回写理由；确认后进意图单状态机。
- **下发分流**（《灵策总纲》3.5）：商品域素材单、换图单经灵鉴路由至灵枢；营销类直连灵犀；客服类至鹊桥；执行方待定环节（价格·上下架、运营、供应链）落人工工作台。
- **与事件单的关系**：事件单（诊断里批准开出）不经本流程，但从同一个池子扣额度；单池事件单累计占用超阈值时须规划 Owner 加签，阈值在配置中心蓝图分区。批量单与事件单在产能账里分列，是月度对账的两个看点（10.4）。

# 7. 节点日历

## 7.1 是什么

全公司一本的时间锚：各域的叠加包、活动、EDM 波次、产能提前量挂同一批节点。承载四合一里的节奏。三类节点：

| 类型 | 例子 | 来源 |
|---|---|---|
| 周期型 | 品类旺季拐点 | 同期指数曲线回算 → 自动生成候选 → 人确认 |
| 日历型 | 平台大促（黑五）、节日 | 人工录入；进同一实例状态机，后续机制共用 |
| 节奏型 | 上新批次、素材补齐批次 | 由规划表过程目标推导生成 |

> 口径澄清：换图候选层面"明确不做季节错位"（SPU 级图片季节信号对婚纱礼服不成立，《换图决策需求》4.4 注）与品类级旺季规划不矛盾——品类量价周期（婚礼季）真实存在，两条决策记录各自成立。换图不是节奏型节点：换图单由诊断批准或检视队列产生，不按批次排。

## 7.2 里面有什么

| 对象 | 字段 | 性质 |
|---|---|---|
| 节点定义 | 品类（或"全站"）、节点类型（旺季启动/峰值/回落/大促/节奏型）、识别规则版本 + 曲线版本（周期型）、提前量配置分项（上新倒排 W / 专项规划 X / 素材准备 Y / 投放蓄水 Z，品类可配）、历年预测偏差记录 | 资产，年年复用 |
| 节点实例 | 所属定义、年度、预计拐点周（+ 证据：曲线图、历年实际拐点）、触发链（各环任务 × 触发日期 × 状态 × 派生意图单批次号）、状态、确认人与时间 | 每年由定义自动生成 |

## 7.3 规则

**同期指数曲线（季节性的数据本体）。** 品类近 2–3 年销量按周聚合、逐年归一化（消年度增长）、跨年平均 → 52 周相对强弱曲线。拐点识别：指数低位连续 N 周上行且累计超阈值 → 旺季启动拐点；同理识别峰值、回落点，输出"预计第几周"。**一份资产三处复用**：判定引擎的品类同期校正、节点日历的拐点识别、年度规划目标篇的月度分解加权（《战略目标层需求》5.1）共用同一条曲线，资产环统一维护，全系统只建一份——战略层的月度目标线和蓝图层的节点曲线永远是同一条，不另存副本。冷启动例外：历史不足 2 年的品类用相近品类曲线代用或人工录入节点（人工节点的正当来源）。

**实例状态机**：待确认 → 已排期 → 触发中 → 进行中 → 已结束 → 已复盘。"待确认"不可省：季节回算是统计推断，系统出证据（曲线图 + 历年实际拐点），人确认后排期——"规则出证据 + 人拍板"。

**触发链**：

```
T−W 周 ─→ 上新批次触发（提前量最长：生产 + 素材 + 新品爬坡期 ≈ 保护期 90 天）
T−X 周 ─→ 专项规划任务：生成节点叠加包草稿（目标包模板 + 预案动作清单初稿）→ 专项规划会定稿锁定
T−Y 周 ─→ 素材准备意图单下发（经 L3 → L4 商品契约 → 灵鉴路由 → 灵枢）
T−Z 周 ─→ 投放蓄水意图单（营销域，直连灵犀）
T      ─→ 节点启动：实例转"进行中"，叠加包目标 vs 实时达成开始对照
T+结束 ─→ 复盘任务：叠加包达成判定 + 预案有效性复盘
```

- 专项规划本身是触发链的标准首环（上新触发除外，它更早）：不是孤立会议，而是节点实例上的任务，产出物（叠加包）挂回实例。
- 触发链各环时点系统按提前量倒推给初稿，专项规划会上可人工调整。
- **触发链延误为日级预警**（与护栏红线触发并列为仅有的两类"等不起"信号）：错过提前量无法补救。送达机制见《灵策总纲》10.5。

**与战略层的分界**：节点的日期与曲线是**日历事实**，住这里；对节点的**重大押注**（如"旺季 GMV 占比提至 40%"）是可证伪判断，登记进战略假设清单（《战略目标层需求》4.2 第 4 类来源），其"影响范围"指向对应叠加包，证伪时顺藤回调。

## 7.4 什么时候变

- **年度滚动重算**：新一年数据进入后刷新曲线，由定义自动生成下一年的实例。
- **确认**：周期型实例待确认时人确认后排期；日历型录入即排期。
- **复盘回路**：节点结束后复盘任务收两笔账，分别回写两个资产（资产环，频率挂在节点复盘上）——**拐点预测偏差**（预计周 vs 实际周）回写节点定义，校准识别规则；**预案有效性**（动作清单哪些起效/无效/漏项）回写预案库，草稿预案跑过一次且复盘后升"验证预案"。

## 7.5 和谁连

| 对象 | 关系 |
|---|---|
| 判定引擎 | 共建共维同期指数曲线 |
| 年度规划目标篇 | 月度分解加权引用同一条曲线 |
| 规划表 | 板块 5 引用实例；上新节奏按拐点倒排；节奏型节点由规划表过程目标生成 |
| 节点叠加包 | 触发链 T−X 环生成叠加包草稿，叠加包挂回实例 |
| 预案库 | 触发链动作清单引用预案模板；复盘回写 |
| 意图单 | 触发链各环到期生成批量意图单（第 5 节） |
| 驾驶舱 | 节点区读实例倒计时与进行中节点的叠加包达成 |
| 战略假设清单 | 节点重大押注登记为假设 |

# 8. 预案库

## 8.1 是什么

全域共用的动作资产：一个库、按域分区（商品预案 / 活动预案 / 营销预案 / 供应链预案…），本册定义的分级与修订规矩全域通用；v1 只启用商品域分区。冷启动：第一批预案从历史动作整理（历次换图 push、大促准备动作），不求全，求"下次不从零想"。

## 8.2 里面有什么

| 字段组 | 字段 |
|---|---|
| 标识 | 预案名、**所属域分区**（商品 / 活动 / 营销 / 供应链…，v1 只启用商品）、适用节点类型、适用范围（品类 / 全站）、分级（草稿 / 验证）、版本 |
| 内容 | 动作清单（动作 × 相对时点（T−n 周）× 资源需求 × 负责环节 × 产出的意图单类型）、触发条件说明 |
| 沉淀 | 历次使用记录（节点实例引用）、复盘修订记录（有效/无效/漏项） |

## 8.3 规则

- **轻量分级**：草稿预案（没跑过）/ 验证预案（跑过至少一次且复盘）。不建风格库式的重验证期机制。
- 预案模板 = 节点类型 × 触发时机 + 动作清单 + 资源需求 + 历史复盘记录 + 所属域分区。

## 8.4 什么时候变

每次节点复盘回写（资产环）；草稿 → 验证的升级条件：跑过 ≥1 次且完成复盘。预案库属资产环成员，与风格库、阈值同列被数据持续校准。

## 8.5 和谁连

| 对象 | 关系 |
|---|---|
| 节点实例 / 叠加包 | 叠加包动作包引用预案模板；复盘记录回写 |
| 意图单 | 批量单的动作内容与资源需求取自预案（第 5 节） |
| 风格库、阈值 | 同为资产环成员 |

# 9. 专项规划与节点叠加包

## 9.1 是什么

规划事件两类：季度例行规划会 + 节点触发的专项规划（品类旺季、全站大促均需专项）。专项规划的产出是**节点叠加包**：不改季度锁定版基础目标，在其上叠加期间目标 + 动作包 + 资源预留，独立版本、独立复盘。全站大促（黑五）为**跨品类节点包**，资源从全站总账的专项池预留出（不占单站点专项池）。

## 9.2 里面有什么

| 字段组 | 字段 |
|---|---|
| 标识 | 所属节点实例、覆盖范围（品类列表 / 全站跨品类）、版本与状态（草稿 → 锁定 → 复盘完成）、Owner、关联假设编号（重大押注时） |
| 期间目标 | GMV / 销量增量目标（相对基础版的叠加值）、期间窗口 |
| 动作包 | 预案模板引用 + 本次增删调整（清单化：动作 × 对象范围 × 完成时限） |
| 资源预留 | 专项池产能申请（量 + 来源账：站点账 / 总账）、投放预算预留、期间事件单占用（只读） |
| 复盘 | 达成判定结果、动作有效性记录（回写预案库）、拐点偏差记录（回写节点定义） |

## 9.3 规则

- 期间目标是叠加值，不动基础版；季度复盘对基础版、节点复盘对叠加包，两层互不污染。
- 期间目标若构成重大押注，登记为战略假设并在包上记编号（7.3 分界）。
- 专项池申请按规划表规则组的专项池优先级排队（4.3），同优先级内看期间目标。
- 叠加包期间批准的事件单从该包预留扣（10.1）。

## 9.4 什么时候变

触发链 T−X 环生成草稿 → 专项规划会定稿锁定 → 节点进行中对照达成 → 节点结束复盘完成。专项规划会节奏与参会角色 **TBD**。

## 9.5 和谁连

| 对象 | 关系 |
|---|---|
| 节点实例 | 叠加包挂在实例上 |
| 规划表 | 板块 3 专项包申请、板块 5 叠加包状态引用 |
| 预案库 | 动作包引用模板；复盘回写 |
| 产能账 | 专项池预留与扣减 |
| 战略假设清单 | 重大押注登记 |
| 驾驶舱 | 节点区展示进行中叠加包的目标 vs 达成 |

# 10. 产能账

## 10.1 是什么

设计产能的两本账，承载四合一里的资源与常规池规则：

| | 常规池 | 专项池 |
|---|---|---|
| 分配轴 | 站点 × 等级（现行灵鉴规则**保留**：站点总比例 → 站内按等级） | 品类 × 事件（节点叠加包、上新批次） |
| 驱动 | 规则自动：等级挂素材要求 → 缺口生成任务 → 排队 | 规划驱动：专项规划定包，按规则组专项池优先级排队，经 L3 下发 |
| 哲学 | 资源跟着表现走（对象层哲学延续，不问品类） | 资源跟着战役走（规划层意志，以品类为锚） |
| 事件单扣减 | 诊断批准的素材单、换图单从常规池扣 | 叠加包期间批准的事件单从该包预留扣 |

品类在常规池的份额是**涌现**的（S/A 级商品多的品类自然多拿），规划表不推翻它——品类规划的产能内容是需求预估 + 专项包申请 + 对账，不是分配。事件单从哪个池扣由钩子预填，人不选；单池累计占用超阈值要加签（《灵策总纲》3.4）。

## 10.2 里面有什么

| 字段组 | 字段 |
|---|---|
| 标识 | 账层级（总账 / 站点账 / 默认账）、期间（季度 + 月度切片）、锁定版本号（与规划表同锁） |
| 供给 | 产能总量（单位口径 **TBD**：任务点数或图张数）、常规池 / 专项池预留比 |
| 分配 | 站点比例（总账层，以站点分级各档开发资源比例为输入）、站内等级优先级（站点账层，沿用灵鉴配置） |
| 消耗 | 需求预估（各品类行汇总）、实际消耗（分批量单 / 事件单两列）、任务积压量、事件单资源占比、人工来源占比、单池加签触发记录 |
| 对账 | 月度对账结论（正常/积压/超支）、调剂记录（留痕） |

## 10.3 规则

**三级账结构**：

```
全站总账（总盘层）
├─ S 级站点单独账（有专属规则与 Owner 的站点，逐站一本）
└─ 默认账（A–D 级站点：A 级单列小计可见、B/C/D 级合并计，走全局默认规则；分档见《战略目标层需求》5.4）
```

| 账 | 内容 | 谁定 |
|---|---|---|
| 全站总账 | 产能总量（人力盘）、常规/专项池总预留比、全站供需总对账、**站点间比例调剂**、跨品类节点包预留 | 管理层 / 规划会 |
| 站点单独账 | 站点资源比例、站内等级优先级、站内常规/专项比、站内对账 | 站点 Owner |
| 默认账 | A 级站点单列小计、B/C/D 级合并计；随总账带过，异动才拆看 | — |

- **恒等式约束**：总账 = Σ 站点单独账 + 默认账；任一层改比例自动校验加总，防"各账合理、加总超产能"。
- **单独账门槛** = 站点分级表当期 S 级（《战略目标层需求》5.5），跟季走；升降档带交接清单（单独账开立或合并）。开发资源比例以该册 5.4 各档比例为输入。
- **品类资源倾斜的四个杠杆**（均不碰常规池规则）：① 上新量（新品走新品素材档，上新计划直接带产能；配额来自规则组）；② 节点叠加包（战役性投入走专项池，按规则组优先级）；③ 处置态池子大小（移入/移出"优化"态改变常规池需求量）；④ 素材与换图倾斜档（策略包里选档，档的含义在配置中心对象层与换图分区；战略品类 B 级享 A 级素材标准走这条路，不另开配置覆盖）。

## 10.4 什么时候变

- **与规划表一起锁**：季度规划会锁定规划表时，总账的池预留比与站点比例同时锁；季中调剂走留痕。
- **月度对账**（全局快照日，一月一次）：本段是诊断矩阵**站点 × 商品**格子的定期诊断（《灵策总纲》3.6），自上而下三层对应三种决策：

| 诊断维度 | 在看什么 | 非正常时的出口 |
|---|---|---|
| 总账供需 | 总积压；**事件单资源占比**（事件单消耗 ÷ 总消耗）；**人工来源占比**（来源为人工的意图单消耗占比） | 积压 → 人力盘（招人/外包），不是改分配；两个占比超阈 → 推回规划层：是蓝图少规划了还是动作层在绕过蓝图 |
| 站点账 | 站点间结构是否失衡 | 总账层调剂站点比例 |
| 品类行 | 需求是否超出产能；单池事件单占用是否触加签线 | 砍处置态池（优化池收缩）、调排期，或申请专项包；触加签线的后续事件单由规划 Owner 加签 |

对账结论三态：正常 / 积压 / 超支，回填规划表板块 3 对账状态列，并进月度快照。积压或事件单占用超阈可提前触发对账。

## 10.5 和谁连

| 对象 | 关系 |
|---|---|
| 规划表 | 需求侧来自板块 3；对账状态与事件单占用回填 |
| 站点分级表 | 单独账门槛、站点比例输入 |
| 策略包 | 专项池优先级、倾斜档 |
| 意图单 | 批量单与事件单分列扣减；加签 |
| 灵鉴 | 常规池规则（站点比例 + 等级优先级）保留现行机制，配置逐步上收至配置中心蓝图分区（**TBD** 时点） |
| 月度快照 | 对账结论归档 |

- **节点实例详情页**：曲线证据（曲线图 + 历年实际拐点）、触发链各环状态与派生意图单批次、叠加包、复盘记录；待确认节点的确认操作；触发链到期生成的批量意图单草稿在此成批确认（整批确认 / 单张改量 / 单张驳回写理由）。角色同节点日历页。

## 11.4 预案库页

模板列表（分区、分级标识）、编辑、历次使用记录、复盘修订记录。角色：管理层（查）/ 运营负责人 / 站点 Owner / 运营（编）。

## 11.5 产能账页

三级账视图（总账 / 站点账 / 默认账切换，恒等式校验提示）、月度对账结论（含事件单资源占比、人工来源占比）、加签记录、调剂操作（总账层，留痕）。角色：管理层（编+批：总账、调剂）/ 站点 Owner（编本站点账）/ 其余查。

## 11.6 引用处

- **年度规划页**：季度版本页签做季度目标校准与锁定；策略篇商品块按梯度一档一行编辑名册与每档内容。规划表板块 0、板块 1 跳到这里改。
- **品类驾驶舱页**：规划区展示规划表该品类五板块投影（目标 / 现状 / 差距）；节点区展示节点实例倒计时与进行中叠加包的达成；规划会议题、上新方向输入、跨域议题从决策区发出。L2 接入前规划区仅素材目标占位（《品类驾驶舱需求》3.1）。
- **品类列表页**：总评视图规划差距列读规划表；上线前用 GMV 同比替代并标注（《品类驾驶舱需求》3.2）。
- **个人待办中心**：触发链延误置顶红条；批量意图单草稿待确认项；月度对账与调整窗口提醒。

## 11.7 页面间动线

**月度**：品类列表页总评视图横扫（姿态、主要矛盾、规划差距、连续月数，按梯度排月会议程，绿的翻页）→ 品类驾驶舱页看总评与结论 → 决策区领动作（动作类批准即开事件单；需要改规划的走三条路）→ 品类规划表页在调整窗口里改排期、方向、资源、动作包（对照 6.2）→ 产能账页看对账结论。

**季度规划会**：年度规划页季度版本页签校准目标、策略篇商品块调梯度与配额并锁定 → 产能账页定池预留比与站点比例 → 品类规划表页按规则组与目标填板块 2–5、过三道检查、锁定。

**节点**：节点实例详情页确认拐点 → 触发链到期在待办中心收到草稿、回详情页成批确认 → 叠加包在详情页定稿锁定 → 驾驶舱节点区对照达成 → 详情页复盘。

## 12.2 系统对接

- **年度规划**：季度版本是板块 1 的唯一来源；策略篇商品块是板块 0 的唯一来源，规划表显示版本号。
- **驾驶舱与列表页**：快照喂现状列与当期姿态；规划区 / 节点区投影启用；总评视图规划差距列读本表；决策区三条路写入本表候选。
- **判定引擎**：共建共维同期指数曲线。
- **风格库**：计分卡上升风格 / 低拥挤度风格 → 上新方向输入（风格库第二消费场景）。
- **对象层**：新品成功率与平均产出、观察态积压、处置态池规模；素材要求按倾斜档读同一份策略包。
- **意图单**：批量单取数见《意图单需求》3.1；事件单从产能账扣额并记来源；加签走意图单状态权限。
- **L4 契约 / 执行侧**：商品域单经灵鉴路由至灵枢；常规池规则保留现行机制，配置逐步上收至配置中心蓝图分区（**TBD** 时点）。
- **L1 指标树**：GMV、销量目标值指针落年度规划季度版本；过程目标（上新数量、成功率目标线、素材补齐量）指针落规划表板块 2、3；口径指向字典。
- **配置中心**：本册第 13 节参数在蓝图分区；梯度档位枚举在战略分区；倾斜档参数含义在对象层与换图分区。

# 14. 实现依赖顺序建议

1. 品类规划表：字段 + 锁定/版本机制（含三道检查）+ 快照映射现状列 + 规则组（梯度先按临时分档）——先让"承诺 vs 实况"闭环跑起来；年度规划季度版本未建成前目标值暂存。驾驶舱规划区与列表页规划差距列随之启用
2. 节点日历：日历型节点（人工录入）+ 实例状态机 + 触发链——大促先用起来，不等曲线
3. 同期指数曲线回算 + 周期型节点识别（与判定引擎品类校正共建）
4. 预案库冷启动（历史动作整理）+ 叠加包 + 专项规划流程
5. 产能三级账 + 月度对账（依赖产能量化单位定案）+ 事件单扣减与加签
6. L3 相乘生成批量意图单草稿（三件套齐备后）
7. 年度规划接入：板块 1 改引用季度版本，板块 0 改引用策略篇商品块
8. 复盘回路：预测偏差回写 + 预案修订 + 基线预测校准
